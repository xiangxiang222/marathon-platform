## 1. 产品定位与首要原则

赛事档案馆帮助跑者在报名前回答四个问题：**为什么跑这场？赛道适不适合我？报名有多难？今年与往年有什么变化？** 同时为跑过这场的用户保留每年的参赛、完赛与赛事物品记忆。

它是跨年份积累的赛事知识库。现有赛历继续负责时间、报名状态和参赛安排，赛事资讯继续负责时效新闻；档案把值得长期保留的信息组织起来，连接这两种内容。

- 产品名称为“赛事档案馆”；首页入口为“热门赛事档案 / 精选 3 场”。首版只选北京、上海、厦门，不声称全国排名或官方名单。
- 赛事身份与某一届比赛分开。北京马拉松只有一个稳定档案，可以连接多个年度的报名页、赛道与成绩。
- 主体按“赛事 → 年度档案 → 年度资料”组织；每年包括赛道、报名中签、参赛完赛、参赛包与完赛包、服装与奖牌，以及有价值的补充资料。优先收全已核验资料，不为了填满字段制造内容。
- 世界田联标牌与中国田协认证分别展示，并标明适用年份；不能把“白金标”和“A 类”排成一个高低等级序列。
- 数字、路线和认证需要证据；跑法建议属于编辑分析，应能看出分析所依据的事实。
- 阅读优先给判断与关键变化，深度资料按需展开。趣味内容不能遮住报名决策信息。

## 2. 用户任务与信息架构

| 用户情境 | 首要任务 | 合适入口 | 成功结果 |
| --- | --- | --- | --- |
| 还没有目标赛事 | 从知名赛事中选一场 | 首页 → 目录 | 根据城市、赛道特点与等级找到候选 |
| 已在看报名页 | 报名前了解这场 | 单届赛事页 → 对应档案 | 查到历年路线、规模和报名口径，返回原报名页 |
| 想冲击 PB | 看赛道条件与后程难点 | 目录目标标签 → 赛道 | 知道哪些条件有利、哪些条件需要准备 |
| 曾经跑过 | 查看本届改道和组织变化 | 收藏 → 档案年度切换 | 准确分辨与自己熟悉那一届的差异 |
| 想回顾参赛记忆 | 找某年的参赛服、奖牌与包内物品 | 档案 → 年度 → 装备收藏 | 看到对应项目的实物与发放条件，不混淆不同届 |
| 喜欢赛事文化 | 看历史与故事 | 档案 → 故事 | 获得有出处的赛事掌故和城市记忆 |

```text
赛事首页
├─ 热门赛事档案 · 精选 3 场
│  └─ 赛事目录：搜索 / 国际标牌 / 国内认证 / 跑者目标
│     └─ 赛事永久档案 → 年度档案
│        ├─ 概览：适合谁、关键特点、赛事沿革、年度资料索引
│        ├─ 赛道：官方路线图链接、逐年跑法分析、双年文字比较
│        ├─ 报名中签：逐年报名、有效申请、抽签口径与结果
│        ├─ 参赛完赛：实际出发、完赛、未完赛、成绩与统计
│        ├─ 装备收藏：参赛包、完赛包、参赛服、完赛服、奖牌
│        └─ 赛事故事：掌故、名场面、城市文化与补充资料
└─ 单届赛事 / 报名页
   └─ 报名前，先了解这场比赛 → 档案（携带返回上下文）
```

档案可关联现有赛事资讯，但不将资讯正文复制成第二份文章。赛事名称的别称、曾用名和冠名变化进入搜索别名；冠名变化不创建重复档案。

## 3. 屏幕 A：首页入口

**位置：现有 discovery 内容区之后、截止提醒之前。** 保留搜索、快捷工具、提醒和赛事列表的既有任务顺序。入口采用一张紧凑白卡，不新增主导航标签。

```text
热门赛事档案                          精选 3 场 ›
路线怎么跑，报名有多难
北马 · 上马 · 厦马                 查看全部 →
```

- 标题 18px，说明 12–14px，至少 44px 的主点击区域；卡片整体可进入目录，具体赛事名称可直达对应档案。
- 移动端约 100–120px 高；宽屏以横向内容行呈现，不拉成全屏宣传海报。首页不自动播放、滚动轮播或弹出新手引导。
- 原型“精选 3 场”表示首版选题范围，目录明确显示北马样板与上马 / 厦马待补状态。生产接入后数量与已发布档案一致，不把待整理稿算作完整可读档案。
- 入口不展示未经核查的“最难中签”“全国最快”等排名文案。
- 搜索比赛的既有模式不强行插入这张卡；后续可在搜索结果单列“相关赛事档案”，与单届报名结果分别标识。

## 4. 屏幕 B：三场赛事目录

### 顶部与筛选

白色导航“赛事档案馆”；页面标题“把下一场，选明白”，副文“热门赛事 · 首版精选 3 场”。提供“收录说明”，解释首版先用北马打磨结构，再补上马与厦马年度档案，不是名次表。目录卡清楚区分“北马样板”与“年度资料待补”，不让三张卡看起来已经同等完整。

搜索支持全名、城市和别名，如“北马”“北京”。输入与搜索按钮均可执行，清空后保留其他已选筛选。

| 控件 | 选项与行为 |
| --- | --- |
| 世界田联标牌 | 全部、白金标、金标、其他已核验标牌；仅显示有实际资料支持的选项 |
| 中国田协认证 | 全部、A 类及其他实际收录类别；细分级别保留原始称谓 |
| 跑者目标 | 全部、冲击 PB、城市体验、历史经典等编辑标签；不作为官方认证 |
| 已选条件 | 显示条件摘要、结果数及“清空”；两个认证维度之间取交集 |

每张卡的认证必须带年份。若筛选使用各赛事“最近已核验认证”，筛选旁写明这一口径，结果卡继续显示实际年度；不能让不同年度认证形成一个没有年份的“当前等级”。后续有完整年度数据时，再增加认证年度筛选。

### 目录卡片

```text
北京马拉松                              ›
北京 · 北马
[世界田联标牌 · 年份]  [田协认证 · 年份]
从城市地标出发的一场经典全马
赛道 / 城市体验 / 历史等 2–3 个特点
```

- 卡片让人辨认赛事并理解其特色；最多两行介绍、三个标签。不堆创办年、规模、纪录和故事摘要。
- 一列为手机默认；桌面可采用两至三列。卡片标题、信息顺序与手机保持一致。
- 视觉不标名次。默认排序由编辑维护，筛选后保持可预测顺序。
- 首期只提供搜索、双认证与少量标签；城市地图、多场横向对比和用户评分留到验证需求后。
- 返回目录恢复筛选、搜索、页内滚动；分享目录可携带筛选参数。

## 5. 屏幕 C：单场档案

### 首屏与导航

顺序为“返回 → 赛事名 / 城市 / 别名 → 年度认证 → 一句核心特点 → 适合谁 / 主要挑战 / 报名前知道”。赛事历史长文放在概览后段，不占第一屏。

导航固定为 **概览 / 赛道 / 报名中签 / 参赛完赛 / 装备收藏 / 赛事故事**。移动端横滑排列，保留相邻栏目的部分露出以提示可滑动，不把六栏压成小字；选中短红下划线并滚入可视区。桌面可展开更多内容宽度，但不改信息次序。

年度选择固定在年度资料区域上方，切年同步更新路线、报名、参赛完赛、装备和年度故事，模块标题重复显示年份。默认年度采用资料可用情况明示选择，不把“2026 年”自动视作资料最全的一届。提供按年索引和“本年资料”清单，用户能直接看到已收录与待整理模块，不能用一个百分比掩盖关键资料缺失。

稳定信息（创办、赛事沿革、城市定位）与年度信息分别组织。不能把最近已核验年份的规模作为赛事永久属性。

### 概览：先给跑者判断

| 区块 | 内容要求 |
| --- | --- |
| 这场适合谁 | 具体到目标与准备条件，例如城市体验、成熟赛事服务；避免“适合所有跑者” |
| 主要挑战 | 依据路线、地形、典型气象或赛事要求说明；编辑判断注明依据 |
| 报名前知道 | 项目、资格或抽签等已核查关键点；规则变化须带年度 |
| 一眼认识 | 城市、创办信息、赛事特点、官网；未知字段不显示占位数字 |
| 赛事沿革 | 关键节点时间线，控制在 3–5 项，可展开完整资料 |
| 继续阅读 | 进入路线、报名或故事；标题直接说明能获得的信息 |

不以一个无解释的“难度 4.7 分”“PB 指数 92”代替分析。首期不提供缺少采样基础的综合评分。

### 赛道：首版采用官方路线资料与文字分析

1. **本届路线状态**：已公布 / 尚未公布 / 历史参考；显示比赛年份、路线来源和更新日期。
2. **路线概览**：起终点、关键地标、路线概要；官方原图可放大，弱网先加载文字。
3. **跑法分析**：按有意义的路段解释控速、转弯、坡桥、后程体能等问题。里程未经核验时不伪造精确分段。
4. **与上一届相比**：只列真正核实的改动；没有找到改动证据写“暂未核实”，不能直接写“完全相同”。
5. **对比两年**：用户选择两个不同年份，优先用起点、终点、主要路段、折返、后程特点的表格对照。

没有可信 GPX、坐标或同尺度地图时，不画貌似精确的轨迹叠线，不计算累计爬升。可提供标注“地标示意，非导航”的路线表达；原图与示意图在视觉上明确区分。海拔、气温、风向分别说明数据来源、适用时段和局限，往年天气不能当作比赛日预测。

跨年比较的差异须区分“已证实改道”和“资料表述不同”；赛道分析属于编辑意见，避免承诺某个跑者能提高几分钟。

#### 后续保留规格：最新赛道的起终点动画

**以下仅为未来需求规格，首版和本轮原型均不实现，不作为当前验收项。** 首版只保留官方路线图链接、起终点与关键路段文字、跨年文字比较；不提供示意动画或播放控件。

目标是让用户直观看懂“从哪里出发、穿过哪里、在哪里完成”，并能定位分析所说的路段。默认选择**最新已公布且已经核验的官方路线版本**，显示“×× 年 · ×× 项目 · 路线 v2 · 核查日期”；“最新赛道”不等于系统当前年份。用户已经选定历史年度时，动画跟随所选年度，不悄悄切回最新路线。

| 交互 | 明确行为 |
| --- | --- |
| 初始画面 | 全程适配、起终点、主要地标；不自动播放，也不把镜头一开始就拉近到局部 |
| 播放 / 暂停 | 跑者标记沿真实轨迹移动；暂停保留公里数、当前路段与地图位置 |
| 拖动进度 | 以距离为基准定位；同步更新公里标记、地标说明与海拔游标 |
| 倍速 | 提供明确倍速档位；动画是浏览速度，不冒充真实完赛配速预测 |
| 全程 / 跟随 / 缩放 | 可随时回到完整路线；跟随模式由用户开启，拖动地图后暂停跟随 |
| 点击地标 / 补给点 | 选中该点，展示对应公里、设施类型与官方依据；缺证据不补虚构站点 |
| 年份 / 项目 / 版本切换 | 暂停旧动画、清除旧游标，加载对应轨迹；不同项目不共用错误距离 |
| 动态减少设置 | 关闭持续移动与镜头自动跟随，保留可拖动进度及文字列表 |

生产实现的数据来源优先为官方 GPX / GeoJSON；获准使用的其他真实轨迹须清楚标注来源、年份、版本和精度，不能贴“官方”标签。将官方示意图手工描成经纬度并不足以声称精确赛道。轨迹没有海拔数据就隐藏海拔联动，没有补给坐标就不沿路线猜测位置；公开测量距离与轨迹计算距离并列说明。

无可信坐标时维持“官方静态路线图 + 起终点 + 地标顺序 + 跑法分析”，不提供播放。本轮原型不包含 SVG 赛道动画；未来即使另做动画交互示意，也须明确“非真实导航轨迹”，不能作为真实导航导出。

地图资源与轨迹按需加载。小程序优先使用适配的原生地图 / Canvas 能力，不每帧整页 `setData`；保留端上简化轨迹用于显示、原始轨迹用于核查，按设备能力降低帧率和地标密度。切页、切年、进入后台时暂停播放；弱网地图底图失败仍显示文字路段，轨迹失败不继续播放旧年度路径。未来实施阶段验证低端设备、内存、连续拖动和页面恢复，不在包内塞入赛事的全量高清地图。

### 报名中签：每年都有独立口径与记录

| 字段 | 显示规则 |
| --- | --- |
| 赛事规模 | 标明年份、项目；全马人数与全项目总人数分开 |
| 报名人数 | 原始提交人数与发布机构口径；不能直接当作抽签分母 |
| 有效报名人数 | 通过资格审核的申请人数；未公开时不从报名人数推导 |
| 实际参与抽签人数 | 区分直通、抽签等人群，说明项目与组别；不能默认等于有效申请数 |
| 抽签名额 | 与直通、公益、精英等名额分别记录，不用总规模代替 |
| 公开中签率 | 只展示可核查发布口径；未公开即写“未公开” |
| 直通人数与资格 | 人数、规则和抽签分母分别记录，以对应届次规程为依据 |
| 递补情况 | 是否递补、各轮时间与名额、截止口径；首次中签与递补最终结果分开 |
| 项目与人群 | 全马 / 半马、性别或其他公开组别；同年不同组别独立记录 |
| 时间节点 | 报名、出签、缴费等来自单届赛事；历史时间不能生成本届提醒 |
| 来源与适用范围 | 每项数字附来源、发布日期和该数字覆盖的具体人群 |

“规模 ÷ 报名人数”不等于真实中签率；首期不自动补算。不同项目、报名组别和资格条件的数字不拼接。历史表格允许出现“未公开”，这比一个看似完整的错误百分比更有用。

**年度中签对照表为本栏的核心内容**：一行一个“年份 × 项目 × 人群 × 抽签轮次”。手机首列固定年度，横向滚动承载人数和来源；默认露出年度、官方中签率、抽签名额三个决策字段，其余点开完整记录。没有当年资料仍保留年度入口，说明“未收录”；赛事停办或未办则明示原因与证据，不生成虚构的一届。

### 参赛完赛：从起跑到完赛，再看成绩

先展示年度参赛结果，再展开成绩，避免“计划规模”与“实际参赛”混淆。

| 数据 | 口径要求 |
| --- | --- |
| 获得参赛资格 / 领取号码 | 分别记录；领物不能当作实际起跑 |
| 实际参赛 / 出发人数 | 以对应项目、统计口径和官方发布为准 |
| 完赛人数 | 标明是否为有效成绩、是否含关门后、是否为全项目合计 |
| 未出发 / 未完赛 / 取消资格 | DNS / DNF / DSQ 分开；缺数据时不以相减自动补齐各状态 |
| 完赛率 | 优先使用公开官方值；分母、项目与时间范围必须明确，来源不足则不展示 |
| 服务与赛况 | 天气、补给、医疗、关门时间、赛道组织变化等有证据的补充资料 |

成绩继续分为三组：

- 赛会纪录：男子 / 女子、姓名、成绩、年份、项目、枪声或净计时口径，以及来源。
- 历届冠军：按所选年度显示；“赛会纪录”不随当前选年误变成当年冠军成绩。
- 大众表现：仅在可信样本完整时展示完赛人数、分段成绩分布或破三人数；必须标样本范围。未收录时保留可访问的官方查询入口。
- 成绩按项目与性别区分；冠军、国内冠军和大众最佳不能混成一个榜单。暂无资料时不显示 00:00:00。

### 装备收藏：每年赛事物品的可查档案

按年份与项目呈现实物，而不是把不同年度照片混成画廊。“收藏”在此指赛事物品展示，个人是否拥有某件物品不在首期范围内。

| 类别 | 内容与关键区别 |
| --- | --- |
| 参赛包 | 包型、物品清单、领取时间 / 地点与资格；计划清单和实际发放分开 |
| 完赛包 | 完赛领取条件、内含物品、不同项目差异；不能与参赛包合并 |
| 参赛服 | 正反面、颜色、版型 / 尺码、设计说明；区分官方效果图与实拍 |
| 完赛服 | 是否发放、适用项目和条件；没有完赛服不显示为空白参赛服 |
| 奖牌 | 正反面、绶带、细节、设计主题、材质 / 尺寸（有来源时）；完赛奖牌与其他纪念品分开 |

手机采用两列物品缩略图与可读名称，不将图片堆成长瀑布流。点开物品进入轻量详情：年份、项目、物品类型、图集、设计说明、发放条件、来源；可放大查看，关闭后回到原位置。图片每张标注“官方效果图 / 官方实拍 / 已授权跑者实拍”，不同款式、项目和版本有独立标识。

缺图有三种不同表达：“资料待整理”“官方未公布”“该年 / 项目无此物品”（后者需证据）。不使用 AI 生成的奖牌、服装或包内清单冒充赛事物品。原型可以用明确标记的展示占位演示布局，不能让人认为是该年的真实设计。

跨年浏览优先采用同一物品类型的年度胶片条，如“2023 / 2024 / 2025 奖牌”；切换保留物品类别，标明每张年份。高清原图按需加载，目录仅缩略图；保存、下载能力取决于资源授权，不能默认开放所有官方和跑者照片的下载。

### 赛事故事与年度补充资料：有趣，也能追溯

前台称“赛事故事”，容纳赛事掌故、历史名场面、奖牌与城市文化。每篇有标题、时间或背景、短摘要、事实来源；长文复用资讯详情。编辑点评与事实分开，未经证实的私人传闻不进入档案。故事可跨年份阅读，文章中标明相关届次。

“年度补充资料”收录规程、领物手册、号码布与分区、关门表、接驳、官方补给表、配速员、照片与成绩查询等，按类型组织来源索引，不把所有文件混进故事流。资料带年份、项目、版本、文件类型和大小；已有赛事页维护的同一资料以关联复用为主。用户可以尽可能查全，首屏仍由跑者决策优先级控制。

## 6. 屏幕 D：报名关联与收藏

单届赛事页在报名主要信息附近增加一行入口：**“报名前，先了解这场比赛”**，说明“历年赛道 · 报名参考 · 成绩与故事”。仅关联到已发布档案时出现，不让用户进入空壳页。

档案保留进入时的 `fromRaceId`，返回操作进入同一届报名页、同一上下文。不能只按名称跳到最新一届，导致用户丢失原先准备报名的比赛。

| 情境 | 档案底部主操作 |
| --- | --- |
| 从某一届报名页进入 | “返回 ×× 年赛事” |
| 从首页进入且本届报名开放 | “查看本届报名” |
| 有本届赛事，但报名未开放或已截止 | “查看本届赛事” |
| 没有已核验的单届关联 | 不提供失效报名按钮，展示“本届信息尚未收录” |

档案收藏收藏的是赛事品牌，既有“想跑”等参赛计划仍属于单届赛事。未来账户收藏可以进入“我的”；登录后收藏应保留原阅读位置。原型仅演示可切换、可反馈的收藏状态，不把原型状态写入现有参赛计划。

## 7. 状态、错误与可访问性

| 状态 | 页面行为 |
| --- | --- |
| 游客 | 完整阅读公开档案、来源、路线和故事；浏览不要求登录 |
| 搜索无结果 | 显示搜索词、已选条件及“清空筛选”；不静默重置搜索 |
| 某年缺路线 | 展示“该届路线暂未收录”，可选择其他年；不自动换年后隐去提示 |
| 本届未公布资料 | 明确显示“参考 ×× 年”，入口不伪装为本届资料 |
| 某项数字未公开 | 写“未公开”；“未收录”和“官方未公开”是不同状态 |
| 网络失败 | 保留已选年度和分区，当前区块提供重试，已加载内容继续可读 |
| 图片失败 | 保留文字路线、来源链接和重试，不使用无关风景照片补位 |
| 外部来源失效 | 保留来源标题与适用年，标待复核；不删除历史事实的核验记录 |
| 档案不存在或下架 | 说明状态，提供回目录；不能用另一场档案悄悄替换 |

所有操作至少 44px 触达；来源、收藏与筛选有明确文字或可访问名称。年度切换后读屏可获知新年份和加载状态，键盘焦点不丢失。路线图提供等价文字说明；颜色不作为区分年度的唯一方式。固定底栏留出安全区及正文空间，320px 下页面不横向溢出，宽表只在自身容器滚动。弹层可关闭、可键盘操作，关闭后焦点回到触发控件。

## 8. 内容后台与发布流程

沿用现有平台管理员权限体系，新增“赛事档案馆”内容分组，不允许普通跑团编辑修改全国赛事公共档案。

编辑流程为 **草稿 → 待核验 → 发布 → 修订 / 下架**。正式发布前展示与前台相同的预览，并对缺少年份、口径或来源的关键事实逐项提示。实际实现时根据现有管理员能力映射编辑与审核权限，不能仅在前端隐藏按钮。

编辑器按“基本信息 / 年度认证 / 各届资料 / 故事关联 / 来源 / 发布预览”分节。某一年度内部编辑赛道、报名中签、参赛完赛、装备收藏与补充资料，并能复制结构；复制上一届只复制字段结构，不自动复制认证、数字、实物图片和“已核验”状态。

发布要求：

- 基本信息、原创摘要、适用年度、至少一个有效资料来源完整；有内容的各区块独立核验。
- 认证、数值、路线、纪录必须能关联到具体证据，记录发布者与核查时间。
- 来源冲突保留两方记录与处理说明；不能选择看起来更漂亮的数字。
- 缺资料可以发布“未收录”，不可发布占位百分比或未经核实的标牌。
- 内容更新记录编辑人、时间、变更字段与适用届次，支持回退已发布版本。
- 路线文件校验项目、起终点顺序、坐标系、距离、版本及来源；实物图片校验年度、项目、版本、权利与效果图 / 实拍类型。批量导入先预览差异，不自动覆盖已发布记录。
- 用户“纠错”携带赛事、年度、区块和可选来源，复用现有反馈流程；用户提交不直接覆盖公开内容。

资料优先级为赛事组委会 / 官方规程与结果、中国田协与世界田联、主办城市政府、可靠媒体的一次报道。整理采用原创归纳并链接来源，原图授权或引用条件单独核对，不把完整媒体文章复制进档案。

## 9. 建议数据模型

| 实体 | 关键字段 | 关系与规则 |
| --- | --- | --- |
| `RaceArchive` | `id`、名称、别名、城市、介绍、标签、创办信息、官网、发布状态 | 永久赛事身份；稳定 slug，不随冠名变化重建 |
| `ArchiveEdition` | `id`、`archiveId`、年份、日期、项目、`raceId`、举办状态、各模块资料状态 | 关联某届现有赛事，允许先有历史档案而无报名记录；停办 / 未办不造空白记录 |
| `Certification` | 体系、原始等级、适用年、`sourceIds` | 国际与国内体系分开；不同年多条记录 |
| `RouteVersion` | `editionId`、项目、版本、发布日期、核查日、概要、起终点、官方图、轨迹引用、坐标系、轨迹距离、公开测量距离 | 官方与非官方来源分开；原始与显示简化轨迹分开；版本替换可追溯 |
| `RoutePointOfInterest` | `routeVersionId`、类型、名称、坐标、公里数、海拔、`sourceIds` | 地标、补给、坡桥等；未知字段可空，不为动画猜测 |
| `RouteAnalysis` | `routeVersionId`、路段、观察事实、编辑建议、依据、跨年变更类型 | 分析与官方事实分字段，不把编辑推断当官方结论 |
| `RegistrationStats` | `editionId`、项目、人群、轮次、报名数、有效申请数、实际抽签人数、抽签名额、直通人数、公开中签率、递补 | 数值可空，每项附口径与证据；不能由总规模自动补算中签率 |
| `ParticipationStats` | `editionId`、项目、资格人数、领物人数、实际出发、完赛、DNS、DNF、DSQ、公开完赛率、统计口径 | 未知与零分开，不由差额猜测未完赛各类人数 |
| `ResultRecord` | 年份、项目、性别、姓名、时间、计时口径、纪录类型 | 冠军、赛会纪录与大众统计独立 |
| `EditionCollectible` | `editionId`、项目、类型、款式 / 版本、名称、清单、设计、领取条件、`assetIds` | 区分参赛包 / 完赛包 / 参赛服 / 完赛服 / 奖牌 |
| `ArchiveAsset` | 类型、URL、缩略图、年份、项目、正反面或角度、官方效果图 / 实拍、署名、权利、来源 | 图片、文件、轨迹统一登记；控制授权、原图与下载范围 |
| `EditionResource` | `editionId`、类别、标题、版本、文件 / 链接、`sourceIds` | 规程、领物、补给、接驳等年度资料索引，优先关联现有资料 |
| `ArchiveStory` | 标题、摘要、相关年、事实正文或资讯引用、来源 | 可关联现有资讯，避免维护两份长文 |
| `Evidence` | `id`、标题、机构、URL、发布日期、适用年、核查日 | 数据引用具体来源；记录失效与冲突状态 |
| `ArchiveRevision` | 版本、状态、编辑人、更新时间、变更说明 | 已发布版本可回退；草稿不进入公开接口 |
| `ArchiveBookmark` | `userId`、`archiveId`、创建时间 | 后续账户收藏，与单届参赛计划分开 |

这些字段用于保留完整设计，不代表本轮均已建表或有资料。首版优先实现三场静态档案所需字段；轨迹坐标、地标联动等动画相关结构保留为后续扩展，不要求本轮采集。

资料状态建议区分 `verified`（核验）、`not_collected`（未收录）、`not_published`（明确未公布）、`needs_review`（待复核）；不将这些状态压成一个布尔值。日期保留来源时区，比赛日期与报名时刻分别表达。

## 10. Web 与小程序的接入建议

本节是后续实施方案，本轮不新增真实接口、不迁移数据、不改变现有报名流程。

| 接入处 | 建议 |
| --- | --- |
| Web 目录 | `/race-atlas`；查询参数保存搜索与筛选 |
| Web 档案 | `/race-atlas/:archiveId?year=2025&tab=route`；年份、栏目、项目可深链，避免占用现有 `/races/:id` 单届路由 |
| 小程序 | 独立目录与详情页，复用现有请求、页头与分享方式；首页和报名页仅增加入口 |
| 公开读取 | 建议 `/api/race-atlas`、`/api/race-atlas/:id` 及年度资料子资源；目录返回摘要，详情与高体积资源按需加载 |
| 现有赛事响应 | 增加可空的已发布 `archive` 摘要或 `archiveId`，由显式映射生成 |
| 内容数据 | 初期可用校验后的共享数据文件；需要在线编辑时采用版本化存储并复用后台认证 |
| 图片与轨迹 | 经服务端登记的资源按需加载；图片缩略与原图分级；轨迹版本、ETag / 缓存键与年度对应，资源不打包进小程序主包 |
| 收藏 | 有账户服务后提供幂等写入 / 删除；原型本地状态不冒充服务端结果 |

赛事映射使用显式稳定 ID，名称匹配只生成后台候选，不自动将“北京半马”等相似名字关联到北马。服务端决定公开状态和来源可见性；移动端不下载完整后台草稿数据集。

两端共享内容 schema、认证口径、标签和状态文案，不共用不适配的小程序 DOM。首版赛道采用官方路线图链接与文字说明，不引入动画或地图 SDK。后续评估真实地图动画时再确定选型与授权。新页面加入现有小程序包预算与原生编译检查，图片不能阻塞档案文字阅读。

## 12. 视觉系统与内容节奏

遵循[现有统一视觉规范](unified-visual-system-20261112.md)：品牌红 `#ff1838`、选中浅红 `#fff0f2`、主文字 `#1a1a1a`、辅助文字 `#777777`、白卡与 `#f5f5f5` 底色。

- 页面边距 16px、卡片圆角 12px、控件圆角 8px；标题 24px、分区 18px、列表 15px、正文 14px、辅助至少 12px，长文 16px / 1.9。
- 使用原生文字、清楚的数字对齐与克制的分隔；颜色强调选中和行动，不为每场建立一套主题。
- 标牌以小型徽标、名称与年份识别，不使用大幅金色背景制造排名感。真实赛事图只在有内容作用和合法来源时使用。
- 路线是详情的主要视觉信息，文字分析与图片并列服务阅读。无图时仍能完整理解，不用无关风景填满卡片。
- 手机一列阅读，宽屏可用主体与资料栏；阅读宽度控制在舒适范围，正文不横跨整个桌面。

1. 从首页进入目录、按别名搜索北马、查看档案，再返回目录，筛选和位置保留。

## 14. 衡量是否有用

上线前记录现有报名页浏览与转出基线；上线后按入口分别观察，不先承诺未经测量的增长数字。

| 指标 | 要回答的问题 |
| --- | --- |
| 首页档案入口点击率 | 用户是否理解并发现这个板块 |
| 目录 → 详情到达率 | 搜索、筛选和卡片是否帮助找到目标 |
| 年度切换 / 路线比较使用率 | 历史资料是否产生实际阅读价值 |
| 中签表与装备年度切换使用率 | 是否满足逐年查资料与赛事记忆的需求 |
| 报名页 → 档案 → 返回原报名页 | 档案是否服务报名前判断且不造成迷路 |
| 来源查看与纠错处理时间 | 用户能否核查，内容维护是否可靠 |
| 三场资料覆盖与关键字段核验率 | 北京、上海、厦门是否有实质内容支撑，缺项是否被准确说明 |

不单独以停留时间判断成功：快速查明不适合并退出，也可能是一次有效决策。优先结合短访谈确认用户能否复述赛道挑战、报名口径与所读年份。
