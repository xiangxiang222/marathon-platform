# 跑圈资讯中心：设计、发布与资料范围

实现日期：2026-11-11。网页与微信原生小程序同步实现，未部署生产或提交小程序审核。

## 放在哪里

保留现有四个底部导航。首页与「我的」快捷入口中的「赛事资讯」升级为「跑圈资讯」，网页 `/marathon/news`，小程序 `pages/news/news`。统一入口包含精选、业界、运动员、私兔、跑团、赛事六个栏目；原有赛事资讯详情链接继续可用。

跑团主页的概览中增加独立「跑团资讯」卡片，放在常用活动和赛事信息之后、更多服务之前。跑团资讯是管理员编辑的报道与文章；原有团友交流动态保持原入口。访问 `/marathon/clubs/:id/news` 或 `pages/news/news?club=:id` 只浏览该团文章。团长和管理员能进入发布页，游客可以阅读已经公开的文章。

## 阅读设计

按用户反馈更新为白色内容面、浅灰背景、深墨文字与统一品牌红。删除大型蓝绿宣传卡，搜索和栏目置于首屏，运动员与私兔改为紧凑入口，仅在精选栏展示。人物列表突出姓名和 PB，再列成绩赛事、日期、履历和原始来源。没有引入未经核实的人像照片。完整规范见《四个主入口统一设计与验收-20261111.md》。

列表支持栏目切换、搜索、男女筛选和分页；加载失败有重试，空内容提供下一步入口。资料口径和待核内容保留在阅读页，不用含糊的「认证」标签代替证据。

## 发布流程

平台后台新增「内容运营 → 资讯中心」，用于发布业界资讯、人物文章和跑团稿件。原有「赛事资讯」保留赛事关联与上传审核。

跑团发布页位于 `/marathon/clubs/:id/news/manage` 和 `pages/news/editor?club=:id`。支持原创、授权转载、公众号 / 原文推荐三种内容类型，包含标题、摘要、正文、来源名称与链接；支持阅读预览、保存草稿、发布和下架。平台后台另有全站优先展示和发布时间控制。

权限由服务端核实：只有该团当前团长与管理员可写入；普通成员、跨团账号、失效登录不能读管理草稿或修改文章。受限跑团的文章不公开。全站优先展示仅由平台管理员控制。网页与小程序编辑页清理换号后的草稿和权限，并忽略过期请求。

独立 `content_articles` 表承载内容，不再强迫每篇文章关联一场赛事。公开接口只返回已发布且到达发布时间的内容。下架保留管理记录，不删除资料来源。

## 公众号文章

采用「摘要 + 来源 + 用户点击阅读公众号原文」。小程序在点击处理器直接调用 `wx.openOfficialAccountArticle`，基础库 3.4.8 起支持；旧版本或调用失败时复制原文链接。不自动抓取和镜像整篇公众号文章或图片。完整依据和真机验收项见[公众号文章展示调研](公众号文章展示调研-20261111.md)。

## 验证

`npm run test:content` 覆盖资讯权限与生命周期、旧赛事资讯搜索、小程序 VM 旅程、Web 构建及隔离真实接口的浏览器旅程。`npm run test:mini` 另验微信原生离线编译与模块引用。

已完成服务端 289 项全量回归、23 份扩展客户端回归脚本、资讯专项 HTTP 验证、16 组小程序 VM 旅程和原生离线编译。旧活动浏览器测试补齐了训练组查询的模拟响应，未为此改动产品行为。真实浏览器覆盖首页入口、男女各 20 人筛选和来源、私兔证据、跑团草稿→发布→公开→下架、后台新增文章；320 / 390 / 1024 三种宽度共 39 张截图，无页面异常或横向溢出。测试数据使用临时 SQLite 与媒体目录并自动清理，没有写入线上业务数据。

截图与结构化报告位于 `design/previews/content-center-20261111/`。原生编译与 VM 不能替代正式 AppID 真机验收：公众号跳转、低基础库、失效原文、分享返回仍需在微信 iOS / Android 实测。没有接入公众号自动同步、自动抓取新闻、人物认领、私兔交易、收费预约或人工实名认证。
