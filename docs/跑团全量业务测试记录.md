## 运行与隔离

在项目根目录执行：

```sh
node scripts/club-full-acceptance.cjs
npm test
```

只运行本次新增回归：

```sh
node --test --test-concurrency=1 --require ./server/test/setup-env.js server/test/mileage-validation.test.js
```

批量脚本每次自行创建独立的临时 SQLite 数据库、媒体目录和 `127.0.0.1` 随机端口服务，不读取项目 `.env`，不连接现有服务，不调用中国马拉松、微信或其他外部平台。注册、入团、审核、实体创建、上传、签到、删除等业务写入均调用实际 HTTP 接口。账号和跑团只存在于这次隔离测试内，结束后数据库、媒体文件及该脚本自己的服务自动清理；不会向现有环境注册 36 个可长期登录的账号。

注册接口本身当前不要求验证码。本轮在注册后为 36 个账号逐个调用 `/auth/captcha` 和 `/auth/login`，验证实际的一次性本地验证码登录流程，并重放验证码确认拒绝。脚本从**自己临时数据库**读取验证码答案，用于稳定验证服务端登录流程；没有接入、破解或代替中国马拉松官网的滑块验证码。SQL 的其他读取仅用于查看测试归属和断言；SQL 写入仅调整临时数据的开始/截止时间，以验收到时签到、历史快照等边界，不直接插入用户、会员或比赛业务数据。

测试数据每次都重新生成。可复用方式是再次运行脚本，不依赖本次账号的密码、token、ID 或残留数据。脚本输出逐场景结果，并重写机器报告 `design/previews/club-full-acceptance-report.json`；报告不保存登录 token 或真实个人信息。一次失败会保留失败场景说明、设置非零退出码并清理临时服务，不会关闭其他开发服务。

## 发现与修复

| 编号 | 修复前复现与影响 | 修复结果 | 回归验证 |
| --- | --- | --- | --- |
| B-01 | 先创建一条未自动纳入的 10 km 跑步记录，再由管理手动“计入”。原实现只改 `counted`，未补实际计量，排行仍为 0 km。 | 首次纳入补齐按本团规则计算的里程；重复裁定、排除再恢复保留已确定的计量快照，避免后续规则变更重写越野折算里程。 | 真实 API 复现原始失败 `0 != 10`；修复后反复计入/排除总量正确；另验证 10 km + 200 m 越野按原规则折算 12 km，切换规则后反复裁定仍保留 12 km。 |
| B-02 | 规则生效日、手录开始时间和报表日期主要只校验字符串形状；`2026-02-30` 等不存在的日期可通过，异常报表日期还可能触发内部日期计算错误。 | 校验真实公历日、有效月/年、时分和自定义起止范围；显式非法输入稳定返回 400；未提供报表日期时仍使用当前日期。 | 修复前非法日期接口返回 200；修复后无效闰日、月、24:00、周/月/自定义报表均返回 400，合法 `2024-02-29` 正常通过。 |
| B-03 | 手录运动类型通过普通对象属性查找判断，`toString`、`constructor`、`__proto__`、`hasOwnProperty` 等继承属性可能被当作有效类型入库。 | 只接受类型表自身定义的 `run` 和 `trail`。 | 修复前继承属性类型返回 200；修复后上述四种输入全部 400，且没有产生运动记录。 |
