# 协议发布与权利请求受理手册

这份手册供项目运营及维护人员使用，不替代对用户公开的七份协议。当前版本为 **2026-11-01.2 待确认稿，尚未部署发布**。公开文本源为 `shared/legal-documents.json`，不得分别修改小程序副本或生成的 Markdown。小程序副本为 `utils/legal-documents.js`，使用微信支持的 `module.exports` 导出；不能改回 JSON 模块引用。

小程序入口为 `pages/legal/legal?doc=privacy`，`doc` 使用同名文档 ID；游客可读，网络失败时显示明确标识的随包副本。微信平台生成的《用户隐私保护指引》仍需在公众平台另行配置，自建协议不能替代平台声明或原生授权。

本版增加私人跑史：用户提供文字、CSV / JSON，或逐次确认临时解析成绩截图；确认候选后保存结构化字段，另行上传的照片作为私密收藏保存。OCR 使用随服务器安装的中英文本地模型，运行时不将图片传给外部识别服务；原图和完整识别文本不持久保存。微信后台文件声明应同时覆盖主动选择的跑史文件，图片声明覆盖临时识别和私密收藏两种用途。`race-history-ocr` 同意凭据与运动文件的 `activity-file` 分开记录；不得互相替代。

## 正式发布前要落实的事项

- 确认真实运营者是否为“北京华创科技有限公司”，并核对小程序主体、网站备案及服务范围；不是同一主体时修改正文与卡片，不能只更换页脚。
- 提供可实际接收请求的公开邮箱、通信地址，确认收件和备岗人员。无法登录的人必须能使用公开渠道。
- 核对 API、数据库、媒体、日志、备份、CDN 的实际地域与服务商；核对腾讯云合同中的法律主体、委托处理条款和分包情况。地域未知时不得承诺“全部境内”或“绝不出境”。确认没有遗漏统计、广告、客服、短信或其他供应商。
- 确定最短必要保存期限或清晰的确定标准，落实手工记录、收件资料、服务器日志、备份的实际清理安排。跑团身份及权利工单的自动清理不代表所有业务数据均已自动清理。
- 逐项验收敏感资料、团内展示、公开发布的场景告知与必要的单独同意。文件导入已增加本次解析确认；不能据此推定成绩、训练资料、照片和公开展示的所有场景已一并获授权。对依法需要开展的处理活动，事先完成个人信息保护影响评估并按法定要求保存记录。
- 寄递当前只有平台手工发货记录，没有在提供信息前告知具体承运主体并取得相应同意的完整产品流程。**完成该次承运主体、联系方式、规则、目的和字段的告知及必要同意前，不能把收件信息交给承运方。** 现有“同意用于领奖”不自动覆盖具体承运方。
- 目前没有经核实的监护人授权流程。账号及个人资料提交暂不向不满十四周岁的儿童开放；保留无需账号的公开浏览。明确运营处理人员及保护请求通道，不能用普通注册勾选代替监护人同意。
- 在微信公众平台核对真实接口声明、文件和照片用途、写入相册、复制内容等，并使用真机验收。`errno 112`、未声明隐私接口和 banned 仍须平台侧配置，更新文案不会自动开通接口。
- 对新版本执行游客阅读、未勾选、拒绝权限、取消导入、换账号、离开页面、平台与团后台权限及注销实际处理验收。

上述事项不是填满配置字段即可完成。`LEGAL_PUBLICATION_CONFIRMED=true` 只能在实际核对和落实后设置；接口的 `ready` 是明确配置状态，不是法律认证。正式生效日须单独确定，不能把开发日期当作生效日期。

## 配置与维护

公开配置为 `LEGAL_CONTACT_EMAIL`、`LEGAL_CONTACT_ADDRESS`、`LEGAL_STORAGE_REGION`、`LEGAL_HOSTING_ENTITY`、`LEGAL_OPERATOR_CONFIRMED`、`LEGAL_PUBLICATION_CONFIRMED`、`LEGAL_EFFECTIVE_DATE`，均在 `.env.example` 注释示范。联系方式等会公开显示，不填内部秘密或账号凭据。运营主体名称变化需修改源文档中的全部相关位置。

更改正文应递增版本并重新生成副本：

```sh
npm run legal:generate
npm run test:legal
```

版本变更后的新注册须确认新版本；旧版本文件解析同意会被拒绝并要求重新阅读。当前没有向所有历史用户自动推送条款更新的系统，涉及依法需重新同意的存量处理时，应另行落实通知和重新授权，不以保持登录视为同意。

## 权利请求办理

用户在“我的→个人信息权利”或协议中心权利文档中私密申请。平台管理员在后台“个人信息权利”中处理；跑团后台无权受理全局权利申请，也不得通过重置他人密码取得用户资料。

1. 接收并核对请求人及必要处理范围。核验限于必要资料，不要求提供密码、登录令牌或所有请求一律提交身份证。
2. 原则上十五个工作日内答复受理情况或结果。需要补充时说明具体事项及原因，不反复索要无关资料；复杂事项说明延长原因与预计时间。
3. 查阅、复制、更正、删除、撤回、注销根据实际数据范围办理。现有入口为人工受理；“已回复办结”仅更新工单，不执行数据清除。实际完成哪些操作、保留哪些信息及依据，必须在回复中说明。
4. 注销涉及团长移交时协助安排并说明处理方式；不得仅以尚未移交为由无限期拒绝。数据库现有删除操作有团长校验，需要运营妥善处理实际困难及保留义务后执行。
5. 删除或注销的结果须为删除或不可复原的匿名化；可重新关联个人的去标识化不能充当最终注销完成。备份和法定保留例外应限定访问及用途并说明期限。
6. 申请记录终结九十天后自动清理原始说明和回复，终结一年后清理工单与决定事件；实际定时清理间隔为六小时，查询时也会触发。未结工单保留至完成必要处理；不要无限期搁置。账号删除会一并清理关联工单和同意凭据。

对于不能登录、儿童保护和紧急泄露等请求，使用公开联系渠道受理并进行适度核验，必要时先限制有害展示。不得引导用户把资料发到公开“共创建议”。运营需安排人员定期查看后台及公开邮箱；系统尚无自动邮件通知或外部工单服务。
