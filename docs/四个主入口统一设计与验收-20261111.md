# 四个主入口统一设计与验收

更新日期：2026-11-11。已实现网页和微信小程序源码，未发布生产服务或提交小程序版本。

## 信息安排

| 入口 | 首屏重点 | 次级入口 |
| --- | --- | --- |
| 赛事 | 搜索、分类、赛事列表 | 赛事日历、拿奖雷达、发现跑团、跑圈资讯 |
| 跑团 | 我的跑团、搜索与口令 | 跑团内活动、团内资讯、创建跑团 |
| 运动 | 本月跑量、目标、记录跑步 | 文件导入、运动记录与编辑 |
| 我的 | 账号、运动摘要、赛事生涯 | 完赛记录、跑史、档案工具、右上角设置 |

“我的”右上角为齿轮和“设置”，小程序留出微信胶囊区域。设置集中放账号、隐私政策、个人信息权利和退出登录。退出仅在设置中出现；返回设置前的页面会保留原来的栏目。游客进入设置可登录。

海报是成绩的后续操作：放在赛事生涯和完赛成绩汇总内的工具行，不再使用单独金色广告卡。没有有效成绩时显示“去记录成绩”，避免进入空白海报流程。小程序将 PB 并入赛事生涯卡，去掉重复的 PB 宣传区和底部赛事引导卡，缩短“我的”。

资讯总入口保留在赛事页常用功能和我的常用功能；跑团内部提供本团资讯入口与有权限的发布入口。资讯页先展示搜索和栏目，再显示内容；精选栏才显示运动员、私兔两个紧凑快捷入口。运动员男女筛选保持单行，人物姓名与 PB 对齐，详情保留来源与核实说明。错误时隐藏数量和空说明条，提供重试，不展示 HTTP 或后台部署术语。

## 视觉规则

| 项目 | 统一规则 |
| --- | --- |
| 背景 | 页面 `#F6F7F9`，卡片与页头白色 |
| 文字 | 深墨 `#17212B`，辅助文字 `#687480` |
| 强调 | 品牌红 `#E1251B`，浅红仅用于选中、快捷入口和提示 |
| 主标题 | 24px，四个主入口统一标题行与留白 |
| 层级 | 内容标题 16–19px，正文 14–15px，辅助信息 11–13px（11px 仅用于日期等次要说明） |
| 间距 | 左右约 16px，页头与首卡约 16px，卡片间距约 12–16px |
| 形状 | 卡片 16px 圆角，主要控件 10px；表单、筛选与标签各有层级 |
| 交互 | 核心按钮与设置、搜索、性别筛选、重试等触达区域至少 44px |
| 图标 | 工具图标统一中性色，快捷入口用统一红；底栏选中红、其余灰 |

移除原来按目的地分别使用的暖橙、绿色和紫色渐变，不再用金色、紫色区分我的档案工具。数据本身用深色，红色用于主要动作、选中状态、PB 标识和图表。未知赛事状态使用中性灰，保留必要的语义状态文字。

跑史导入使用并列的“截图识别 / 导入文件”入口，压缩粘贴区，保留识别、校对、保存步骤及隐私说明。正常识别提示为中性色，失败信息才强调。

## 截图中 404 的原因与上线边界

2026-11-11 只读实测，默认线上 `https://togetherbetter.cn/marathon/api/content/articles` 和 `/content/profiles` 均返回 Express 404；旧 `/news` 返回 200，内容为 8 条带“模拟”标识的新闻。小程序默认线上配置未变。

相同代码在隔离的本地服务中，内容接口均 200，运动员 40 人、私兔 10 人可读取。因此页面友好重试已完成，但不能靠前端样式使旧线上服务具备新接口。上线时需要一并更新服务端和网页，再发布小程序；已有编辑内容需保留。初始历史文章通过 `npm run content:seed` 显式幂等导入，不自动覆盖人工编辑。

没有用虚构文章或本地假档案遮盖线上失败，没有改动线上数据或自动部署。测试中注入的合成内容仅在隔离夹具和标注的预览内。
