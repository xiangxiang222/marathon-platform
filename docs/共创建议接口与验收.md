# 共创建议：产品约定与接口

目标：跑者可以提出功能和 UI 建议，审核公示后投票；运营公开答复、采纳和更新进度，并兑现指定实物奖励。沿用赛历红白视觉，不设置付费投票、积分兑换或自动中奖。

## 固定接口约定

以下路径均相对于 `/marathon/api`，JSON 使用 camelCase。普通登录使用现有用户 Bearer；管理接口只允许平台管理员，跑团后台账号无权访问。

- `GET /feedback?category=all&sort=hot&page=1&mine=0`：返回 `{items,total,page,pages,summary:{published,adopted},unread}`，每页 12 条。category 为 all/feature/ui/bug/other，sort 为 hot/new/adopted；mine=1 需要登录，返回本人所有状态。公开列表永不包含未审核内容。
- `GET /me/feedback/summary`：登录后返回 `{total,unread}`，只统计本人，用于「我的」入口的进度更新提醒。
- `GET /feedback/:id`：返回完整建议对象；未公示内容只允许本人和管理后台读取，其他访问返回 404。
- `POST /feedback`：登录提交 `{title,body,category,module}`；title 4–80 字，body 10–3000 字，module 为 races/clubs/sport/profile/other。新建议为 pending，待审核。每天最多 10 条，每人最多 20 条待审核。
- `PUT /feedback/:id/vote`：登录提交 `{voted:boolean}`，幂等，一人一票，不允许给本人投票。只允许 published 状态投票。返回更新后的完整建议。
- `POST /feedback/:id/read`：本人提交 `{revision}`，仅确认已展示的详情版本，返回 `{ok:true}`。旧版本的确认不会消除更新版本的未读状态；缺失、非整数、超过当前版本的 revision 返回 400。
- `POST /feedback/:id/withdraw`：本人可撤回 pending 或 published 建议；返回完整建议。
- `POST /feedback/:id/images`：登录本人、pending 状态，multipart file；最多 3 张，单张最多 5MB，JPEG/PNG/WebP，检查真实文件签名，不接受 SVG。返回完整建议。
- `DELETE /feedback/:id/images/:imageId`：本人 pending 状态移除图片，返回完整建议。
- `GET /feedback/:id/images/:imageId`：按建议可见性鉴权输出图片；公开图片不需登录，私有图片支持 t 查询参数用户 token。对象中的 images 为 `{id,url}`。
- `PUT /feedback/:id/reward/claim`：仅本人、奖励 unclaimed/claimed 时可填写或更新 `{receiver,phone,address,consent:true}`。收件人 2–40 字，手机支持中国大陆 11 位，地址 8–300 字。返回完整建议。
- `POST /feedback/:id/reward/received`：仅本人、shipped 时确认收货，返回完整建议。
- `GET /admin/feedback?status=all&page=1&q=`：返回 `{items,total,page,pages,counts:{pending,published,adopted,building,released,declined,withdrawn},rewardsPending}`，每页 20 条。status=rewards 仅筛选已领取、待寄出的奖励。
- `GET /admin/feedback/:id`：完整建议，含私有奖励领取和物流字段。
- `PATCH /admin/feedback/:id`：`{status,reply,rewardName}`。pending 可转 published/declined；published 可转 adopted/declined；adopted 可转 building/released；building 可转 released；同状态可更新公开答复。published 后驳回仍保留公开结论。withdrawn/declined/released 为终态（允许同状态补充回复）。从 published 采纳时必须指定 rewardName 2–80 字，自动创建 unclaimed 奖励。后续不撤回或抹去奖励，不改变已承诺奖品。公开答复 reply 2–2000 字，审核公示可选，其他状态变化必填。返回完整建议。
- `POST /admin/feedback/:id/reward/ship`：`{carrier,tracking,expectedVersion}`，只允许 claimed 状态，承运商 2–40 字、单号 4–80 个字母数字或连字符，返回完整建议。

详情另返回 `revision`。后台审核与发货均提交 `expectedVersion:revision`，截图增删或收件地址变化都会更新版本；版本过期返回 409，管理员必须重新打开核对后再操作。接口兼容未提供该参数的旧调用，当前后台始终提交。

建议对象：`{id,title,body,category,module,status,statusLabel,author:{nickname},votes,voted,isMine,canVote,canWithdraw,createdAt,updatedAt,publishedAt,reply,revision,unread,images:[],events:[{status,statusLabel,reply,createdAt}],reward:null|{name,status,statusLabel,receiver?,phone?,address?,carrier?,tracking?}}`。公开列表可不含 body/events/images，但详情必须含。收件资料和物流仅本人/平台管理员返回，其他人的 reward 只含 name/status/statusLabel。建议作者不输出账号 ID 和 token。未登录无 isMine/voted 权限。

状态文案：pending 待审核；published 征集中；adopted 已采纳；building 开发中；released 已上线；declined 暂不采纳；withdrawn 已撤回。奖励：unclaimed 待领取；claimed 待寄出；shipped 已寄出；received 已签收。

## 页面及边界

「我的」常驻共创建议入口，游客可浏览，提交和投票时返回现有登录页，登录后回原建议。网页版 `/feedback` 和 `/feedback/:id`；小程序 `/pages/feedback/feedback?id=…`。本人待审核建议可见而不暴露给他人。表单保存本机草稿，按账号隔离，提交成功清除。照片提示避免上传身份证、电话和住址等个人资料。正文只作纯文本展示。

用户只需选择分类、填写标题和想法；模块可选“其他”，截图选填。支持查看“大家的建议 / 我的建议”、热门/最新/已采纳、分类筛选、分页、重试和空状态。详情展示官方答复、进度和投票，奖励只在采纳后出现。站内进度通过“我的建议”未读标记呈现，不承诺微信主动推送。分享使用公开建议详情（待审核和撤回不能分享）。无奖励库存时不提前展示具体装备或虚构价值。

后台“共创建议”提供待审核、征集中、已采纳、开发中、已上线、暂不采纳、已撤回筛选，先读原建议和截图再审核。状态动作按服务端流转提供；发货独立操作并确认。所有票数来自唯一用户记录，同一建议重复请求不累加。状态、奖励和计数写入使用原子事务；文件先校验落盘再短事务登记，失败删除文件，删除账号清理用户建议、图片及相关投票和收件信息。历史进度只存公开回复，不能把地址带进事件或列表。

## 验收重点

游客/作者/投票人/跑团后台/平台后台分别校验可见性；重复投票、取消投票、给自己投票、关票后投票、未审直链；空表单、超长文本、脚本作为纯文本、上传伪装文件、超过容量、不同账号草稿；非法状态跳转、未指定奖品采纳、重复采纳、无权限领取、无同意提交、收件信息不外泄、未领取发货、重复发货、签收；删除账号清理、移动端 320/390 和桌面 1440 宽度、登录返回、请求失败重试。真实浏览器多账号执行提交→审核公示→投票→采纳→领取→发货→签收完整链路。

`npm run test:feedback` 使用临时数据库、临时媒体目录和三个真实注册的测试账号，执行网页、后台及真实接口联动；不读取本地 `.env`，不操作现有业务数据。结果写入 `design/previews/feedback-live-report.json`，页面截图以 `feedback-live-` 开头。`npm run test:client` 另包含网页模拟故障回归与小程序 VM 逻辑回归；`npm run test:mini` 是微信离线原生编译，不代替真机上传和微信转发测试。
