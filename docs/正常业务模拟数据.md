# 正常业务模拟数据

本工具只处理上一批创建的 10 个跑团（13–22）和 200 个测试账号（8–207）。账号必须同时匹配原始账号清单、昵称和创建时间；不创建或重置账号。公开内容带 `【模拟】` 标记，记录之间通过真实业务接口关联。

## 使用方式

先用 SQLite backup API 生成一致备份，在仓库外的私有目录保存原始账号清单。不要复制凭据到仓库。

```sh
node scripts/seed-normal-scenarios.cjs \
  --database /private/scenario/rehearsal.sqlite \
  --run-dir /private/scenario/rehearsal \
  --cohort-manifest /private/scenario/accounts.json
```

隔离模式在随机本地端口启动真实应用，使用独立数据库和媒体目录，不加载 `.env`，不启动定时同步。演练通过后，同一工具可以连接既有应用的 loopback API；生产写入必须显式指定 `--apply`，并从服务器本地环境读取现有管理员凭据。

```sh
SCENARIO_APP_ROOT=/var/www/marathon node /private/tooling/scripts/seed-normal-scenarios.cjs \
  --apply --database /var/www/marathon/server/data/app.sqlite \
  --origin http://127.0.0.1:3790 \
  --env-file /var/www/marathon/.env \
  --run-dir /private/scenario/applied \
  --cohort-manifest /private/scenario/accounts.json
```

实际数据库、端口和媒体目录应以部署配置为准。同一批次重复执行必须保留同一 `--run-dir`；其中 `ledger.json` 保存固定日期锚点及每个已完成步骤的业务 ID，不保存凭据。失败可以从原目录续跑。不要把新目录当作重置或清理工具。

## 覆盖内容

- 跑团：训练模板、活动报名与分组、签到、照片审核、完结与取消、积分与兑换、分期团费和缴费登记。
- 社群：入团申请、团员分组、日常签到、自由约跑、队内赛、成绩召集、动态、评论与点赞。
- 个人：运动记录、当月目标、跑量分组及 PK、记录核对、赛事计划、完赛成绩、私人跑史、成长数据、个人收藏和奖项雷达条件。
- 平台：明确标注的模拟赛事和资讯、训练联赛、模拟物资领取以及意见处理进度。

新建的历史场景需要回填日期时，只调整本批新对象，详细记入 `historySetups`。原有成员 `joined_at` 保持原值；团 PK 使用原入团时间和当前规则计算。已有资料、成绩、活动和真实账号记录受到前后指纹检查保护。已有成员的模拟管理角色或跑量分组调整会单独记录。

会费和物资数据都是站内模拟登记，不触发实际扣款、邮寄、短信或微信通知。设备授权、官方认证、法律同意和隐私权利申请保留真实状态。

## 验收与记录

`report.json` 包含每个模块的返回结果、全表新增数量、200 人与 10 团覆盖检查、代表账号的真实读取、媒体文件与下载检查、旧记录变化及数据库完整性检查。`completed` 仅在所有模块和验证均完成时为 true；阶段演练不能作为完整填充成功的证据。

模块分工：

- `scripts/fixtures/catalog-scenarios.cjs`：模拟赛事、资讯、反馈、物资与联赛。
- `scripts/fixtures/club-scenarios.cjs`：跑团内的完整参与流程。
- `scripts/fixtures/user-scenarios.cjs`：200 人的个人记录和跑量联动。
- `scripts/fixtures/verify-scenarios.cjs`：只读业务覆盖检查。
- `scripts/fixtures/scenario-training.png`：自行生成、明确标为模拟且无真人的有效图片。

上线执行结果应以独立验收摘要为准，不在本文中把演练数量当成已写入生产的数据。
