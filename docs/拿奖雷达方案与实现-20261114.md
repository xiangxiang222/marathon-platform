# 拿奖雷达：用目标成绩选择比赛

本期目标是帮助有名次竞争力的跑者决定下一场跑哪里。主流程为「设置项目、参赛性别与目标成绩 → 筛选有竞争力的比赛 → 查看比赛的历届前八与今年已知选手 PB」。网页和小程序使用同一套评估接口，后台可持续更新资料。

## 首期范围

以「当届赛事 × 项目 × 男女总排名」作为独立评估单元，支持全马、半马、10 公里和 5 公里。历史榜单只收录男女前八；实际仅奖前三的比赛使用第三名作为奖励线，奖励超过八名的比赛本期只评估前八。年龄组、本地籍、跑团奖和破纪录奖仍保留旧后台能力，不混入新版主列表。

用户填写的时间是目标情景，可以用于找比赛，不作为已取得的 PB。未设置目标时，读取本人已发生的线下路跑成绩，优先使用匹配该组计时口径的 PB。枪声、净计时与未知计时分开；其他人的私人跑史不会自动进入竞争池。

## 页面设计

首屏用一个短表单完成选赛条件：项目、男子/女子组和一个目标时间。主要操作为「寻找拿奖机会」。其他项目的目标分别保存，切换项目后可继续使用。

结果卡片重点展示四件事：本场奖励前几名、历史奖励参考线、我的比较成绩与差距、今年已知阵容和 PB 更快的人数。提供全部参考与有竞争力两种查看方式。模拟资料在卡片与详情中明确标记。

打开一场比赛后，先说明当前判断，再查看当届奖励与资格说明。「历年前八」按年份切换，逐名展示选手和完赛成绩；未收录名次保持缺项，不补造数据。「今年已知阵容」单列展示已标记者的同项目 PB、日期、参赛状态和证据等级。两组资料不拼成今年的预测名次榜。

## 推荐如何形成

1. 从最近三届同计时口径、具有当届实际奖励末位成绩的榜单中提取奖励线，以中位数为历史参考，同时保留各届成绩与范围。
2. 目标快于全部样本奖励线时为「值得优先看」；达到中位参考线时为「可以冲一冲」；慢于参考线时为「竞争压力较大」。缺个人能力、性别或可比历史门槛时为「待补充资料」。相同成绩不算严格领先。
3. 今年已经出现 PB 更快的参赛线索时，优先展示竞争变化。已核验强手足够覆盖奖励名额时下调为竞争压力较大；少量强手或自报强手出现时，将原先的历史优势调整为需要进一步评估。
4. 已知人数少不能推导为参赛强手少，也不能因此上调推荐。不给百分比获奖率，不宣称目标成绩一定实现，不把 PB 当成本场已跑出的成绩。

例如去年前三为 2:11、2:12、2:13，今年出现 PB 2:10 的中签选手：历史仍显示原始完赛成绩，今年阵容显示这条 2:10 线索及其证据；个人目标的推荐同时考虑新竞争信息，不继续只依据去年第三名描述优势。如果只奖励前三，历史第八名不会被称作奖金线。

## 今年阵容如何更新

后台可以手工维护公开选手、PB 日期、当前中签/已缴费/已领物/弃赛状态及来源。未来人工收集或代码采集均可写入相同资料结构，本期不接真实采集。

用户可在真实比赛的雷达详情中选择「我已中签，补充阵容」，主动提交明确的项目、性别、本人 PB、日期和状态。必须主动同意匿名展示；目标时间与 PB 分开填写。提交同时更新本人该场参赛状态。其他人只看到随机匿名标识与明确授权的成绩资料，不会获得账号 ID、真实昵称或私人跑史。

竞争池实时读取当前参赛状态。改为未中签、弃赛或移除参赛标记后，线索退出有效阵容；撤回雷达授权后不再参与雷达，原有参赛计划保留。模拟赛事不接收真实个人线索，演示阵容与真实用户分开。

同一账号在同一场赛事只有一份雷达项目声明，重提会更新，不重复累计。后台手工选手与用户匿名声明暂时没有跨来源身份匹配，编辑应避免重复录入同一选手；不能仅凭同名或相同 PB 合并身份。后续可增加经本人授权的关联核验、PB 时效区间和参赛确认更新提醒。

## 后台与数据入口

在赛事编辑的「奖项」中进入「拿奖雷达」，为当前赛事添加参赛组，再独立维护「当届奖励 / 历年前八 / 今年阵容」。逐名奖金可空；零表示非现金。历史每年预留八行，空行不提交。每个榜单有独立年份、计时和来源。保存雷达资料即时用于用户侧评估。

- `GET /api/radar`：本人资料、可用成绩与赛事推荐；旧奖项响应保留兼容。
- `GET/PUT /api/admin/races/:id/radar`：管理员读取与整体更新当前赛事雷达资料。
- `PUT/DELETE /api/me/radar/entries/:raceId`：本人提交、更新或撤回匿名参赛线索。
- 数据表：`radar_configs`（按当届赛事保存结构化资料）、`radar_entries`（按账号和赛事保存主动授权）。

所有同年名次、组别、年份、选手标识均校验重复；限定 1–8 名并校验成绩顺序、有效日期、来源与字符长度。只对与该赛事已配置项目相符的组别开放评估。

## 模拟资料与验证

运行 `npm run seed:radar` 添加三场明确命名为模拟赛事的资料，覆盖男女全马/半马共十组、三个历史年份、只奖前三与奖励前八、今年更快选手、待核验 PB 和前八缺项。脚本重复运行保留已有后台编辑，不覆盖真实赛事和已有个人目标。

`npm run test:radar` 执行引擎与 API 测试、小程序页面行为验证、网页构建和真实接口浏览器验收。`npm run test:mini` 另做微信原生离线编译。浏览器验收使用临时数据库，覆盖设置目标、筛选、年度切换、后台更新和参赛信息授权；不写现有业务数据。微信真机表现需在开发者工具/手机中另外验证。

### 本轮验收结果

- 服务端全量测试：325 项通过，包含旧雷达兼容、新前八评估、实际奖励末位、当年阵容、弃赛退出、匿名隔离与撤回、缺项和不同计时口径。
- 网页真实接口：320 / 390 / 1440 三种宽度，目标筛选、年度切换、详情刷新深链、今年 PB 展示、空项目、自愿匿名提交与撤回共 8 项检查通过，零页面错误。
- 后台真实接口：1440 / 390 两种宽度共 9 项检查通过，覆盖历史编辑、增加部分年度、奖位与奖金、选手 PB / 参赛状态 / 证据更新、模拟开关、不同赛事间不串写。
- 小程序：目标保存、筛选、年度切换、缺名次、授权和撤回、登录失效及过期请求行为检查通过；微信原生 WXML / WXSS 离线编译通过。
- Web 生产构建通过。报告和截图位于 `design/previews/radar-20261114/`。小程序未做微信真机测试。

### 反馈后页面重构

去掉首屏口号与大块卡片，目标改为时 / 分 / 秒三格输入。压缩项目与男女筛选区，让 320 / 390 × 753 屏幕能直接看见第一场比赛。赛事行并列显示历史奖励线与本人比较成绩，用水平位置标尺解释时间关系（不是胜率），底部保留今年已知阵容与前八入口。

新增离线模拟体验：未登录、接口尚无新版资料或无已收录赛事时，可体验明确标注的模拟赛事；界面提供退出体验。示例成绩不写入个人资料，模拟搜索不发保存请求，也不能提交真实参赛授权。真实资料与示例资料分开，退出后恢复原资料。预览模块以 `shared/radar-preview.cjs` 为规范源，运行 `node scripts/sync-radar-preview.cjs` 同步网页和小程序，`--check` 校验一致。

本次网页真实接口8项、小程序行为检查、Web构建与微信原生离线编译通过。小程序另以真实Page与隔离API生成320/390×753源码镜像，8个场景通过并人工查看首屏；截图与报告位于 `design/previews/radar-redesign-20261114/`，源码镜像不代表微信真机验证。
