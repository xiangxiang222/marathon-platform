# 马拉松赛事专题：按栏目看历年，后台维护内容

更新日期：2026-11-14。本轮将赛事档案改为六个主题栏目，并提供网页后台录入、图片上传与日常维护入口。首批维护北京、上海、厦门三场，保留已有年度事实。

## 1. 本轮范围

赛事页面按用户兴趣浏览：想看参赛服就连续看各年的图组，想看赛道就看版本变化，想查成绩就在成绩栏内选择年份。取消先进入“某届详情”的浏览门槛；年份只影响当前栏目。

**赛事资料由管理员在后台上传、录入和修改。本功能不自动联网采集，不自动搜索、引用或同步外站文章和图片。** 现有记录作为初始资料继续保留；后续补充由后台维护。

页面不展示整块资料来源和复制原文按钮。图片、描述、日期和数字都按实际录入展示，缺失不伪造；普通衣服示意图不会冒充某届参赛服。

## 2. 六个前台栏目

| 栏目 | 内容与界面组合 | 年份规则 |
| --- | --- | --- |
| 概况 | 大幅封面、赛事名称与认证、简介、基础事实、看点与图鉴入口 | 赛事身份长期稳定，年度数值标出年份 |
| 参赛 | 报名中签、报名安排、费用资格、参赛指南、历年报名比较 | 具体安排局部选年，比较区同时展示历年 |
| 赛道 | 道路顺序、路线图、版本卡、适用年份、变化和跑法参考 | 按维护的路线版本浏览，组内保留年度差异 |
| 成绩 | 冠军计时卡、其他已录入组别、计划规模与实际参赛完赛记录 | 在成绩栏目内选择年份 |
| 图鉴 | 参赛服、奖牌、参赛包、完赛包、官方图集 | 每类按年份连续展开，每年一组图片或相册 |
| 动态 | 新鲜事与相关新闻，标题、日期、摘要和内容展开 | 真实发布日期与相关年份分别记录 |

主导航固定为“概况 / 参赛 / 赛道 / 成绩 / 图鉴 / 动态”。不设置全局年份下拉框，切换成绩年份不会把图鉴或赛道强制改为同一年。

## 3. 视觉与首屏

统一使用平台品牌红 **#ff1838**，配白色、浅灰、黑灰文字；不使用绿色主题、绿色选中态或绿底卡片。

北马默认封面是原创红灰色北京跑步 SVG 插画，作为插画呈现，不称赛事摄影。管理员可在“基本信息”上传封面替换；移除上传封面后恢复默认视觉。标题、主题句与认证使用原生文字，避免烘焙在图片里导致裁切和阅读问题。

封面手机端约300px高，桌面端约420px高。主导航手机端一行六项、约52px高，吸顶后仍清楚可点；320px宽度下每项触控范围不小于44px。正文手机边距18—22px，桌面容器约1120px。

赛事标题约30—32px，栏目标题约21—23px，正文14—16px，说明至少12px。不同内容使用不同组件：简介用留白与细线，路线用道路序列和版本卡，成绩用计时数字，物品用横向图组，新闻用日期与条目。避免所有内容重复套白色圆角卡。

## 4. 分类内的历年内容

### 图鉴

五个分类为“参赛服 / 奖牌 / 参赛包 / 完赛包 / 官方图集”。物品分类按年倒序，每年可上传多张正面、背面和细节图，并配当年名称、设计描述和物品清单。点击图片查看大图，不进入单届赛事详情。

官方图集按年份建立相册，封面取相册第一张，照片数量按实际上传记录显示。网页打开相册浏览照片，小程序使用图片预览。当前上传范围为图片，不承诺视频播放。

没有实物图的年份保留已有文字记录，不展示通用衣服图冒充当届设计，也不铺满空白图片框。参赛服图片在后台“赛事物品”中有明确上传入口；前台公开浏览不要求用户上传。

### 赛道

默认展示已收录路线，版本卡保留名称、适用年份和说明。有后台上传的路线图时展示对应图；否则展示道路顺序，并注明不是精确导航轨迹。

版本分组由管理员维护，可选“相近路线”或“已确认相同路线”。不能只因道路摘要相同就归为完整同一赛道。北马2025／2026现有资料只能支持道路序列相近，各年细部记录保留；2023、2024保持各自版本。

路线变化与跑法分析分别呈现。不生成缺少依据的高程曲线、PB评分或精确轨迹；赛道动画不在本轮范围。

### 成绩与参赛

成绩在栏目内选年，突出组别、姓名、成绩与枪时／净时。没有全体选手数据库时仅展示已录入的成绩记录，不提供假榜单或不能工作的个人查询。

计划规模、实际起跑人数、完赛人数分别显示，未知值不写0。中签率只录入已有公布值及适用口径，不以计划规模除以报名人数估算。报名资格、领物、交通、发枪与存取包按相应年份维护，历史安排不自动沿用到下一届。

### 动态

新鲜事记录奖牌巧思、赛事故事和城市记忆；相关新闻记录有明确时间的公告、安排和赛后报道。旧掌故标相关年份，不包装成刚发生的新闻。内容由后台填写，前台在站内展开阅读。

## 5. 后台操作指南

使用管理员账号进入运营后台，在“内容运营 → 赛事档案”选择北京、上海或厦门，再选择以下八类编辑内容。其他跑团后台账号不提供本模块维护权限。

| 后台类别 | 可以维护的内容 | 前台对应位置 |
| --- | --- | --- |
| 基本信息 | 名称、简称、城市、主题句、简介、创办年份、封面、赛事看点 | 封面和概况 |
| 赛道 | 年份、日期、项目、起终点、道路顺序、变化、分析、路线图、版本分组 | 赛道 |
| 报名参赛 | 报名时间、费用资格、人数与中签、领物交通、比赛日服务 | 参赛 |
| 成绩 | 计划规模、实际起跑、完赛、统计说明、组别姓名与计时 | 成绩 |
| 赛事物品 | 选择年份与参赛服／奖牌／参赛包／完赛包，填写描述清单、上传图组 | 图鉴对应物品分类 |
| 年度相册 | 相册年份、名称、照片与图片说明 | 图鉴中的官方图集 |
| 新鲜事 | 标题、相关年份、发布日期、标签、摘要、正文和图片；维护已有故事 | 动态中的新鲜事 |
| 新闻 | 标题、相关年份、发布日期、标签、摘要、正文和图片 | 动态中的相关新闻 |

维护参赛服的具体路径：**赛事档案 → 选择赛事 → 赛事物品 → 选择年份 → 参赛服 → 添加图片**。年份不存在时在年度编辑区新增年份，再填写对应内容。

图片支持 JPG、PNG、WebP，每张不超过8MB，每组最多30张。上传后可填写图注，使用左右移动按钮调整顺序；物品图组和相册的第一张为封面。可移除不需要的图片引用，再保存修改。

上传仅把文件加入编辑内容；确认图片可以在本站展示后，点击“保存修改”才把当前编辑提交到赛事档案。**保存成功即用于公开页面，下次刷新前台可见，无需重新构建或部署。当前没有单独的草稿、审核或发布步骤。**

切换赛事或离开后台的赛事档案模块时如有未保存内容，会提示先保存或放弃。上传中、保存中禁用冲突操作；验证失败保留输入并展示原因，不能把失败当作保存成功。

## 6. 存储与日常维护

后台修改存入SQLite的`race_archive_edits`，作为该赛事的维护版本覆盖初始展示记录；初始JSON仍保留。图片索引存入`race_archive_images`，文件存于持久媒体目录`MARATHON_MEDIA/race-archives/<赛事ID>/`；未配置时使用`server/data/media/race-archives/`。

部署脚本保留`server/data/`，不会用代码部署覆盖运行中的档案和图片。更换服务器或恢复数据时，需要同时备份／恢复数据库与媒体目录；若设置了独立数据库或媒体路径，应按实际配置备份。

图片上传与记录按赛事隔离，文件使用内容摘要命名。管理员录入的文字和图片不依赖外站链接实时可用，也没有后台定时采集任务。本模块不自动替换人工维护内容。

## 7. 验收要点

- 前台六栏清楚可达，没有先选届详情的门槛；各栏内部年份与分类独立。
- 北马默认红灰插画可用，后台封面保存后能替换；整页及后台保持红白灰品牌配色。
- 参赛服等四类物品可按年上传多图、调整顺序、预览；年度相册显示真实照片数量。
- 后台八类可维护，保存后前台获取新内容；失败有明确反馈，未保存修改不会静默丢失。
- 既有事实、组别与统计口径保留；无图不造图，无中签率不估算，不冒称完整成绩榜。
- 320px、390px和桌面无整页横向溢出，正文可读，主要触控目标至少44px。
- 网页与小程序采用相同栏目和后台资料；刷新、分享与旧年度链接合理映射到对应栏目。
- 本轮不包含自动外搜、视频、高程／趋势图、个人全量成绩查询或赛道动画。
