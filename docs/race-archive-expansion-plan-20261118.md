## 二、统一内容标准

### 1. 内容分层和必填规则

“必填”区分**必须有已核实内容**与**必须有字段/核查结果**。身份不明的赛事不发布；资料不足的具体数字可以留空，不以完整率要求逼填数值。

| 层级 | 内容 | 必填/选填及边界 |
| --- | --- | --- |
| 长期身份 | 稳定ID、赛事正式品牌名称、城市/省份、已确认官网或组委会权威入口、身份依据 | 必须核实；简称/历史名/冠名另记，不能把冠名变化当作新赛事，也不能只按城市合并赛事 |
| 赛事概览 | 简介、创办年份及来源、发展脉络、定位、2—3个有依据的独特看点 | 简介和特色为必填内容；创办年份、定位、历史栏目必须核查，未知留空并说明；简介建议150—250字 |
| 认证与定位 | 世界田联标牌、田协认证、其他确有依据的定位 | 必须记录核查状态；有值必须带适用年/届、来源。两机构分别展示；候选资格不能写成正式成员资格，历史标牌不能作为当前认证 |
| 代表性赛道 | 城市地貌/文化与赛道关系、代表性道路和地标、路线演变 | 必须有已核验的代表性内容，并注明所依据年份；不承诺各届都经过同一路段 |
| 历史时间线 | 创办、改名、重要认证、路线调整、停办/恢复等关键节点 | 栏目必备；只收有来源节点，首批建议3—6条；资料不足展示已有节点及缺口，不按年份凑数 |
| 赛会纪录 | 男/女及可核实的中国籍等类别、姓名、成绩、创造日期/届次、计时口径、核验截止日、来源 | 必须核查男/女纪录；确证才写“赛会纪录”。未能确认是否仍有效的值只作对应年度成绩；中国籍等类别选填 |
| 历届信息 | 届名/届次、举办状态、日期、项目、规模、路线、报名资格/费用/抽签、领物交通、发枪关门、统计和成绩 | 每个非空值必须对应届次。所有栏目有结构，未知字段可空；计划规模、实际出发、完赛分列；人数注明项目和统计口径 |
| 报名特点 | 普通报名、直通、候补、资格变化、官方公布中签数据 | 必须有有依据的说明；“长期特点”须有多届证据，只有一届证据就明确写年份 |
| 跑者体验与建议 | 起终点交通、领物行程、赛道应对、住宿选区等实用建议 | 每场必须有针对自身条件的建议，区分官方要求与编辑建议。跑者个人反馈为选填，注明时间/样本性质，不冒称普遍体验或伪造亲历 |
| 物品/图集/动态 | 参赛服、奖牌、物资、城市故事、新闻、照片 | 选填，有资料才展示；实物按年，新闻按真实发布日期；无图保留文字，不造图填位 |
| 资料依据 | 来源记录、引用关系、适用年、核验日、缺口/争议记录 | 必填；每条关键事实应能定位到支持该事实的原文或具体附件/表格 |

建议初次研究覆盖**最近3届已举办赛事**，再补充已正式公告的下一届；更早年度以重要历史节点和纪录为主，不承诺逐年全量规程。资料不足3届时按实际收录列明，不补造。每场至少形成身份与历史、赛道与城市、报名与参赛三方面的独特内容；不统一套用“风景优美、服务完善、适合PB”。

### 2. 时间和缺失规则

- 长期档案不放无年份的比赛日、人数、项目、费用、抽签门槛、路线、当前认证。涉及这些数据的看点、概况摘要同样标年。
- 记录`year`（现有展示字段）及独立`editionName/editionNumber`；需要处理延期/跨年或一年多届时，补稳定`editionId`与实际举办日期。届数不得由“当前年减创办年”计算。取消/延期/尚未举办单列状态，不当作已举办届。
- 日期只在来源明确时精确到日；只有月份就保留月份，不补成1日。报名与比赛时间按举办地时间解释。
- 当前结构的未知标量沿用空字符串，空集合用`[]`；新字段若用`null`需统一适配，避免双端出现字面量`null`。另用`gaps`区分未核实、暂未发布、来源冲突、仅图片待识读、使用条件未确认等原因。
- 缺少证据不等于0、不等于没有认证、不等于赛事未举办。对比表单元格用“—”，全空列隐藏；整个栏目空用一句说明，重要缺口集中放“收录说明”。
- 官方公布中签率必须保留适用群体；不以总名额除预报名人数估算。不从仅收录的冠军中取最快成绩宣称历史纪录。不把计划规模当作芯片统计实际起跑人数。

## 三、资料收集、核验及图片使用

### 1. 每场执行流程

1. **先确身份**：核对正式名称、城市、当届主承办单位、官网与公告发布主体、田协/世界田联赛事条目，建立稳定品牌ID、经确认别名与逐届官方ID映射。官方ID可能对应某一届，不能假设跨年永远不变。
2. **建立资料清单**：赛事官网/组委会的赛事介绍、竞赛规程、报名须知、补充通知、赛道与领物公告、赛后成绩/统计优先；认证分别查中国田径协会和世界田联；历史/城市背景用政府公开资料，权威媒体补充。
3. **留证据再写稿**：关键数字在内部研究表记录字段、原值、单位、项目、适用年/届、来源ID、文中位置和核验日期。来源字段沿用`id/title/url/publisher/publishedAt/accessedAt`，扩展`applicableYears/verifiedAt/evidence`。发布日期未知就空，访问日不能冒充发布日期。
4. **按字段权威核验**：身份以组委会/政府及官方赛事登记交叉核对；认证以认证机构为准；比赛安排以该届最新正式补充公告为准；赛后成绩/人数以更正后的成绩册或官方统计为准。重要数字尽量交叉核对，独立来源不存在时说明单一官方来源，不伪造“双源”。
5. **处理冲突**：先检查是否项目、国籍、枪/净时、预报名/有效报名、计划/实际统计不同；确有更正则采用新公告，保留旧值、双方来源和取舍原因。网页较新不代表正文适用年份较新；同一官网模板标题更新也不能替旧正文改变年份。不能判断就不发布争议值，在`conflicts/gaps`登记。
6. **编写与复核分开**：事实归纳改写，不整段复制；编辑建议标“基于YYYY年路线/指南的建议”。逐一复核姓名、数字、单位、引用、年份与链接。第二阶段输出14场资料覆盖和缺口矩阵，审查17场结构与展示一致性。

搜索结果摘要、百科、营销榜单、聚合报名页只作线索，不能单独支持关键事实；已有仓库快照也只是待复核线索。本阶段网页浏览工具返回404，示例改用HTTPS直接读取官网正文核验；这不影响使用官网原文作为依据。访问失败应如实登记，不声称核实了未读到的内容。

### 2. 图片与地图

- 每张记录原始页面/文件URL、作者或权利人、作品名、适用年/届、使用条件、许可证明链接或记录、核验日及要求的署名。公开可见和注明出处不能替代使用依据。
- 沿用现有`mediaRights`过滤，在现有图片编辑入口补全逐图证据；总确认复选框不能替代来源、权利人及许可条件记录。仅经确认适用本站展示的图片才进入公开媒体；未确认图片只保留内部出处，不下载为公开素材。
- 图片下方展示来源和必要署名，许可细节可展开；没有可用图片就用现有城市文字/中性视觉及原生道路序列。原创装饰明确为插画，不冒充真实摄影、奖牌或路线图。
- 路线图必须注明年份。精确地图须有可用轨迹及相应使用依据；无轨迹不画似真导航线，不生成海拔、坡度、PB指数。此次地图为有合适资料时的增强，不作为发布门槛。

## 五、页面展示方案

### 1. 列表与入口

首页保留3张编辑精选卡，双端采用同一精选配置；“全部档案”进入17场目录，不在首页堆17张卡。首批精选可保持北京、上海、厦门，目录包含全部新增赛事，说明编辑顺序不代表排名。

目录卡片顺序为正式品牌名/简称→城市和一句独特简介→两套带年份认证→实际收录届数/年份范围→阅读入口。费用、日期、报名状态留在对应届次；“收录3届”不暗示赛事只举办3届。保留搜索、独立认证筛选、空态与重试，别名可检索。筛选选项按实际核验数据生成，不固定只支持白金/金标和A类。

### 2. 详情阅读顺序

沿用六栏及局部年份，不增加第七、第八个主导航。进入默认概况，页内引导顺序如下；用户仍可直接进入已有栏目。

| 阅读内容 | 放置位置与形式 |
| --- | --- |
| 赛事概览 | 概况首屏：名称、城市、简介、定位；正文是原生文字，封面不承载唯一信息 |
| 核心数据 | 创办年份、举办城市、主赛距离；认证分别标适用年，最近收录日期/规模明确年与统计口径 |
| 赛事历史 | 概况内竖向时间线，默认显示4—6个重要节点，其余展开；看点只保留2—3条，不重复全文 |
| 赛道特色 | 赛道栏先讲城市与代表性路线，再展示带年份版本、起终点/道路序列、变化；有可用图再配图 |
| 历届纪录 | 成绩栏先给截至某届核验的男/女赛会纪录，再提供逐届冠军表与计划/实际参赛完赛统计；不同口径分列 |
| 参赛指南 | 参赛栏先短述报名特点与一般建议，再按年查费用资格、抽签/候补、领物交通、关门补给；历史安排明确标年 |
| 图鉴与动态 | 沿用物品分类图组、年度图集和站内文章，长文展开；没有材料就简洁空态 |
| 资料来源 | 页面末尾默认收起的来源清单，显示发布主体、标题、适用届、核验日和原文链接；各栏目可跳到对应来源组；图片来源在图下 |

本次“展示资料来源”按用户新要求实施，取代旧设计文档与测试中“无前台来源”的约束。采用轻量折叠清单，不恢复每段重复的来源大卡和复制按钮。

### 3. 长内容、缺失与移动端

- 沿用平台品牌红`#ff1838`、红色下划线导航、白/浅灰底和黑灰文字；复用现有页头、目录卡、栏目、道路序列、年份选择、图组、弹窗/微信图片预览。历史用细线时间轴，纪录用数据行/表格，不把所有段落套多层卡片。
- 长文按小标题分段，正文建议16px/1.8—1.9，辅助文字不小于12px，主要点击区域至少44px。时间线默认摘要，长指南展开；避免首页和概况重复图鉴入口与泛化故事。
- 320/390px保持可读字号，表格仅在自身容器滚动或转换逐届信息块，不产生整页横向溢出。桌面复用现有约1120px容器。
- 官方路线的道路序列过长时先显示关键地标并允许展开完整序列；不把摘要冒充完整路线。图片延迟加载、可放大，图失效时回落文字，不出现假素材占位。
- 参赛/赛道/成绩各自切年，分享链接保留栏目与适用年；返回目录保留搜索筛选。默认选择该栏目较完整的已收录届，下一届不足时不拿旧规则填充。最近收录与最近已举办明确区分。
- Web与小程序使用相同资料和摘要，统一看点数量及空态语义；不出现Web只截两条而小程序全文堆叠的差异。

## 六、数据接入和后台兼容方案

保留`shared/race-catalog.json`及`shared/race-archives/<id>.json`，不另建平行内容系统。示例中的新字段属于待确认的增量扩展，不代表当前后台已支持。

| 数据区域 | 拟扩展 |
| --- | --- |
| 目录`race` | 已核验`aliases`与`identity`（品牌名、当届主承办/官方ID映射、身份来源）；`featuredIds`统一首页精选 |
| `archive.profile` | 结构化`foundingYear`及对应引用、定位与引用；避免由简介解析基础事实 |
| `intro/highlights` | 增加`introSourceIds`与每条看点的`sourceIds`；涉及年度内容记录适用年 |
| `history[]` | 年份/日期精度、关联届次、标题、简述、`sourceIds` |
| `records[]` | 纪录类别、项目、组别/适用人群、姓名、成绩、计时、创造届/日期、截至何届核验、`sourceIds`；不能仅由本地逐届成绩推算 |
| `editions[]` | 保留现有路线/报名/参赛完赛/成绩/物品/物流结构；补正式届名、项目分项规模/费用/规则、必要的届ID和状态 |
| `sources[]` | 保留现有字段，增加适用年、核验日及证据位置；冲突、缺口单独记录，不把缺值伪装成事实 |
| `mediaRights` | 补逐图原始来源、实际权利人、使用依据和署名；沿用公共媒体过滤 |

为便于评审，两个新增数组的单条字段草案如下（仅字段结构，空对象不是待发布事实）：

```json
{
  "historyItem": {
    "date": "",
    "datePrecision": "",
    "editionId": "",
    "title": "",
    "body": "",
    "sourceIds": []
  },
  "recordItem": {
    "category": "",
    "project": "",
    "group": "",
    "athlete": "",
    "time": "",
    "timing": "",
    "editionId": "",
    "achievedAt": "",
    "verifiedThroughEditionId": "",
    "verifiedAt": "",
    "sourceIds": []
  }
}
```

`datePrecision`区分年/月/日；`verifiedThroughEditionId`记录“截至哪一届仍被确认有效”。纪录必须有组别、成绩、创造届及权威依据，不能把空字段结构作为公开条目。

第二阶段必须同时完成：API读取与缺省兼容、后台编辑字段及来源维护、保存校验、双端展示和回归测试。未知引用应明确报错，不静默丢弃；新增字段保存后重读必须保留。

已有SQLite维护版本不能用初始JSON整份覆盖。先识别维护版本与结构版本，采用保留人工内容的增量兼容：新增缺失结构可补入，人工已改字段优先，冲突单列；在隔离测试数据库验证后才形成迁移代码。不连接线上修改、不部署。用户之后如另行安排发布，运行数据库与媒体的实际变更应单独核对。

新档案缺封面时使用可用的文字/中性降级；当前Web按ID拼地标图片、小程序媒体路径仅允许三个ID、固定认证类别、固定三场说明与测试断言，都须同步调整。维护安全路径校验，不能为了扩容改成任意外部URL可执行。
