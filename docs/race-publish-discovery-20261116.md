# 赛事发布与展示改造 · 2026-11-16

本方案基于当前 Vue、Express 和微信小程序代码及现有数据接口。设计以红色品牌、轻盈白底、细边框和统一留白为基础，保留新版首页上半部分及筛选区域的布局。资料和图片继续由后台上传；没有采集外部资料，也没有改写现有真实赛事事实。

## 页面结构与关键交互

后台采用“赛事库 + 编辑工作区”。工作区按建赛、报名、内容三个阶段展开，每阶段连续录入相关字段，不再以九个互斥页面为主要操作方式。标题处展示当前状态、保存影响和未保存提示；顶部提供准确主动作与预览。每个阶段显示填写进度；必填资料和选填资料分别提示，填写进度不等于官方已确认或已发布。

节点使用纵向时间线，保留留空不覆盖规则。修改时对保留值一起校验，避免只提交一个字段后与已有日期倒置。线上赛事保留跨日录入能力，不机械要求节点在单一比赛日之前。来源为条件必填。错误展开对应阶段并定位字段。日期只精确到天时，报名开始按中国时区当日 00:00，截止沿用当日结束；不假造具体小时。已有官方精确时刻在重新保存同一天时继续保留，预览与公开阶段按真实时刻计算；当天已过的精确节点不再作为下一节点。

预览随输入实时更新，列表复用 RaceCard，移动详情为内容概要，展示长标题、关键节点、入口配置、本地未上传图片与缺失资料。预览只读，不执行关注、计划、打开官方链接或发布动作。详情概要明确标注范围，个人资料和另行保存的内容不伪装成已录入。

前台结构为：赛事身份 → 报名阶段与实际官方行动 → 四栏公共内容。Web 个人功能在赛事信息中以紧凑摘要出现；小程序合并为导航前的一行“我的参赛安排”，展开后再编辑。四栏为赛事信息、参赛指南、赛事资讯、我的成绩；赛事资料先回答是什么、何时、何地、有什么项目，再提供时间线和参赛细节。个人工具保持原有深链入口，可按需展开，普通栏目切换保持当前位置。

图片沿用 JPG/PNG/WebP，每张不超过 8MB；封面 1 张、路线 4 张、配速 8 张、规程 16 页、直播二维码 1 张。已发布赛事图片立即上传并影响前台，新建时先保留在本页，创建成功后再上传。替换成功之前保留原图。缩略图与原图预览、上传状态和失败重试分别呈现。

## 完整 UI 状态组合

| 后台状态 | 主动作 | 反馈与前台影响 |
| --- | --- | --- |
| 空白新建 | 新建并发布到赛历 | 必填未满足定位字段；没有“保存草稿” |
| 新建填写中 | 同上 + 实时预览 | 预览当前输入；离开需确认，未创建服务器记录 |
| 新建成功 | 保存修改 | 立即进入赛历，返回创建 ID，后续重试不再次创建 |
| 已发布编辑 | 保存修改 | 保存更新前台，处理期间禁止重复提交 |
| 待审资料 | 保存待审资料 / 审核通过发布 | 前者仅更新审核队列，后者保存本次修改并执行审核发布 |
| 已打回资料 | 保存待审资料 | 保留打回原因与当前权限，不冒充已发布 |
| 审核已发布、详情刷新失败 | 重新加载已发布赛事 | 发布结果以成功响应为准，明确赛事已公开，锁定旧待审表单；重载只读取资料，不重复发布 |
| 待审资料保存成功、列表刷新失败 | 继续编辑 | 明确资料已保存，单独说明刷新失败，不报为提交失败 |
| 部分失败 | 重试未完成项 | 明确基础资料已发布/已保存，列出节点或图片失败；保留输入和失败文件 |
| 图片即时上传失败 | 重试上传 / 取消 | 原图保留，本次文件可重试；不将文字修改报为已保存 |

| 官方公开阶段 | 首要操作规则 | 独立个人状态组合 |
| --- | --- | --- |
| 报名时间未录入 | 有真实入口则展示，明确时间资料缺失；没有则显示入口未录入 | 未关注/已关注 × 无计划/想跑/报名/确认/完赛，互不推导 |
| 报名未开始 | 展示已录入开始日期；有报名链接时允许查看官方报名页面，避免暗示已开放 | 同上 |
| 报名中 | 优先官方报名入口；真实入口缺失则提示尚未录入 | 同上 |
| 报名截止、等待抽签 | 显示已录入中签节点；真实中签入口按日期提升优先级 | 待抽签、中签、未中签均为个人自记，不覆盖公开阶段 |
| 缴费/赛前 | 已有号码日期和入口可提升号码查询；缴费在官方渠道完成 | 确认参赛/已缴费/已领物不自动同步资格 |
| 比赛日 | 展示比赛日安排与真实号码等查询入口 | 个人计划保持原值 |
| 已结束 | 优先真实官方成绩查询；个人成绩在我的成绩单独记录 | 完赛/未完赛/弃赛独立 |
| 任一阶段无链接 | 不生成假按钮或占位 URL | 关注和计划仍可独立使用 |

Web 真实 HTTPS 地址在新窗口打开，报名二维码仅使用现有支持接口。微信小程序沿用实际支持的复制链接、二维码预览和本地导航，不假设外部网页可以直接打开，不推测目标小程序 appId。

## 数据与接口边界

本次不新增服务端草稿能力。若将来需要跨设备草稿，应单独建立 race_drafts（id、owner_admin_id、payload、revision、status、created_at、updated_at），新增受后台权限保护的创建/更新/读取接口及显式发布接口；发布需在事务内校验并创建当届 races 记录，使用幂等键和版本冲突控制。草稿必须排除在公共赛历、搜索、提醒和公开图片 API 之外；媒体需绑定草稿并在发布后迁移。仅用 localStorage 或把 pending 审核记录改名，都不能完整实现草稿权限、审核与公开边界。

现有数据没有逐字段“官方未公布”证据枚举，因此不新增该断言。未来若需表达，至少增加字段状态 missing/official_unannounced/recorded 以及 source/source_at，经过审核后才允许前台显示官方未公布。现阶段未录入不等于官方没有发布。
