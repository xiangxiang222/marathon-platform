# 跑团成员主页：设计与功能说明

日期：2026-11-11。本文说明 Web 团内成员主页及相关入口；与小程序保持资料、跑量、赛事、成绩、相册五个栏目的一致语义。

## 1. 页面目标

成员主页是一份团内可读的跑者档案。用户可以了解一位团友是谁、日常在哪个训练组、近期跑了多少、参加什么赛事、取得哪些成绩，以及一起训练时分享的照片。页面沿用清爽白卡、浅灰背景、少量天空蓝／薄荷／杏金／柔紫分区，品牌红只用于选中与操作。

主页使用现有路由 `/clubs/:id/members/:uid`，不复用 `/me/runner` 私人跑者中心。排行榜与报表进入跑量栏，成员目录与日常名单进入资料栏。完整五栏属于同一份档案，不增加五个独立页面。

## 2. 顶部身份与累计指标

- 轻量白色标题栏包含返回入口与“跑者主页”，返回目标由进入页面的业务上下文生成。
- 头像为 72px 规整圆角图，缺少头像时用昵称首字占位。昵称为 25px 主标题，长昵称换行；本人有小号“我”标记。
- 次级行显示团内角色、当前训练组；加入日期单独显示，避免与身份挤成一长行。
- 三项关键指标分别为团内累计公里、累计运动次数、完赛赛事数。前两项始终来自 `mileage.all`，不随所选统计周期改变。
- 累计公里／运动次数可进入累计跑量；完赛赛事数进入成绩栏。顶部指标与跑量栏的“本期跑量”保持明确区分。

## 3. 五个栏目

### 资料

包含跑者介绍、常设训练组、常用配速、训练组说明、团内角色、加入日期、参赛标记与团内影像数量。

介绍支持原有 300 字限制。只有本人出现“写下介绍／编辑介绍”；保存使用独立的 `PUT /me/introduction`，成功后更新当前档案，失败保留输入并允许重试。其他成员只读。训练组由跑团管理分配，个人页不额外提供有歧义的自主归组按钮。

### 跑量

- 日、周、月、年、累计五档；自然周从周一开始，日期口径为北京时间。
- 支持前后周期和日期选择；不能跳到未来统计周期，累计时停用周期翻页。
- 主卡显示当前周期公里、运动次数、运动天数、运动时长、平均配速；当前周期标“本期跑量”，累计才标“累计跑量”。
- 下方显示当前周期最近 20 条已计入本团的运动明细：日期时刻、类型、计入公里、时长、配速。
- 空周期有明确的文字空态，不画无数据曲线，不把累计数当本期数。
- 页脚提示“按本团计入规则统计 · 北京时间”。

### 赛事

赛事卡按公开参赛标记展示日期、赛事名称、地域、类型、原始状态和已记录成绩项目，可打开既有赛事详情。

提供全部、待参赛、已完赛、想跑四种筛选。待参赛为未来赛事中仍有效的参赛状态；想跑、未中签、弃赛、未完赛、完赛不会混入。想跑独立展示参赛意向，不计入待参赛。已完赛以已发生且状态完赛或已有成绩判定。具体标记状态仍直接显示，避免将“想跑”表达为报名成功。

赛事数据不随跑量周期筛掉。标题区的赛事总数和即将到来数量来自全量公开记录汇总。

### 成绩

上方用浅杏金卡展示各项目 PB：项目、净成绩、赛事名称和日期。PB 的口径为已有的线下路跑成绩，依据 API 提供的标记，不在前端推测核验等级。

下方成绩履历展示日期、赛事、项目、配速与成绩，支持按项目筛选。PB 标记用小号文字强调。每条记录都能打开相应赛事详情，完整保留原赛事操作流程。

### 相册

- 以团练活动分组，显示活动名、日期、照片／视频数；网格为三列方形缩略图。
- 点击照片打开大图，视频打开播放器；支持上一张／下一张、方向键和 Escape。
- 浮层有明确关闭按钮、键盘焦点约束与焦点恢复；打开时锁定页面滚动，关闭或离开页面时恢复。
- 媒体使用现有 `mediaSrc(id)` 生成鉴权地址，不直接信任数据中的外部 URL。
- 只展示该成员在本团活动中上传且已公开展示的媒体。其他成员的入口为“相册”，本人为“管理相册”，均去既有活动相册页。
- 不增加重复上传入口；不展示运动凭证截图、私人照片库或设备数据。

## 4. 入口与返回上下文

`memberProfileLink()` 统一生成入口；`memberReturnTo()` 对返回目标限定为当前跑团及其既有活动／约跑／队内赛／接龙页面，另允许现有赛事详情。外部地址、其他跑团、控制字符和非业务路径回退到当前跑团。

| 入口 | 默认栏目 | 保留的上下文 |
| --- | --- | --- |
| 跑量排行榜 | 跑量 | 范围、日期、训练组筛选、昵称搜索 |
| 周／月／年报表 | 跑量 | 报表周期、统计日期、主看板筛选、展开的报表区 |
| 跑团成员目录 | 资料 | 成员分区、昵称搜索、角色筛选 |
| 团练报名／出勤名单与头像 | 资料 | 活动 id、当前栏目、展开的报名组 |
| 日常签到／出勤排行 | 资料 | 当前跑团分区 |
| 赛事名单／成绩榜 | 赛事／成绩 | 原跑团分区 |
| 队内赛／约跑／接龙名单 | 资料 | 原详情页 |
| 会费成员名单 | 资料 | 会费分区；已离团记录保持只读文字 |

链接依据稳定 `userId`，不根据昵称猜用户；没有用户 id 的历史记录保持文字。姓名的点击区域清楚，原来的赛事成绩、管理按钮、报名与导出功能保持各自入口。

URL 中 `profileTab` 保存当前栏目，`range/date` 保存个人跑量周期，`returnTo` 保存原页面上下文。刷新个人主页可恢复当前栏目；个人主页更改统计周期不会覆盖返回来源的筛选。

## 5. 接口与状态管理

主请求：`GET /clubs/:id/members/:uid/profile?range=day|week|month|year|all&date=YYYY-MM-DD`。

| 字段 | 用途 |
| --- | --- |
| `user`、`group`、`mine` | 身份、介绍、归组及本人编辑权限 |
| `mileage.all` | 顶部固定累计指标 |
| `range/date/period/stats/recentRuns` | 跑量周期、汇总与最近明细 |
| `summary` | 全量赛事、成绩、媒体数量与 PB |
| `races` | 公开赛事标记及嵌套赛事／成绩 |
| `results`、`summary.pb` | 成绩履历与各项目 PB |
| `albums` | 本团活动分组的公开媒体 |

周月年报表使用 `GET /clubs/:id/mileage/report?kind=week|month|year&date=YYYY-MM-DD`。报表姓名使用该报表周期打开个人跑量，而返回后保留原主看板周期。

每次请求同时绑定当前账号、跑团、成员和递增版本。账号切换、跨团或换成员后清空旧档案、编辑状态和媒体浮层；过期响应不能覆盖新页面。周期快速切换只接受最后一次请求。失败显示可重试状态，不把旧成员的内容继续显示为新成员。

后端负责同团权限和可公开数据范围。界面不显示私人收藏、设备连接、运动凭证、私密参赛故事与审核证明。

## 6. 视觉、响应与可访问性

- 大区块 16–20px 间距，白卡约 17px 圆角；顶部天空蓝、训练组薄荷、PB 杏金与相册柔紫仅在局部出现。
- 一级昵称 25px；章节 16–21px；正文以 12–14px 为主，辅助日期与元信息更小。数字用等宽数形，信息不靠颜色单独传递。
- 320px、390px 与桌面布局都可阅读；长昵称、训练组名与赛事标题允许换行；网格与 PB 列使用 `minmax(0,1fr)` 避免撑宽。
- 栏目和筛选带可理解的 ARIA 名称、当前／选中状态；日期按钮和大图操作有明确标签。媒体浮层支持键盘与关闭后的焦点恢复。
- 不引入新图片依赖或自动生成跑步照片。实际照片来自活动已有内容。

## 7. 实现与验证清单

主要实现：`web/src/views/ClubMember.vue`、`web/src/member-profile-navigation.js`。入口适配：`MileageBoard.vue`、`Club.vue`、`Activity.vue`、`Meetup.vue`、`Internal.vue`、`Call.vue`。

定向验证覆盖五栏切换、周期语义、顶部累计不变、赛事状态筛选、成绩项目筛选、相册鉴权与键盘关闭、本人介绍编辑、返回上下文、长文窄屏与构建。独立浏览器验收由统一脚本补充；所有模拟接口拦截在内存中，不向线上写入。

## 8. 实际展示产物与模拟口径

入口为 `design/previews/member-profile-20261111/index.html`。这是纯静态预览，不需要登录、连接业务接口或启动应用。支持五个栏目、边界状态、历史与报表三组场景，按 Web／Mini 与 320／390 像素筛选；点击截图可看完整原图，方向键切换，Escape 关闭。筛选与图片预览仅作用于画廊。

### 截图与应用行为

- `web-gallery/` 是当前真实 Vue 源码在 Chrome 中的截图，使用严格内存接口拦截。共 36 张：五栏正常态、五栏空态、错误态、长昵称、本人编辑、相册大图、历史跑量、历史周月年报，各 320／390 两个宽度。
- Web 捕获同时完成 28 项检查；历史周、月、年报都实际点击过姓名，确认进入对应周期的成员跑量，并返回原日期／报表。错误态实际执行过重试。
- `web-smoke/` 是更早的交互短专项，13 项通过，覆盖导航返回校验、栏目刷新恢复、介绍保存、鉴权图片、方向键、关闭后焦点恢复和看板筛选恢复。该短专项与主画廊 fixture 的数量不同，不拿其数量充当展示数据库数据。
- `mini/` 为当前 WXML／WXSS 和真实页面派生数据生成的浏览器源码镜像；Mini 原生控件、页面标题栏及微信运行时存在近似，不能表述为真机截图。原生编译、VM 逻辑与镜像布局分别有报告。
- 画廊所展示的历史报表不是新的产品入口；应用仍使用原有“近期明细、报表与规则”分区。Mini 沿用跑量页既有报表入口。

### 展示 fixture

主画廊使用隔离的合成场景，固定时钟为北京时间 **2027-01-01 00:30**，浏览器时区为纽约，用于检查统计日不被本机时区改变；画廊的日期不是当前实际日期。

每份有数据档案用于展示 5 条赛事标记（完赛 2 场、中签 1 场、想跑 1 场、未中签 1 场）、2 个不同赛事的项目 PB、2 组活动相册与 4 张跑步插画。跑量各周期用不同数值验证本期与累计分离；空态场景明确将统计、赛事、成绩与相册清空。插画为本地代码生成的合成训练场景，不是真人照片；参赛结果、成绩和公开状态均为展示字段，不代表真实报名、真实中签或官方核验。

Web 主画廊的昵称带“【模拟】”；Mini 镜像场景沿用 fixture 昵称，画廊与本文统一标明其模拟属性。Web 图片请求仍经过当前 `mediaSrc()` 鉴权路径，但只由内存拦截器返回插画；画廊 PNG 本身不含可用账号凭证。

### 人工目检

已逐张检查两端 320px 的双列 PB 卡、`01:47:05 / 04:08:40` 成绩数字、顶部累计公里／次数、跑量主数字、长昵称和成绩履历。双列数字保持完整，长文本换行，不横向撑出视口。

同时查看两端零跑量、空成绩、空相册和加载失败：空态保留各自标题与说明，错误态保留重试入口，没有用虚构成绩填空。Web 截图在页面稳定后强制回到顶部，避免浏览器恢复旧滚动位置造成标题截断。

### 已完成的产物检查

主画廊目前引用 **84 张**场景截图（Web 40、Mini 44），含 Mini 历史周／月／年报和报表空态／错误态。静态画廊在 1440px 与 320px 检查全部场景、平台、截图宽度组合，共 36 种组合；文件链接、横向溢出、展开原图、方向键和 Escape 均通过。Web 28 项场景检查、13 项导航交互、独立 Web 20 项、Mini 39 项 VM、44 张镜像与原生编译报告分开列出，避免把镜像数量当原生功能测试数量。最后一次授权修正将“想跑”与“待参赛”分离，另用两宽定向检查验证筛选不重叠，并刷新全部赛事、待参赛与想跑截图。

Web 复现脚本为 `web-gallery-audit.cjs`、`web-smoke-audit.cjs`、`web-races-filter-audit.cjs`、`gallery-audit.cjs`，位于主画廊目录，均从仓库根目录用 Node 执行。前三个启动独立本地 Vite 并拦截业务 API；后一个只打开静态 HTML。`artifact-manifest.json` 列出本次 Web 展示产物和引用的 Mini／独立验收依赖，便于精确提交。`web-source-manifest.json` 记录最后筛选修正后的 Web 源码 SHA-256；Mini 原生编译及源码摘要沿用独立报告，没有因 Web 条件修正重复生成。


### 与正常场景数据演练的区别

页面截图 fixture 与数据库增量造数是两套独立验证。最终本地克隆演练覆盖 200 个合成账号、10 团、490 个目标会员关系；新增 1,800 条运动记录分布在当前 6 日、当年 2 月／6 月及上一年，使日、周、月、年、累计有正常时间层次。

另有 6 场明确模拟赛事：未来想跑／中签各 1 场，过去 4 个不同日期赛事各对应 1 个成绩项目；共 800 条成绩、每人 4 项 PB、200 份带“【模拟】”的简介、490 份本人在本团公开展示的训练插画。每团原有 5 组加新 A–F 共 11 个常设训练组，均有成员。

该摘要为本地克隆演练口径：7,310 项数据检查无失败，18,422 条既有记录无非授权变化，继续执行新增写入数为 0。生产应用由主任务另行执行和报告，本文不将本地演练表述为线上已完成，不把模拟中签／成绩／插画表述为真实报名、付款或官方核验事实。
