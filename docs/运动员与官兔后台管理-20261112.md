# 运动员与官兔后台管理

后台“内容运营”新增“运动员管理”和“官兔管理”，平台管理员可搜索、筛选、分页查看已有采集人物，也可新建个人档案。最近创建或维护的档案优先显示，未编辑的采集人物保留榜单顺序。

可维护姓名、英文名、性别、头像图片地址及预览、出生日期、籍贯、队伍、城市、简介，以及完整 Markdown 人物文章。运动员还可编辑全马PB、赛季成绩、个人最好成绩及比赛履历；官兔按人维护多场 A 类赛事，记录赛事、日期、距离、目标组别、配速和任职状态。支持全马、半马、10公里及5公里，目标配速按实际距离计算（半马1:30对应约4:16/公里）。已担任与入选公示分开，“曾任官兔”只收录已完成的任职经历，未来日期不能标为已担任。关联已收录赛事时复用原赛事ID，并统一CAA目录编号与赛历编号。后台保留采集证据，阅读页继续只展示整理后的个人内容。

操作流程：新建或打开人物，填写资料与正文，通过“文章预览”检查效果，再选择“存为草稿”或“发布档案”。已发布档案可继续编辑、下架和重新发布。为已公开人物存草稿时，读者仍看到上次公开版本；新人物的草稿只在后台可见。下架不删除资料，自动采集也不会令其重新公开。

人工改稿保存在 SQLite `content_profiles`，按字段覆盖采集数据，不直接改写采集文件。未修改的赛季成绩、排名和记录继续跟随采集更新；已改写的正文等字段保留。编辑版本与采集基线均进行冲突检查，防止覆盖他人的修改或把已更新的成绩写回旧值。发生冲突时保留本地稿，重新载入并对照后再保存。

新建运动员不自动加入官方百强名次，前台使用“运动员档案”及无排名标记。原有运动员、官兔及历史详情链接继续可用。

管理接口：

- `GET /marathon/api/admin/content/profiles`：按 `type`、`gender`、`status`、`q`、`page`、`pageSize` 查询。
- `GET /marathon/api/admin/content/profiles/:id`：读取完整编辑稿及版本。
- `POST /marathon/api/admin/content/profiles`：新建人物。
- `PUT /marathon/api/admin/content/profiles/:id`：保存草稿或发布。
- `DELETE /marathon/api/admin/content/profiles/:id`：下架，保留内容。

所有管理接口使用已有平台管理员认证。前台继续使用原有 `/content/profiles` 列表与详情接口，无需另建人物访问入口。
