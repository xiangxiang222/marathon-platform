# 成员主页模拟数据增量验收

本批仅覆盖原 200 个合成账号（id 8–207、昵称 `测试跑者001` 至 `测试跑者200`、创建时间 `2026-11-10T14:49:00.392Z`），并与仓库外原始账号清单逐个核对。目标为原 10 个跑团（id 13–22、团长 id 1）。真实团长仅用于团管理 API，不修改其资料、运动记录、赛事计划或照片。

## 覆盖与口径

- 每人新增本月约 6 个训练日、今年较早月份及去年训练日，避免所有周期仅使用同一条记录。日期按执行批次北京时间固定，运动已完成且不与其原有记录重叠。
- 每个合成账号通过本人 `PUT /me/introduction` 补充不同的训练爱好、目标与恢复习惯简介，明确写 `【模拟】`。原有非空简介保留，头像沿用现有首字缺省展示，不添加外部头像。
- 显式启用 `--include-simulated-history` 后，仅本批新建模拟训练通过现有团长 `decision` API 人工计入本人已加入的目标跑团。报告标记为 **模拟历史团长补录**；不回拨入团日期，不修改规则，不把它描述为平台自动认定或官方核验。原有运动与计入结果均保留。
- 每人新增“想跑”“中签”未来计划，以及过去四场不同日期模拟赛事的全马、半马、10 公里、5 公里成绩，每人每场仅一项目。赛事、计划与成绩均为演示内容。新中签赛事具有已开奖、待缴费时间节点；想跑赛事尚未公告报名节点。
- 沿用已有常设训练组名称、容量与介绍，并补齐 A–F 组；只调整这些合成账号的归属，保证每个现有组至少有一名合成成员。真实成员归属不改。容量不足、组多于可分配成员等情况会明确停止。
- 每个合成账号在其**每一个已加入的目标团**，都有自己上传且 `shown` 的活动照片。成员页按本团过滤，不使用其他团照片或私人跑者媒体充数。
- 四款本地矢量插画（公园、赛道、山径、奖牌）分别导出 960×540 PNG，画面明确写“模拟训练插画”“非真人照片 / 非完赛证明”。不使用一像素占位图，不冒充证书。

## 执行入口

默认仅只读规划，不启动应用服务，也不调用写接口：

```sh
node scripts/seed-member-showcase.cjs \
  --database /path/to/before.sqlite \
  --cohort-manifest /private/accounts.json \
  --run-dir /private/member-showcase-plan \
  --include-simulated-history
```

隔离演练会自动使用 SQLite backup 复制数据库至独立 run-dir，再启动当前源码的本地临时 API。无需复制旧媒体，本次新增图片必须可读取：

```sh
node scripts/seed-member-showcase.cjs --rehearse \
  --database /path/to/before.sqlite \
  --cohort-manifest /private/accounts.json \
  --run-dir /private/member-showcase-rehearsal \
  --include-simulated-history
```

实际应用由主任务部署后协调执行：同一命令改为 `--apply`，提供真实数据库、私有 `.env` 和 loopback `--origin http://127.0.0.1:3790`。应用模式不会自行启动、部署或重启生产服务，也不接受公网 API 目标。数据库与 API 必须属于同一实例；只读连接用于身份、归属与结果核对。

仓库外 run-dir 保存绑定数据库和模式的 `ledger.json`、旧行哈希 `baseline.json`、`plan.json`、完整 `report.json`，均为 0600 权限，目录为 0700。续跑使用相同 run-dir；不要将演练 run-dir 直接用于生产。journal 仅记录无凭据结果，并对创建后中断的赛事、训练、相册照片做精确身份恢复。

## 验证

```sh
node --test scripts/test-member-showcase.cjs
```

独立用例覆盖跨周期日期、不与旧记录重叠及完成时间、身份创建时间拒绝、旧行保护、凭据不可进入报告、四款非占位图。默认 dry-run 对本地最新备份执行前后 SHA-256 比较，数据库内容保持一致。

完整演练会验证全部 200 账号、全部合成会员关系、各团五个周期榜单和每一位成员公开 profile；核对模拟简介非空并实际可见、每个周期有量且日＜周＜月＜年＜累计、榜单与个人页一致、赛事三种状态、四类成绩及 PB、每人每赛仅一项目、所有训练组有人、本团本人新相册可见、PNG 实际文件及尺寸。每团另对一张新图片执行带鉴权二进制 HTTP GET。所有旧表行逐行哈希核对，仅允许目标合成会员的训练组字段及这些合成用户的 `introduction` 字段变化，其他用户字段和入团日期仍受保护。

没有执行真实报名、收费、通知、设备同步、隐私同意、官方成绩认证，亦没有把私人跑史或私人照片转为公开。

## 本地演练结果

使用最新生产只读备份自动复制后完成隔离演练，**7,310 项检查通过，0 失败**：200 人、490 个目标会员关系、1,800 条新增运动、6 场新模拟赛事、800 条新增成绩、490 张本人团内可见插画，以及 200 份模拟简介。每团保留原 5 个训练组并新增 A–F 后，共 11 组，所有组均有模拟成员。50 个分期榜单和 490 个公开成员页均经真实本地 API 核对。

旧行哈希核对 18,422 行，无非授权变化。基础填充实际调用 8,477 次写接口，简介增量另 200 次。最终完整续跑仍为 **7,310 项通过、写接口 0 次**，未重复插入。默认 dry-run 对原备份 SHA-256 比较一致。独立安全与日期用例 7/7 通过。

完整私有结果保存在演练 run-dir 的 `report.json`；数据库、凭据清单和完整逐人记录不加入仓库。本脚本作者尚未执行生产写入，生产结果应由主任务实际执行后另行补记。
