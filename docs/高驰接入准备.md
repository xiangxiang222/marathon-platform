## 1. 申请路径与当前结论

赛历希望让每位跑者主动授权后，把高驰跑步摘要持续同步到个人档案、运动周报和跑团跑量 PK。申请目标为 **COROS Partner API**。

官方确认该方案提供多用户 OAuth 2.0 凭据、运动 Webhook、运动数据同步和 FIT 下载。申请要求包括已有用户基础的平台、注册公司和经授权的技术代表、安全与隐私要求，以及接受 COROS API 使用条款。不能把代码已完成、拥有网站或填入一组密钥等同于获得接入资格。

申请步骤：

1. 核对下面的主体、联系人、真实运营规模和页面链接；提供能证明当前用户基础的材料。
2. 由公司授权的技术代表填写 [COROS API 申请表](https://coros-teams.feishu.cn/share/base/form/shrcnLqSduZsaNhbvDJTO2x0Vlf)。
3. 按 [官方申请说明](https://support.coros.com/hc/en-us/articles/17085887816340-Submit-an-API-Application) 向 `api@coros.com` 提供公司资料、技术联系人及 OAuth 2.0 回调地址。
4. 阅读并接受厂商条款，完成身份与安全要求核验，取得正式协议、接口文档和应用凭据。
5. 使用获批的测试账号验证授权、续期、推送、去重、撤销、历史记录范围及国区账号支持，再申请生产使用。

官方 [Partner API Access](https://support.coros.com/hc/en-us/articles/53181766856724) 列出了授权、访问令牌、刷新、撤销、绑定状态等能力，但公开介绍不足以确认实际 URL、参数、响应格式、推送鉴权和重试契约。当前代码保持自动接入关闭；后续必须按获批文档实现，不使用猜测的端点或签名。

官方另有无需申请的 [Build on COROS MCP](https://support.coros.com/hc/en-us/articles/53181619102996)，允许应用实现 OAuth，让每位用户访问自己授权的数据；该路径没有 Webhook，不提供 Partner API 的运动同步与 GPX 能力。它可以用于单用户数据工具的探索，但本次申请连续自动同步时不能将 MCP 的可用性当作 Partner API 已获批。

## 5. 安全、授权与删除方案（计划态）

以下为接入后的设计约束，需实现并验收后才能在申请中表述为现有能力。

- 跑者主动发起连接，跳转到高驰官方授权页；赛历不收集或代填高驰账号密码。展示授权目的、数据范围、历史范围、保存方式和跑团可见边界，不默认勾选授权。
- 由服务端以一次性、短时有效且绑定当前用户的 state 关联回调；回调不得接受客户端指定任意用户。失败、过期、拒绝授权和重复回调均有明确结果。
- 厂商令牌仅存服务端并加密，密钥与业务数据分离；不返回网页/小程序、不写到日志、仓库或公开材料。刷新、并发同步、断开和删除账号需统一处理。
- Webhook 只有按官方协议通过鉴权后才能触发拉取，不直接信任来路不明的运动正文。以官方账户和运动唯一标识做幂等处理，并避免与现有导入记录重复计入。
- 只保存声明用途所需摘要；不收集实时位置，不以运动推断官方赛事成绩。跑团成员仅看到与既定权限及排名用途相符的信息，不展示厂商身份或令牌。
- “断开高驰”应停止后续同步、撤销厂商授权（按官方支持方式）、清除访问和刷新令牌，并使在途请求不能继续写入；向用户明确断开后已导入摘要是保留还是另行删除。
- 删除运动记录后，重复推送不应悄悄恢复；删除账号时清理关联凭据、状态和运动数据，执行与隐私政策一致的保留与删除规则。
- 上线前完成身份隔离、state 重放、令牌过期、厂商取消授权、Webhook 伪造、重复通知、更新/删除、时区、未来记录、跨来源去重及 PK 规则回归。

## 6. 当前可用的文件导入与边界

这部分属于本次代码实现，与未来 Partner API 自动授权分开：

- 网页与小程序可从运动页及数据来源／设备页导入单场 FIT / TCX 活动文件，每次一个、不超过 5 MB。导入器不限品牌，高驰、佳明、颂拓等设备导出的文件均按实际格式与内容校验；不承诺每个品牌或版本的所有文件均兼容。只接受能识别的已完成跑步活动，路线文件、训练计划、骑行及未来运动不作为跑量入库。
- 文件来源不等于厂商核验。导入来源标为“文件导入”，跑团 PK 按手填规则判断，不获得“设备自动同步”的可信标识，也不自动增加团练积分。
- 跑步类型与爬升分别保留“未知”状态。TCX 未提供可靠类型时请本人确认，未提供爬升时不填为 0；FIT 缺少明确子类型时也保持待确认。FIT 区分路跑、越野、跑步机、室内跑、操场和虚拟跑；只有确认的路跑与越野可按当前跑团规则参与 PK，其他类型及未知类型仅计入个人跑步统计。越野爬升未知时暂不计 PK，补填后再按规则判断；明确填写 0 表示已知零爬升，不能与缺失混用。
- 去重使用同一账号的活动开始时刻等摘要，不依赖四舍五入后的公里数。开始时间相差不超过 60 秒，且距离、用时接近时，同场先导入 TCX、后导入完整 FIT，可在现存记录上补全类型、爬升等缺失信息；本人已修改的字段、既有来源和管理员 PK 处理保留。距离接近指差值不超过 0.1 公里与两份较短距离的 2% 中的较大值；用时接近指差值不超过 60 秒与两份较短用时的 2% 中的较大值。仍存在的记录发生距离／用时明显冲突、或不能安全确定唯一同场时，返回冲突提示（409），不新增或覆盖，须先到运动页核对。
- 已有手填跑步／越野记录也使用 60 秒窗口，不再只比较分钟字符串；手填时间按北京时间所填分钟的第 0 秒比较，文件使用实际开始秒数，恰好 60 秒包含、61 秒不合并。唯一且摘要接近时关联原手填记录，完整保留手填内容、来源及 PK 判定；多个候选或摘要冲突时拒绝。骑行手填不作为跑步候选。
- 本人已删除的已导入记录留下删除标记，同场其他格式或更完整文件也不会自动恢复；补全应在现存记录上进行，不需要先删再导入。删除标记不占用整个前后 60 秒：仅时间邻近、摘要明显不同的另一场可以导入；精确外部编号或精确开始秒数撞到删除身份，摘要冲突时仍拒绝，并提示核对导出文件，不引导查看已不存在的记录。解析后仅保留摘要，不保存原文件、轨迹和心率。
- 补全后，同场各导入映射的距离、用时、类型和爬升均更新为最终接受的记录；后续文件按新摘要比较。各导出文件原来的时间和哈希保留，新别名以最早精确开始时间为 60 秒锚，手填关联的文件也遵守此锚，避免逐份偏移而无限延长匹配窗口。旧库已丢失开始秒数时，仍存在的相邻分钟记录保守拒绝；已删除的旧记录只在摘要接近时拦截，并使用删除专用提示，不占用摘要明显不同活动的时间窗口。
- 导入服务端在隔离解析任务中处理文件；真实高驰导出样本、不同 App 版本与微信收发文件流程仍需真机验证。测试样本通过不等于已完成厂商联调。
- 小程序需先把导出的活动文件发送到微信文件传输助手，再在设备页选择文件。具体高驰 App 中文菜单名称、分享与导出入口、不同系统能导出的格式，**尚未依据当前真机版本核对，不承诺固定点击路径**。可在 [COROS 官方支持中心](https://support.coros.com/) 查找当前版本的导出说明，并用本人单场跑步数据验收。
