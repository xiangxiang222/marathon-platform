# 我的跑史：首期实现与验收

2026-11-01，本地工作区实现。依据 [MAKAKA 调研与跑者成长档案方案](MAKAKA调研与跑者成长档案方案.md)，用户选定“看懂成长并生成有个人味道的比赛回顾”，本期不收费。本文件记录可运行范围，不代表已部署或已完成微信真机验收。

## 使用入口与旅程

网页 `/marathon/history`；微信小程序 `pages/history/history`。两端的「我的」及跑者生涯均有入口。

1. 选择成绩截图 / 证书、CSV / JSON 文件，或粘贴成绩文字。没有资料可手动记一场。
2. 图片逐次取得临时解析同意；在服务器本地识别，返回文字后生成候选。逐条核对赛事名、真实日期、项目、参赛形式、状态、计时口径和用时，由本人确认归属后保存。无法识别的字段允许补填。
3. 「看成长」显示个人突破、已记录跑史起点与时间轴；「拾回忆」展示自己的感受、标签和代表照片。搜索比赛 / 城市，按年份筛选。
4. 打开单场回顾，查看用时、同口径进步、此前比较对象、本人感受和事实依据；补充图片或更改代表照。支持导出完整 JSON / CSV，以及单场回顾文字。
5. 可编辑或删除新记录及其资料。原有成绩在跑史中作为私人覆盖层，移除时只从跑史隐藏；原成绩 / 原收藏在原入口单独管理。

## 数据与判断范围

- 私人记录独立存于 `race_history_entries` / `race_history_media`。不要求关联公共赛事，不自动写入公共赛事表、跑团排行或训练跑量。支持全马、半马、10 公里、5 公里及其他项目，路跑 / 越野 / 其他，线下 / 线上，完赛 / DNF / DNS。完赛可以没有用时；用时上限 72 小时。
- 净计时、枪声计时与口径未确认用时分开保存。原有成绩默认“口径待确认”；确认前可查看但不混入新成长比较。净计时不得长于同场枪声时间。
- PB 与进步只比较已记录、已发生、线下路跑、同距离、同计时口径的有效完赛。相同日期不推定先后。没有分段时不推断掉速、撞墙或补给问题；不推断训练原因、全国排名、年龄组分位或未填写的情绪。
- 来源标注“本人记录 / 导入后本人确认 / 原有成绩”，不冒充官方核验。首场指“本账号已记录最早”，不宣称用户人生第一场。
- 自由文本通过明确项目字段及完整值、独立的“全程马拉松 / 半程马拉松 / 全马 / 半马”名称，或“全程：男子 / 10公里：公开组”等项目与中立组别标题确定项目依据。“上半程”、分段用时和补给间隔不提供项目或参与项目冲突；净计时仍可保留。独立的“全程 / 半程 / 5公里 / 10公里”等短值本身不能定项，但同一份资料已有明确项目依据时，所有完整短值均参与冲突核对，无论它们的先后顺序，或中间是否隔着姓名、城市、号码布及普通说明；候选保留这些项目线索。15 / 25 / 35 / 50 公里等非标准距离保留原文并要求手选。多个项目相互冲突时留空并提示，网页和小程序均不会因勾选“已核对”而接受未选择的项目；更改候选字段后须重新勾选核对。
- 项目字段内用中英文逗号、分号、顿号或换行列出的所有项目均参与判断，不只保留首项。重复表达同一项目（如“全程，全马；42.195公里”）不会制造冲突。字段名按冒号或行尾识别，OCR 省略冒号时仅接纳完整项目值，“项目介绍 / 项目组”等其他栏目不会被当成项目字段。说明文字或“项目：上半程”等无效字段不能阻止采用另外写明的完赛项目；实际识别出的不同项目及非标准距离仍参与冲突判断。男子、女子组、公开组及年龄等非距离组别不妨碍明确项目，组别实际包含半程、全程或距离时仍参与判断；项目标题冒号后的内容须为这类中立组别，分段时间与补给说明不作为项目依据。
- 冒号后的组别按结构识别，不依赖固定名称名单：“精英组 / 大众组 / 青年组 / 家庭组 / 公开男子组”及自定义组名均可使用；年龄支持性别在前后、年龄区间、“40岁以上 / 男子40岁以上 / 40周岁以下”等条件。其他无法确定的类别也会保留整行线索，同份资料已有明确项目时参与冲突核对，单独出现时要求确认；时间、用时、配速、补给点等说明仍排除。不同项目冲突时，网页与小程序候选展示完整的项目与组别，核对勾选不能绕过手选。
- 括号与冒号使用同一套项目注释判断，适用于完整项目名、短项目、字段值及独立行，如“全程（精英组） / 全程马拉松（大众组） / 项目：5公里（青年组）”；组别与空格保留在候选线索中。括号中的年龄、多个注释或“42.195公里”等真实距离参与判断，两个括号项目相互冲突时也不能自动取首项。拆分资料时保留括号内的逗号，顿号或斜杠列表逐项判断，辅助说明不连带丢弃其他项目。计时组、补给组、水站组、配速组等先按辅助说明排除，不能因“组”后缀成为项目依据或制造冲突；这条规则同时适用于冒号与括号写法。
- 圆括号、【】、[]、「」、『』、〔〕及花括号共用注释规则；仅在解析时归一形状，候选保留原括号和完整内容。组别与时间写在同一括号中（如“全程【精英组，03:12:45】”）或分成连续括号时，分别提取组别与时间，已有的组别或真实距离依据不会被附带时间删掉；注释前后顺序不影响判断。只有分段时间、计时或补给说明而没有组别依据时仍不提供项目，冲突候选须手选后才能保存。
- 项目、组别和时间按同一结构拆解：间隔号“· / ・”和短横线两侧必须分别是完整项目及组别，前后顺序均可，“18-39岁”等年龄区间保持完整；“全程：03:12:45（精英组） / 全程 03:12:45（精英组）”保留组别依据和完整线索。括号支持《》、〈〉、〖〗等形状，也可包住整个项目（如“【全程】 / 完赛项目：【全程】”），外层包装与项目后注释分别解析；两个整体括号项目或连接符项目相互冲突时仍要求手选。纯时间及水站、配速、补给等辅助组在这些写法下均不能确定项目或制造冲突。第一行的“[全程]”按项目文字识别，合法 JSON 导入保持原流程；长串未知连接符文本不会递归重试所有前缀。
- 组别与项目可紧邻、空格分隔或调换前后顺序：“半程马拉松大众组 / 全程马拉松男子精英组 / 精英组·全程马拉松 / 男子【全程】 / 大众组-半程 / 男子：全程 / 18-39岁全程”均保留完整项目依据。解析完整距离与用时后，剩余文字须整体符合组别或年龄条件；不会将 15 / 35 / 105 公里缩成标准项目。组别后的括号外用时（如“全程·精英组 03:12:45 / 全程·精英组：03:12:45”）不再使项目丢失。顿号、斜线列表中的中立组别按项目注释处理（如“全程、男子组 / 全程/男子”），实际出现的另一个项目仍参与冲突。分段限定词和补给间隔不因附带组名而成为完赛项目，“前半程男子组 / 上半程精英组 / 每5公里青年组”仍排除。
- 并列项目与附带用时分开判断：“半程、全程 03:12:45 / 5公里/10公里 00:48:00 / 全程（03:12:45）、半程（大众组）”均保留两个项目，中文“3小时12分 / 03时12分45秒”同样处理。空格连接的多个“项目·组别”、以及 / 至 / 到 / 或者 / ～ 等连接语及“18岁-39岁 / 18周岁至39周岁”等完整年龄前缀均参与核对。项目栏保留原标点、组别与用时；仅一个项目带用时不会删掉它，重复表示同一距离也不会误报冲突。独立分段时间和计时、配速、补给说明仍不能提供项目。
- 明确项目栏另做证据完整性核对：解析成功的前缀不能吞掉其他已打印的距离；连接语或组别语法未能解释完整时保留原文并要求手选，不能因旁边有一个明确项目就直接保存。项目字段换行后的值沿用该规则。服务端持久回归包含 2,400 个用时、组别、括号和连接语交叉组合；两端同时验收完整线索、多项目提示、核对勾选仍不能保存空项目，以及记录和 PB 未产生。
- 完赛项目栏中的距离即使只附带用时，也保留为待核对依据：“全程马拉松 03:12:45 / 全程：03:12:45 / 全程（03:12:45） / 全马用时03:12:45”与其他距离冲突时均提示多个项目，单独出现仍须手选；栏名、距离或用时换行不会改变作用范围，换行用时保留在候选原文中。分号、竖线后的项目仍沿用该栏语义；另起字段的姓名、组别和备注不并入项目栏。独立的“5公里：00:25:10”仍按分段过滤。
- 分段和补给注释逐项过滤：“全程（上半程01:05:00） / 全程（每5公里补给） / 全程（分段10公里00:50:00）”保留外层全程，注释里的距离不作为项目；“上半程和全程”只保留没有分段限定的全程。计时组、用时组、耗时组、成绩组、时间组、水站组、补给组和配速组仍不能提供完赛项目。
- 项目栏名共用定义，支持“距离 / 里程 / 项目名称 / 项目名”及原有项目、参赛和完赛距离字段，并按完整栏名匹配。中文距离按完整数字处理：“五公里 / 十公里 / 十千米”与阿拉伯数字对应，原文保留；“十五公里 / 二十五公里 / 五十公里 / 一百零五公里”等保留为非标准距离并要求确认，不抽取其中的五或十。“每五公里补给”等仍属于辅助说明。
- 米制按精确值换算，5000 / 10000 / 42195 米与对应标准项目一致；21097 米按 21.097 公里保留为非标准距离，不四舍五入成半马。千位分组如“42,195米”作为一个完整距离，数字内逗号不拆栏目，其他逗号仍作分隔。“赛程 / 路程 / 项目类型 / 项目类别 / 赛项”使用相同项目栏规则。
- 解析数字支持“伍 / 拾 / 壹拾”等大写数字、“公裡”和中文数字搭配 km；先区分完整数值与单位，保持“五千米 / 十千米 / 42.195千米”的准确换算，不把“十五 / 拾伍 / 五十”截成五或十。候选保留原写法。没有栏名的有效短距离即使尚不能定项也保留原文；“上半程和全程”只保留未被分段限定的全程作为弱证据，同份资料已有项目时参与冲突核对，单独出现仍要求手选。
- 拉丁字母 m（含大写 M）及“公尺”按米制精确换算，支持“5,000m / 五千m / 五千公尺”等完整数值；km 与 m 的单位边界分开，重复表达如“5公里（5000m）”仍为同一项目。英里保留完整数值与单位，暂不推断标准项目：“26.2英里”单独出现须手选，与半程等距离同时出现则提示冲突。项目栏名另支持“报名项目 / 竞赛项目 / 跑程”，同行、换行和核对保存沿用现有规则。
- 完整英文单位 kilometer / kilometre / meter / metre 及复数形式、kms 使用同一单位定义换算；mi / mile / miles / 英哩作为英里保留为待确认依据，不推断半马或全马。“距离（米 / m / meters / km）”中的单位作为字段信息解析，仅补给裸数字，不重复换算已有单位的值；原文保留栏名、单位与数字。同样适用于换行值及 CSV / JSON 的单位栏名。“比赛组别 / 参赛组别”沿用组别规则：半程、全程、10公里参与冲突，中立性别或组名不清掉已写明项目。
- 重复导入不覆盖更正、故事和照片；同批重复在确认时去重。删除后仅保留用户关联的身份 / 来源 hash，避免原资料重导恢复，不保留已删除记录的姓名、号码布、用时或故事。账号删除清除这些映射与新媒体。
- 已建立的私人覆盖层不随原成绩被删而丢失自己的故事和新照片；继承收藏沿用原接口与归属，不复制文件。继承资料在原收藏入口管理。

## 图片识别与存储

`POST /api/me/race-history/recognize` 需要本人登录及 `X-Race-History-Consent` 当前协议版本。识别使用 Tesseract.js、简体中文与英文模型，模型随 npm 依赖安装；运行时不向第三方识别服务发送图片，也不从用户地址读取远程文件。

单张支持 JPG / PNG / WebP，不超过 8MB、2000 万像素、单边 12000 像素。先检查尺寸，再在隔离子进程处理；同时处理一张，25 秒截止，客户端取消时终止，单账号每小时最多 60 次。原图与完整识别文本不写持久存储；临时目录只有公共模型文件。常见身份证号和手机号会在结果中遮盖，不能保证 OCR 能发现全部敏感内容；选择时应裁剪无关信息。

识别不会自动保存原图。另行选择收藏时，图片存于 `MARATHON_MEDIA/history`，本人鉴权读取，单场最多 30 个新资料；新资料与原收藏合计最多 500 项 / 512MB。导出只包含结构化资料，不包含登录令牌或媒体鉴权 URL。

相关告知统一维护于 `shared/legal-documents.json` 版本 `2026-11-01.2`。微信平台需将用户主动选择跑史文件和图片的用途加入实际声明；更新代码无法自动完成平台配置。

## 验证与复现

```sh
npm run test:history
npm run test:mini
npm run legal:check
npm run build
```

`test:history` 使用临时数据库与媒体目录，不操作现有业务数据。服务端覆盖本人隔离、净枪时间比较、DNF / 无用时、批量原子保存、重复更正保护、删除防恢复、旧收藏读取、媒体访问和注销清理。OCR 测试对一张无个人信息的合成中英文证书运行真实本地模型，验证“识别 → 一条候选 → 核对确认 → 私密保存”，同时验证未同意 / 旧版本 / 多文件 / 无效图片和尺寸超限。

浏览器验收脚本为 `design/previews/race-history-web-acceptance.cjs`，使用真实 API，覆盖 320 / 390 / 1280 宽度、回顾编辑、私密图片及封面、DNF / 缺用时、CSV / JSON 往返、OCR 同意与账户切换。小程序逻辑脚本为 `design/previews/race-history-mini-regression.cjs`，覆盖候选二次确认、失败保留、多图局部失败、账户切换、导出与继承资料处理；`test:mini` 做微信原生离线编译。

对应报告为 `design/previews/race-history-web-report.json`、`design/previews/race-history-mini-report.json`，页面截图以 `race-history-live-` 开头。小程序真实微信授权、文件选择、上传和系统导出仍需真机核对，离线编译和 VM 测试不能替代真机。

## 下一步数据接入

本期提供已拿到资料的整理与加工；尚未开通中国马拉松个人全历史查询、赛事证书自动下载、爱云动 / 跑步维生素 / 其他摄影平台的自动照片汇集。公开赛历抓取不代表取得个人查询或内容再利用权限。后续逐个数据源核实正式接口、授权方式、可查询字段和素材使用范围，适配后仍进入现有候选核对流程。当前没有收取身份证号、保存第三方登录状态或绕过验证的功能。

后续可在现有可信记录上增加年度跑史、同场跨年变化、本人选照片的回忆长图；分段回放与更深入复盘应在获得分段或运动轨迹后再做。
