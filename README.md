# 赛历

跑团一起看谁报了哪场、截止前谁还没缴，也在团里报每周的训练。满人数并且每人打卡够里程才记分，积分可以换礼品。后台可以给已收入的赛事补规程原图和报名、查询链接，自动拉到的截止日期不会被盖掉。界面以红、白、浅灰为主，日期卡使用中性色，报名和截止状态通过文字标签呈现。

公司主体与同行者众相同：北京华创科技有限公司。代码仓库在同一 GitHub 账号下，部署在同一台腾讯云，目录、端口、进程都分开，不碰 `/var/www/beiyexing`。

线上：<https://togetherbetter.cn/marathon/>

## 本地

需要 Node.js 20。

```bash
npm install
npm run install:all
npm test
npm run dev
```

浏览器打开 <http://127.0.0.1:5174/marathon/> 。接口在 `3790`。

本轮本地验收可运行 `npm run test:all`，依次执行服务端隔离数据库测试、客户端模拟接口回归、小程序原生离线编译、共创建议真实接口与浏览器联调、Web 构建。客户端脚本会在需要时启动本地 Vite；默认使用本机 Chrome，可通过 `CHROME_PATH` 指定浏览器。小程序编译需要安装微信开发者工具，可用 `WECHAT_COMPILER_PATH` 指定 `wcc-exec` 目录。真实微信授权、上传与长按保存仍需真机验证。范围、结果与未完成能力见 [本轮验收与产品缺口](design/本轮验收与产品缺口.md)。

跑团新版按「今日、活动、赛事、跑量、成员」规划，两端同步；多跑团切换、常用报名与名单优先展示。见 [跑团体验重构方案](design/跑团体验重构方案.md) 和 [跑团验收用例](design/跑团重构验收用例.md)。`npm run test:clubs` 会在临时数据库中注册五个账号、创建两个跑团，执行真实接口与浏览器旅程，再运行网页导航和小程序逻辑回归；不操作现有业务数据。

跑团面向普通登录用户直接开放创建，不再要求建团资格或普通建团审批。同名可以并存，使用城市、团长昵称和固定团号区分；默认每账号滚动 24 小时创建 1 个、同时担任团长最多 3 个，旧团和正常移交保留。团长可自愿提交组织管理授权核验，登录用户可私密反馈名称或身份问题，平台管理员在后台处理并填写理由。核验只证明提交的管理身份，不授予名称独占权；处理争议不会转移成员或账目。首期材料采用文字和公共渠道链接，不收证件照片或附件；材料仅本人和平台处理人员可见。见 [跑团开放创建与身份保护方案](design/跑团开放创建与身份保护方案.md)。

微信原生小程序放在 `miniprogram/`，用微信开发者工具打开该目录，打同一套接口。本地联调时在 `miniprogram/config.js` 把 `USE_LOCAL_API` 改为 `true`，并关闭「校验合法域名」。AppID 单独申请，不要用同行者众的。密钥只放服务器上的 `.env`。

微信登录需要在服务器 `.env` 配置 `WECHAT_MINIPROGRAM_APP_ID` 和 `WECHAT_MINIPROGRAM_APP_SECRET`。旧昵称密码账号可以登录后绑定微信；分享入团需团长或跑团管理审核。跑团分区和微信接入约束见 [跑团产品设计与微信接入规范](跑团产品设计与微信接入规范.md)。

## 运动文件与高驰接入

网页与小程序支持导入单场 FIT／TCX 跑步活动文件（不超过 5 MB），不限于高驰品牌，可从「运动」或「我的 → 数据来源／设备」进入。导入后更新个人跑量、配速与周报；TCX 没有可靠的跑步类型与爬升时会提示本人补充，缺失值不会当成路跑或零爬升。跑团 PK 按手填规则判断，只有已确认的路跑与越野按现有规则计入；跑步机、室内跑、操场和虚拟跑仅计个人统计。

同场文件去重不依赖四舍五入后的距离。后导入的完整 FIT 可以补全既有导入记录，但保留本人已修改的字段与管理员的 PK 处理；明显冲突或无法安全合并的近似记录会被拒绝，不重复加跑量。删除后重复导入不会恢复。仅保存运动摘要，不保留原文件、轨迹和心率。小程序先把已导出的活动文件发到微信文件传输助手，再从设备页选取；厂商 App 的具体导出菜单尚待真机核对，不承诺固定点击路径。

小程序文件选择还需在微信公众平台「设置 → 服务内容声明 → 用户隐私保护指引」声明“收集你选中的文件”，用途为用户主动导入 FIT／TCX 活动摘要。该声明对应 `wx.chooseMessageFile`，不能用 `app.json` 或页面内隐私说明代替。遇到 `errno: 112`、`api scope is not declared in the privacy agreement` 或 `appid privacy api banned`，请管理员核对后台声明和提审时的隐私采集选项；补充声明后约 5 分钟生效，再退出小程序重进验收。选择失败时可在数据来源页复制错误信息或网页版导入地址。依据：[微信隐私类型对应表](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/miniprogram-intro.html)、[隐私授权与错误说明](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/PrivacyAuthorize.html)。

手填跑步与文件也按开始时间 60 秒窗口去重（手填按所填分钟第 0 秒、文件按实际秒数比较），唯一且摘要接近时保留原手填内容和 PK。删除标记只保护同场及精确身份，不占用邻近但摘要明显不同的另一场；精确身份冲突会给出删除专用提示。

高驰自动同步尚未申请开通。[高驰接入准备材料](docs/高驰接入准备.md) 是待核对的申请草稿，尚未提交表单或发送邮件，英文产品名与公司英文全称也尚待确定。获得官方协议和文档后再做授权、推送与真机联调；不能仅配置密钥就启用。文件导入的测试与边界见 [跑者个人中心验收用例](design/跑者个人中心验收用例.md)。

## 共创建议与实物奖励

网页与小程序「我的 → 共创建议」支持功能、UI、问题反馈和其他想法，游客可浏览，登录后可提交与投票。内容先由平台管理员审核，公示后征集支持；票数是评估参考，采纳时由运营指定可兑现的具体奖品。采纳、开发、上线进度及公开答复持续展示在建议详情中。

后台「共创建议」负责审核、进度和奖品发货。收件信息仅本人和平台管理员可读，跑团后台账号不能读取；用户领取后运营登记真实物流，用户可确认签收。没有接入自动采购、快递下单或微信主动推送，站内「我的建议」显示进度更新。上线时需在小程序后台同步声明建议截图和领奖收件信息用途；实际奖品由运营准备和履约。接口与验收约定见 [共创建议接口与验收](docs/共创建议接口与验收.md)。

### 协议与个人信息保护

网页 `/marathon/legal/privacy` 和小程序“我的”底部提供公开的协议中心，包含用户协议、隐私政策、收集使用清单、第三方共享与受托处理清单、权限与本地存储说明、未成年人保护说明、个人信息权利与注销指引。七份正文统一维护在 `shared/legal-documents.json`；运行 `npm run legal:generate` 同步微信可加载的 `miniprogram/utils/legal-documents.js` 离线模块与 `docs/legal/*.md`，`npm run legal:check` 检查一致性。

新注册需主动确认当前协议版本；历史账号的服务端登录兼容保留。运动文件上传另行取得本次解析同意。登录用户可以私密提交查阅、复制、更正、删除、撤回或注销申请，平台后台“个人信息权利”处理回复；工单办结不会自动执行账号删除，运营人员应完成实际处理并准确回复。

协议目前为待确认版本。公开主体联系方式、受托云服务法律主体、存储地域及正式生效日期必须真实核实；相关 `LEGAL_*` 配置见 `.env.example`。完成 [发布与受理手册](docs/legal/README.md) 中的实际流程核对之前，不得将 `LEGAL_PUBLICATION_CONFIRMED` 设为 `true`。配置标记表示运营方确认，不能替代实际授权、合同、影响评估或数据清理。调研来源和事实底稿分别见 [官方来源调研](docs/合规调研与发布核对.md) 与 [个人信息处理核对](docs/个人信息处理事实核对.md)。

验证：`npm run test:legal` 覆盖文档同步、真实 HTTP/网页私密申请、管理员回复和小程序生命周期；服务端 `npm test` 另有权限、同意版本、限额与清理测试。
