# 跑团体验重构

目标：让同时加入多个跑团的跑者，在微信里快速找到下一次集合、报名入口、同行名单和自己的记录。延续赛历的红白视觉，减少首屏的表单和长文本。

## 页面结构

| 层级 | 内容与操作 | 设计原则 |
| --- | --- | --- |
| 我的跑团 | 已加入、待审核、发现跑团、口令邀请 | 优先回到已加入的团；待审核有明确状态；口令先看介绍再申请 |
| 团首页「今日」 | 团名、角色、切换与邀请；下一场团练；活动报名、赛事名单、跑量排行、跑团成员四个入口；我的待参加、会费与更多服务 | 首屏回答「什么时候、去哪儿、怎么参加」，不堆积管理表单 |
| 活动 | 团练、约跑、队内赛；组织者发布入口 | 三种活动在同一层级；日期与参与状态优先于分享接龙文字 |
| 赛事 | 成员参赛与成绩；成绩接龙；名单、长图与表格导出 | 同行名单易找，长接龙文字默认收起，不改变名单统计规则 |
| 跑量 | 排行、周期筛选、已有 PK 规则 | 与相册、动态、搭子等服务分开，避免功能混在排行榜中 |
| 成员 | 昵称与角色筛选；入团申请；会费期次；管理与个人跑团关系 | 只按真实身份筛选，不推断固定 ABC 分组；退出与移交可发现 |
| 详情 | 活动概要 → 我的参与 → 名单/照片 → 折叠的组织者工具 | 报名和打卡容易找到，长分享文案与低频管理不占据首屏 |

两端菜单对齐为「今日、活动、赛事、跑量、成员」，保留原业务入口及深链。底部全局导航继续为「赛事、跑团、运动、我的」。

## 视觉与交互

- 页面使用浅灰底、白色卡片、清晰的深色标题。品牌红用于当前状态和主要操作；一张卡片优先突出一个主要操作。
- 卡片使用一致圆角与间距；元信息降一级，姓名、时间、名额与个人状态保持可读。长团名、地点和昵称可换行。
- 操作按钮使用 flex 垂直居中，避免依赖超大行高模拟居中。网页触控操作最小高度 44px；小程序主要操作最小高度 88rpx，并兼顾底部安全区。
- 分享保留微信原生转发与真实申请路径。介绍页不展示内部成员资料；团外用户先申请、审核后才能查看团内内容。
- 切换跑团、修改分组或切换会费期次时，数据始终属于当前跑团和账号。空列表提供下一步，加载失败保留重试入口。
- 「我的待参加」与下一场团练使用同一北京时间口径：未来场次、仍在结束时间内的进行中场次；未填结束时间的旧活动，仅当天进行中场次保留，历史场次不长期置顶。首页数字与点击后名单一致。
- 成员性别与跑步水平继续仅活动组织者可见；成绩截图、私人收藏继续由服务端控制访问。

## 验证范围

功能以真实注册的多账号、两个跑团及独立临时数据库执行；测试角色包括团长、管理员、普通成员和团外用户。除正向流程，也覆盖跨团隔离、拒绝/再申请、满额、截止、取消、退出/移出和旧期次历史等边界。

网页检查 320px、390px 和桌面尺寸的真实流程、溢出及运行错误。小程序运行 JavaScript、WXML、WXSS 校验与现有逻辑回归；微信真实转发、朋友圈、设备通知与真机安全区保留为真机验证项，不把网页测试当作真机通过。

执行明细与结果见 [跑团重构验收用例](./跑团重构验收用例.md)。
