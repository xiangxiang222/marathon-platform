# Review 问题核实与处理

本次按当前代码和数据模型核实，不把历史产品设想当作已实现能力。界面方案以 [产品与 UI 改版方案](产品与UI改版方案.md) 为准，配色以 [视觉规范](视觉规范.md) 为准。

## 1. 赛事入口与分类

| Review 项目 | 核实结果 | 处理 |
| --- | --- | --- |
| 海外赛入口始终为空 | 属实。原 `inChannel` 对 `overseas` 固定返回 `false`。当前 races 表及迁移、采集字段和赛事输出均没有可靠的 `country` 或海外标记 | 移除 Web 与小程序首页的海外入口，删除固定海外分支；未知频道继续不匹配任何赛事，不回退成全部结果 |
| 路跑、越野、线上、线下是否应互斥 | 不是四个互斥类别。`kind` 表示路跑 / 越野类型，`meet` 表示线上 / 线下方式；一场线下越野应同时出现在越野和线下集合 | 保留现有四个 `kind` 查询值；两端增加类型 / 方式说明，按类型与方式分组排列入口 |
| 线上路跑是否属于路跑 | 原路跑分支额外排除了线上，与类型定义混在一起 | 路跑改为 `race.kind === "road"`；线上按 `meet === "online"`，线下按 `meet === "offline"`，越野按 `kind === "trail"` |
| 历史赛事没有参赛方式 | 模型和序列化已有线下默认值 | 保留历史默认，不因本轮 UI 调整改写赛事数据 |

证据来自 `server/src/db.js` 的 races 建表与字段迁移、`server/src/bot-races.js` 的采集映射，以及 `server/src/races.js` 的 `presentRace` / `inChannel`。没有读取用户个人数据，也没有根据赛事名、城市文字或域名猜测国家。

当前四个入口一次选择一个，类型与方式对应的集合允许重叠；本轮不增加组合筛选协议。以后恢复海外入口，须先有可信来源、结构化国家字段及从采集、审核、存储到查询的完整支持，再提供真实结果。

必要的分类单元测试放在独立 `server/test/races.test.js`：覆盖路跑 / 越野与线上 / 线下的四种组合，以及序列化后的历史默认和显式线上值。完整接口测试同时覆盖首次微信登录不建号、文件头像及绑定解绑。

## 2. 口令与入团权限

后台旧文案“口令可直接加入”和“没口令的入团才审核”与当前流程不符，已统一为：打开公开介绍 → 申请加入 → 团长或跑团管理审核 → 成员查看团内信息。口令只定位跑团，不授予成员身份；游客登录后恢复申请，待审和已加入状态分别展示。

后台说明与产品文档已使用同一审核流程。

## 3. 页面导航与日历长图

根目录 [产品方案](../产品方案.md) 已同步当前实施：

- 跑团发现按“我的跑团 → 找跑团 → 折叠创建入口”排列；详情为“概览 / 赛事 / 训练 / 跑量 / 成员”。

长图继续不包含报名状态或占位小程序码。预览保留“长按图片可以保存”提示，不增加独立保存、关闭按钮；点击遮罩空白关闭，点击图片不关闭。未修改长图绘制逻辑和预览交互。

## 4. 微信首次使用、绑定与解绑

未知 OpenID 默认返回 `409` 及 `WECHAT_REGISTRATION_REQUIRED`，不创建账号或写入数据库。小程序先提供两条选择：登录已有账号后使用新的 `wx.login` code 显式绑定，再恢复入团申请；或者用户确认新建后，重新取 code 并传 `createAccount: true`。已绑定的微信身份登录原账号，已有绑定不能被另一个微信身份覆盖。

解绑使用需要当前密码验证的 `DELETE /me/wechat`。没有密码时先设置密码；验证失败不清除 OpenID，成功后保留账号、跑团和记录，仍可用密码登录。不能因解绑或失败请求隐式再建账号。

服务端认证专项的 9 项独立内存 SQLite 测试通过；小程序 8 项 VM 检查覆盖首次提示不保存登录态、登录绑定后恢复邀请、明确创建时取新 code、绑定失败保留邀请及密码解绑等流程。接口背景参照 [微信登录流程](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/login.html)。

## 5. 头像数据与图片地址

旧实现把完整图片 data URL 存入用户记录，并随成员 JSON 反复下发，存在响应负载与跨平台图片地址兼容风险。Review 中“一切微信环境都不支持 base64”的绝对判断证据不足，不能据此宣称所有客户端都无法显示；应按已确认的负载、地址与文件校验问题修复。

本轮新增 `server/src/avatars.js`：文件保存在 `MARATHON_MEDIA/avatars`，数据库仅保存文件名，接口返回 `/marathon/api/avatars/<id>/<hash>.<ext>` 短地址。上传限制为原始图片 256KiB，校验签名和 MIME。启动时将有效旧 data URL 迁移为文件；无效旧值保留在存储中但不再下发，用户需要重新选择头像。

小程序本地临时路径用于预览，先 `POST /me/avatar` 上传，再用仅含昵称的资料请求保存昵称；请求层为短资源地址补 `baseUrl`。Web 兼容原 `PUT /me/profile` 的 data URL 上传，保存后使用短地址。公开跑团介绍继续不附带成员头像名单。图片组件 API 参考 [微信 image 组件](https://developers.weixin.qq.com/miniprogram/dev/component/image.html)，不据此推断所有运行环境对 data URL 的支持情况。

## 6. 历史仅昵称账号

旧产品文档曾允许注册同名昵称给已有无密码账号设置密码；即使昵称唯一，这也不能证明账号归属，必须撤销这一规则。

确认的产品规则是：legacy 账号由管理员核验本人身份后，在原账号上重设登录密码，保留已有跑团、角色和记录。注册不能接管任何已存在昵称的账号；同名冲突由管理员核实处理。删除仍担任团长的账号前，先完成团长移交。后台现有用户编辑已支持重设密码。已同步根产品方案及 UI 方案；认证接口与登录页展示同一恢复说明。
