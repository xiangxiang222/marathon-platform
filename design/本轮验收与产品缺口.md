# 本轮验收与产品缺口

更新日期：2026-10-29。本文区分已经实现的代码、本地自动化验证、外部接入条件和尚未实现的产品需求。本轮新增修补和本地完整回归均已完成；这不等于所有最初设想都已经实现，也不等于完整商业产品已通过上线验收。

## 已实现的核心流程

| 产品任务 | 当前行为与边界 |
| --- | --- |
| 找比赛 | 搜索、日期/地点/距离/状态筛选；类型 `kind` 与形式 `meet` 独立组合；赛事日历、资讯、拿奖雷达；没有可靠国家字段时不提供空的海外分类 |
| 跑者个人中心 | 红白灰总览、下一场赛事、周/月/年/累计原始跑量、同期比较、赛事生涯、PB、年度趋势、时光轴与城市护照；证书/奖牌/照片/视频支持关联已有个人成绩后私密上传、预览与删除。成绩删除和接龙撤回不删除私人收藏，仍可由本人管理；履历统一为比赛里程，配速列表说明越小越快。Web 与小程序同步，设备连接仍待外部接入；没有虚构全国排名、卡路里或官方认证。见 [专项设计](跑者个人中心设计方案.md) |
| 参赛记录 | 成员标记想跑、报名、中签等状态，提交完赛成绩和证明；跑团按赛事聚合，个人中心汇总计划与成绩；官方报名仍在赛事方平台完成 |
| 找跑团与申请 | 游客可搜索公开目录，口令/分享先打开公开介绍；公开介绍只提供团名、团长、人数；登录后恢复申请，待审核期间无团内详情权限 |
| 跑团管理 | 概览、赛事、训练、跑量、成员五分区；申请审核、角色/团长移交、组别、会费名单及积分礼品；高负担表单按需展开 |
| 训练报名 | 三步发布、模板仅选类型与标题提示、按账号与跑团保存草稿、复制清空期次及日期；主动选组、截止与名额由服务端复核，人数校验和写入位于事务中 |
| 团内协作 | 训练签到、约跑预报名与打卡、合影、队内赛、活动相册与审核、跑量及距离成绩榜；签到入口仅在开场后显示，未开场或已取消的活动不能新增签到，已有签到后不能改期到未来；无当前报名关系的保留签到标为历史记录；约跑仅为现有日期/地点/文字说明模型 |
| 会费名单 | 开放期仅列出现成员；开放期离团/移出时事务快照未交或保留已有状态，关闭期为当时成员补齐未交并固化离团标记。关闭历史只展示快照/明确记录的人；晚加入者不进入旧期，重新加入不改历史缴费或离团快照 |
| 成绩与赛事导出 | Web：成绩接龙完整 CSV、全团赛事名单 CSV；小程序：完整成绩榜与全团赛事表格复制；两端：单场赛事画像与成绩长图。保留只有成绩、没有参赛标记的记录，并合并重复项。长图最多 350 条，完整数据使用表格/文本；没有原生 `.xlsx` |
| 退出与移出 | 普通成员和跑团管理可退出本人跑团，团长先转让；主动退出、团内管理员移出、后台移出共用事务清理，取消未来团练、未出成绩未来队内赛、明日及之后未打卡约跑报名，再解除成员关系及待审申请。当前分钟已开场的报名、当天约跑、历史签到/成绩/积分及已审核申请保留；旧异常提前签到的已有积分后续结算也保留。离团失去团内详情权限，再入团重新审核 |
| 登录与头像 | 未绑定微信不会自动新建空账号；用户明确选择绑定旧账号或新建。支持密码验证解绑，旧无密码昵称账号经管理员核验恢复；头像用校验后的文件短地址 |
| 隐私边界 | 活动敏感统计与成绩截图按服务端身份裁剪；公开介绍不带成员名单；小程序已接官方隐私授权事件、同意按钮和指引入口 |
| 页面恢复与性能 | 关键详情页有加载、失败提示及重试；失败业务操作不显示成功；未知网页路由可返回有效页面；次级页和后台按路由加载 |
| 后台运营 | 真实数据总览、内容采集待审、赛事编辑、资讯、官网同步、跑者/跑团与权限管理；待办直达入团审核，跑团管理可进入账号安全；清除历史固定默认后台账号 |

导出只包含平台中本团成员已经提交的状态和成绩，不代表已取得官方平台全体报名名单。已有训练组、距离成绩榜和统计画像，也不等于已经实现按 A/B/C 等跑团训练组组织的全部单场成绩画像。

## 已有代码仍需外部配置和运营验收

| 条件 | 当前状态与后续动作 |
| --- | --- |
| 微信正式运行配置 | 配置真实 AppID/服务端 Secret、运行主体、类目与合法 request/upload/download 域名、生产 HTTPS；本地设置不能证明微信后台已经完成 |
| 正式隐私指引 | 代码已接官方授权与阅读入口；需运营方填写并发布真实收集项目、用途、期限、处理方式与联系渠道，随后真机核对授权触发和拒绝流程 |
| 内容采集与来源 | 已有采集接口和待审发布流程；真实平台来源、字段准确性、更新频率和失败处理需持续运营核对，不能由页面样式验证代替 |
| 生产发布与运维 | 本地构建通过；正式部署、数据库备份/恢复、日志留存、监控告警和运营交接仍需在目标环境验证，本轮不声称已部署完成 |
| 运营联系与资料处理 | 需要真实客服或联系渠道、负责人及处理规则；不能编造邮箱/电话，也不能只用“联系管理员”替代可触达的产品入口 |

## 尚未实现的业务能力

| 类别 | 真实缺口 | 下一步范围 |
| --- | --- | --- |
| 设备同步 | 没有跑表厂商授权、自动回传与去重链路；现有跑量来源为手动记录 | 选择厂商与可用接口后实现授权/解绑、增量同步、幂等、失败补偿和数据删除 |
| 附近与路线 | 没有精确定位、附近约跑分发、常跑路线推荐、路线预设与收藏；配速/距离主要是文字说明 | 先确定结构化路线和隐私开关，再评估微信能力和附近推荐，不承诺自动通知 |
| 通知 | 入团与活动有站内状态，但没有完整微信订阅授权、模板、发送与重试链路 | 模板与业务触发获准后，接入用户授权、退订/拒绝、发送状态和失败处理 |
| 通用活动接龙 | 当前是训练报名、队内赛与成绩接龙，不支持任意字段、各类接力赛事结构和通用名单导出 | 单独设计字段与权限模型、接力分组、接龙记录、审核和对应表格/长图 |
| 个人主页与单场目标 | 已有“我的”记录；没有他人可访问的个人主页、单场目标/实际结果对照及逐项展示权限 | 明确公开/跑团/本人可见边界，补数据模型、服务端校验和页面 |
| 组别赛事画像 | 有训练组和距离榜，缺少完整的按跑团 A/B/C 等组别汇总、排名与导出布局 | 明确组别快照、并列/多项目规则，再设计单场及多场画像 |
| 账号生命周期 | 有登录、密码、微信绑定解绑；没有用户自助注销及完整资料删除/保留/恢复流程 | 先定义团长移交、内容历史、待办与数据保留规则，再实现验证、确认、处理状态及审计 |
| 客服与反馈 | 没有完整、已配置的用户客服/问题反馈闭环 | 提供真实联系资料、工单或反馈接收方、处理状态，和隐私/账号帮助入口相互关联 |

站内官方赛事报名、支付和代报名目前不属于本产品范围，继续通过官方渠道完成。海外赛事发现需要可信结构化来源后再恢复入口；没有数据时不以空频道占位。

## 迭代顺序

先完成微信后台配置、真实联系渠道、账号生命周期与生产运维验收，形成可运营的基础；随后补个人主页、单场目标和组别画像；再设计通用接龙。设备、订阅和附近能力需分别完成外部授权与真实链路测试，不与本轮本地页面验收混为“全部完成”。
