# 跑团开放创建与身份保护

设计日期：2026-11-01。本文为产品与交互方案，配套 [可点击原型](prototypes/club-open-creation.html)。原型使用演示数据。开放创建、同名辨识、私密核验与申诉已接入当前工作区的服务端、网页和小程序，尚未部署。

本期核验与申诉使用文字材料和公共来源链接，不提供证件照片或附件上传。默认配额为每账号滚动 24 小时创建 1 个、同时担任团长最多 3 个；存量不追删，接任不受阻。旧建团审批写接口停止开通，待处理申请由本人补城市并确认创建。真实接口与浏览器验收运行 `npm run test:club-identity`，所有账号与数据在临时目录生成并清除。

## 1. 产品决定

**任何已登录用户都能立即创建跑团。团名允许重复，身份需要辨认，冒用可以处理。**

先注册只得到一个跑团空间，不得到这个名称的独占权。真实跑团后来入驻时，可以直接使用自己的名称、核验自己的组织身份，无需向先注册的人买名字、买团或拿回成员。

名称和组织身份分开管理，人工精力集中到身份核验、冒用和异常创建。普通朋友团不需要营业执照、不需要先凑人数、不需要付费或获得平台授予的“团长资格”。

| 用户担心的事 | 产品如何回答 |
| --- | --- |
| 有人先用掉我们的名字 | 名称可以重复，你仍能用原名创建；对方不能出售所谓名称所有权 |
| 搜出来不知道哪个才是我们团 | 创建、搜索、公开名片、分享、申请加入统一展示城市、公开负责人、稳定团号；已核验组织展示核验范围 |
| 他复制团徽、冒充团长拉人 | 提交私密的身份冒用工单；平台核查具体呈现与授权，能够限制展示、要求更正或停用 |
| 我只是想和几个朋友跑步 | 填名称和城市即可使用成员、约跑等基础能力；不核验也能正常使用 |
| 我们是真实线下团，但是没有执照 | 组织身份核验支持已有公共渠道控制证明、组织授权和交叉核对，不把企业资质作为唯一凭证 |

不采用全国团名唯一，也不采用“城市＋团名”唯一；后者只是把全国抢注改成逐城抢注。不采用闲置即回收名称，季节性训练团和赛事团也有正常存在的理由。

## 2. 与现有实现的关系

当前 `clubs.name` 本来就不唯一，`clubs.id` 和 `clubs.code` 已承担定位作用，分享名片按 ID 打开。这个基础可以继续使用。

改动前的主要问题是：

- `POST /api/clubs` 要求 `user.leader`，随后进入 `club_applications` 等待平台批准；两端界面也有资格拦截。现已改为事务内直接创建与设置本团团长，不授予全局资格。
- 搜索同等相关度按 `c.id DESC` 排，新建同名页反而容易出现在前面。现按相关度、同城同名核验及固定团号排序，并由数据库分页。
- 搜索卡片和名片主要显示团名、团长、人数，缺少城市、稳定团号及组织管理关系。现已在两端创建、搜索、名片、分享与加入前一致展示身份。
- 后台只有建团申请“通过／拒绝”。现增加平台管理员专属身份核验与私密工单，旧审批只保留历史查询。

本方案开放的是**创建跑团**。申请加入跑团继续由该团团长或管理审批；平台不因开放创建而公开团内成员、活动详情或缴费记录。

## 3. 用户路径与界面

### 3.1 创建：两个必填项，马上开跑

从“跑团”页右上角进入独立创建页。移动端全屏，桌面端表单与实时名片预览并排。

| 字段 | 要求 | 界面文案 |
| --- | --- | --- |
| 跑团名称 | 必填，延续最多 20 字；禁止不可见控制字符和伪造平台状态的呈现 | 给一起跑步的人，一个名字 |
| 活动城市 | 必填，选到城市；片区可选，提供“跨城／线上” | 让跑友更容易找到你们 |
| 一句话介绍 | 选填，80 字以内 | 比如：每周三晚，一起绕湖慢跑 |

主按钮：**创建跑团**。按钮上方说明：**创建后即可邀请跑友，入团申请由你审核。** 不再显示“提交建团申请”“暂无建团资格”。

名称输入完成后查询同名与近似名称，只做辨识提醒：

> 找到 2 个同名跑团  
> 名称可以重复，看看是否已经有你要找的跑团。
>
> 西湖跑团　身份已核验  
> 杭州 · 西湖　负责人 老陈　团号 #10482
>
> 西湖跑团  
> 绍兴 · 柯桥　负责人 小周　团号 #20731
>
> 查看已有跑团　／　继续创建

同名提醒不变红、不显示“已被占用”，不强制加数字后缀，不因同名要求用户上传资质。只有发现复制组织标识、假冒授权等具体风险时，才进入相应核查。

同名查询失败时说明“暂时无法检查同名，你仍可创建”；创建接口仍独立执行名称校验与频率限制。不能让一次建议查询失败变成新的建团审批。

创建请求使用幂等键，按钮等待期间不可重复提交。提交成功后事务内完成建团、加入创建者、授予该团 owner 角色，再进入团首页。

### 3.2 创建成功：先建立真实联系

首屏：“你的跑团，今天开始”。展示团名、城市、公开负责人、团号。

优先动作是 **邀请第一位跑友**，其次是 **发布第一次约跑**。默认入团方式是申请审批，可分享公开名片；邀请口令不是名称权属证明，也不直接绕过审批。

“已有线下跑团？核验组织身份”放到次级入口。基础功能没有灰色锁，也没有“未认证，暂不可使用”的状态。

创建成功即能通过自己的跑团列表、团号、邀请链接及精确名称找到。不会自动登上“新建榜”或获得首页推荐位。当前系统没有成熟推荐系统，首期不新增推荐榜来制造曝光竞争。

### 3.3 搜索：用户找的是组织，不是一串字

名称相同的卡片采用相同布局，固定展示：

1. 名称与可点击的“身份已核验”标记。
2. 城市／片区、公开负责人昵称。
3. 一句话介绍、稳定团号；人数是辅助信息。

不在普通团上显示醒目的“未认证”“临时团”标签。新团与小团具有完整的基础使用体验。

首期排序规则明确为：先按名称精确匹配、前缀匹配、包含匹配分组；用户选择城市时在该城市内找，也可切换“全部城市”。同城同名组内，有效且范围吻合的组织核验优先，剩余结果按公开团号稳定排列。不以新建时间抢前，也不把团号顺序解释为名称归属。当前缺乏可靠运营信号，首期不加入活跃度权重。

模糊匹配的核验团不能压过精确搜索的普通团，外地大团不能吞掉本地小团。人数、公开活动量和跑量不能单独决定身份，不能花钱购买核验或身份优先级。结果分页而非只保留当前实现的前 200 条，精确团号单独直达；普通新团也能找到，后续再根据真实检索数据调整权重。

### 3.4 公开名片、分享、加入：一路保持同一身份

公开名片、微信标题及分享卡、网页分享预览、申请加入前的按钮附近，都保留城市与团号。进入链接后按团号打开指定跑团，不按团名重定向。

示例：**西湖跑团 · 杭州西湖 · #10482**。常驻负责人用其自选公开昵称，不强制公开身份证姓名、手机号或微信号。

核验标记打开说明抽屉：

> **组织管理关系已核验**  
> 核验对象：西湖跑团（杭州西湖）  
> 本页面由该跑团的授权负责人管理。  
> 核验时间：2026-11-01  
> 核验不授予名称独占权，也不代表对活动安全、赛事成绩或商业服务的背书。

“更多”中提供 **名称或身份被冒用**。普通同名本身不加风险条；用户举报后也不会立即向公众展示“涉嫌假冒”，避免恶意举报破坏正常团。

## 4. 组织身份核验

核验证明的是**页面与真实组织之间的管理授权关系**。不评选“正规跑团”，不授予“官方跑团”身份，不给“西湖”“晨跑”等泛称排他权。

### 4.1 提交内容

由 owner 在“跑团管理 → 跑团身份”主动申请，基础使用不受申请状态影响。

| 内容 | 用途与原则 |
| --- | --- |
| 组织名称、活动范围、当前团号 | 明确核验的是总团、城市分团还是某个独立组织 |
| 负责人联系方式 | 仅平台处理人员可见；不放入公开名片 |
| 既有公共渠道链接 | 例如长期运营的公众号、官方站点、赛事组织页面 |
| 管理授权与控制证明 | 由既有渠道确认本团号／一次性核验码，或经可验证渠道确认授权关系 |
| 可选辅助材料 | 过往组织活动记录、说明与必要的脱敏截图 |

没有公共账号的民间团，允许走人工交叉核对：核对既有活动组织记录、不同来源的组织联系人及授权说明。只凭一张群截图、团服照片或拉来若干成员，不足以证明组织管理权。资料不足先补充，不自动认定造假。

核验材料私密提交，不进入“共创建议”的公开展示、评论或投票流程。申请人自己的身份证全件不作为默认必填项；材料只保留核验需要的内容。

### 4.2 状态与变更

`未申请 → 待核验 → 待补充 → 已核验／未通过`；通过后还可能进入`复核中／已撤销`。未申请不在公众界面显示标签；待核验仅管理者可见，不能生成看起来像已经通过的公众徽章。复核或撤销后公众徽章立即失效，决定记录保留，管理者可补充或申诉。

认证绑定组织、当前团号和授权范围。总团可以授权城市分团，不能一个杭州分团自动垄断全国同名团。不同的同名组织可以分别核验，徽章说明清楚各自范围。

移交 owner、实质更改组织名称／范围／关键授权渠道后，保留原核验记录并发起复核；复核期间停止展示“已核验”，团内历史与基础功能保留。普通联系人修正不应机械触发整团停用。

存量平台审核通过的跑团不自动变成“身份已核验”。过去审核建团不等于已经核实线下组织授权。

## 5. 争议：处理冒用行为，保护团内资料

### 5.1 用户入口

“名称或身份被冒用”先分三种情况：

- **同名容易混淆**：提供城市、简介、团号辨识建议；可请平台协助核对，不默认处罚。
- **有人冒充我们的组织**：提交对方团号、误导位置、组织公开来源、可核对的授权与私密联系方式。
- **跑团管理权发生争议**：独立核对现有 owner 与申请人的授权，不让创建新号变成接管旧团的捷径。

提交后给私密工单号和进度。团外申诉不要求先加入对方跑团；游客先登录，以便补充证据和接收站内进度。同账号、同团号、同类反馈已有待处理工单时，保存最新提交的完整说明、公共来源和联系方式到原工单，保留原创建时间；界面区分新建、已更新及内容相同，不能只退回旧材料却提示成功。完全相同的重试不重复建单或刷新事件。

### 5.2 处置规则

| 情况 | 可采取的动作 |
| --- | --- |
| 只是同名，组织不同且表达清楚 | 正常并存；建议完善城市和简介，不强制改名 |
| 辨识不清但没有足够冒用证据 | 让被反馈方补充说明或更正呈现；不公开定罪 |
| 有具体证据证明未经授权复制组织标识、冒充授权或误导招募 | 要求更正名称／标识／说明，停止争议核验标记；按严重程度限制公开搜索和分享 |
| 有明确证据的持续恶意批量冒用 | 限制相关创建能力、公开展示或停用；保留处理理由和申诉入口 |
| 双方材料冲突、管理权尚不清楚 | 要求双方补充，必要时暂时减少争议身份的公开曝光，冻结高风险的身份变更；不强制移交 |

**绝不把对方的成员、会费、私人图片、历史活动或账号控制权作为“认领名称”的附赠品交给申诉人。** 真实组织可以新建自己的核验页面，成员自行选择加入；平台不能替成员把关系和隐私打包迁移。

核验通过本身不自动触发其它同名团处罚。一条举报不自动下架；只有有具体证据的风险才由平台采取临时措施，并通知理由、影响范围、补充途径及复核入口。

材料原则上只给有权限的处理人员。被反馈方收到可回应的事实摘要和脱敏证据，不拿到举报人的手机号、私密授权材料。一般给双方 7 天补充材料，可说明原因延期；超期不等于自动判败。受理时效先作为运营目标，不在没有服务能力前承诺“24 小时必定处理”。

核验／申诉原始附件在结案后 90 天删除，未提交草稿中的附件 30 天清理。用于解释与复核的最小决定记录保留 1 年，包含团号、结论、依据摘要和操作记录，不包含原始证件或联系材料；到期删除或去标识化。未结案材料只用于当前处理，不能转作公开展示。下载需再次校验权限，删除同时覆盖存储副本；如确需延长保存，记录具体原因与期限并告知相关人。

后台不是简单“通过／拒绝”。同一案件有双方团号、材料、公开信息快照、时间线、临时动作、最终理由和申诉记录。改名或限制操作必须确认范围；成员与账目区域不出现“移交给投诉者”按钮。

## 6. 轻量反滥用，不重新造资格门槛

首期统一配额建议：**一个账号滚动 24 小时内最多创建 1 个，同时担任团长的正常跑团最多 3 个**。所有正常登录用户都获得相同基础额度；确有多城分团等需要时可以说明用途申请增加，不要求付费或平台邀请。

配额由服务端事务执行，连点请求以幂等键去重；删除、归档、换团长不会重置当天创建记录。历史超过配额的跑团不追溯删除，只限制继续新增并提供增额入口。

接受正常团长移交不计为主动创建，不因接任者已有 3 个团而阻断移交；接任后超额只影响后续新建，已有管理权继续有效。解散后可以在当日创建冷却结束后再次创建，不恢复已消耗的当日次数。

账号配额无法单独阻止多账号攻击。再结合短时请求频率、重复呈现、已确认违规关联等信号，对明确异常的创建增加验证码、临时冷却或人工复核。IP 只作弱信号，不因学校、公司或跑友共用网络直接封禁。不为防抢名额外强制收集精确位置、通讯录或证件。

名称比较使用独立的规范化字段辅助查找，例如 NFKC、空白规整与大小写统一；显示名保留用户正常写法。相似字、零宽字符及仿造“已核验”徽章需要提示或针对性处理，但近似名称不能直接当作冒用结论。

## 7. 视觉规范

- 延续红、白、浅灰；主操作使用品牌红，一屏只突出一个主要动作。
- 名称提醒使用浅灰或淡玫瑰底，表达“帮助辨认”；只有明确提交错误使用红色。
- 身份标记用小尺寸深色描边勾和“身份已核验”，避免皇冠、金牌、“官方正品”等等级暗示。色彩不是唯一的状态信息。
- 内容顺序始终是名称 → 城市／公开负责人 → 团号与辅助信息。名字可换行，长城名不撑宽屏幕。
- 移动端操作区至少 44px，覆盖 320／390px，底部操作考虑安全区；桌面创建页使用实时名片预览，不把移动表单拉成一整屏宽。
- 核验、申诉是按需进入的页或抽屉；不在创建页堆满资质说明。模态框可用键盘关闭，有焦点和可读标签。

## 8. 实施边界与存量迁移

### 必须一起交付的首期

1. 两端与后端取消建团资格及普通创建审批，原子创建并设置 owner。
2. 城市、公开团号、稳定 ID 链接，同名提示及搜索排序修正。
3. 创建、搜索、公开名片、分享、申请加入五处身份信息一致。
4. 可选组织核验的私密提交、人工处理与可解释标记。
5. 名称／身份冒用私密工单、有限的处置权限与申诉入口。
6. 创建频率、并发／幂等保护、审计与存量兼容。

先放开按钮却继续按最新创建排序、只显示一个团名，不满足上线条件。核验与举报不是以后再补的“运营功能”，它们承担开放后的辨识与救济。

首期不做付费认证、全国名称交易、活跃度回收、自动判定组织真伪、自动转移成员，亦不承诺先造复杂推荐引擎。

### 技术落点，供后续实现评审

| 范围 | 建议 |
| --- | --- |
| `clubs` | 增加城市／片区、短介绍、用于辅助搜索的名称规范字段、公开展示状态；名称保持非唯一 |
| 组织身份 | 单独记录组织、授权范围、当前核验状态及有效核验记录；材料走私密表和私密访问 |
| 创建操作 | 保存创建次数与幂等结果，事务内检查配额；即使归档／转让也保留操作记录 |
| 争议案件 | 工单、附件访问授权、事件时间线、公开信息快照、处理动作与复核记录 |
| 公开响应 | 只输出城市、昵称、公开团号、可展示的核验说明；不输出原始证据或个人联系方式 |
| 权限 | 将该团 owner 和全局 `user.leader` 解耦；不直接删除 `leader` 字段，先审计其它依赖 |
| 客户端 | Web 创建入口在 `web/src/views/Sport.vue`；小程序在 `pages/clubs`，公开名片另在 `club-intro` |
| 后台 | “建团审批”转为“身份核验／名称与身份争议／异常创建”；保留旧审批记录只读 |

现存跑团的 ID、口令、成员、活动及会费记录原样保留。城市未填的显示“城市待补充”，邀请团长补充，不能猜测用户定位。旧待审批申请提供“继续创建”让本人确认后开通，避免批量生成无人管理空团；确认与取消有明确去向。

被限制的公开页和邀请页保留一个不泄露材料的状态页，并根据本人真实成员关系向已有成员提供进入团内的入口；暂停公开展示与招募不撤销成员资格。游客和团外用户不能进入团内，分享与新加入仍被禁止。改名不更换稳定 ID、不让旧链接误入另一个同名团；停用与恢复要有可追踪记录。组织复核不能跨团读取私有资料。

## 9. 验收场景与指标

| 场景 | 必须成立的结果 |
| --- | --- |
| 普通账号第一次创建 | 无需 leader 标记，不等待平台批准；成功后具备本团 owner 权限 |
| 杭州／绍兴都有西湖跑团 | 同名可并存，两端卡片与分享可区分，不强制后缀 |
| 同城两个独立的晨跑团 | 允许同名；城市不是名称锁；团号、负责人和介绍区分 |
| 抢注者先创建，真实组织后入驻 | 后者仍可用原名创建及核验；前者不能靠新建或先建夺取身份优先级 |
| 新成立的两人团不申请核验 | 成员、约跑和团内记录正常；无负面标签，不因人数少不能创建 |
| 同城同名但创建者误找已有团 | 可从同名提醒查看介绍并申请加入，原表单可返回 |
| 复制团徽、谎称授权，材料足以核实 | 可限制具体冒用呈现并通知补正；无权读取或接管成员账目 |
| 竞争者批量举报 | 不自动下架或公开贴涉嫌冒用标记；相同工单合并处理 |
| 用户连点／重试创建 | 不生成多个团；配额检查与写入不可被并发绕过 |
| 换账号／离页后收到旧响应 | 不显示上一个账号的草稿、证据或审批状态 |
| 旧 owner 移交、组织更名 | 历史保留，身份核验适当复核，成员关系不自动转移给第三方 |
| 管理者查看私密材料 URL | 只有被授权的平台处理人员可取；普通团长和其他账号不可取 |

上线观察：创建完成率、创建到首次有效邀请／活动的转化、同名页加入后短时退出／重申比率、核验补充率、确认冒用率、误处置撤销率、每百个新团的人工处理量。以这些指标调整配额与提醒，不以建团总数或认证收入当唯一成功标准。

原型验收另看：320／390／1440px 无横向溢出，同名仍可提交，创建成功信息对应本人输入，核验与申诉状态可区分，核验说明可打开／关闭，后台操作不会出现移交成员资料的路径。

## 10. 参考与设计判断

- [Strava 的跑团说明](https://support.strava.com/hc/en-us/articles/216918347-Clubs-on-Strava)将查找、加入和创建放在同一跑团旅程，查找包含名称和地点。这里参考“开放参与＋地点辨识”，不据此推断其名称权属规则。
- [GitHub 的身份冒用政策](https://docs.github.com/en/site-policy/acceptable-use-policies/github-impersonation)区分名称相似与足以误导的身份／组织关系呈现。这里参考“处理冒用行为，不因重名直接裁决”。
- [GitHub 的用户名规则](https://docs.github.com/en/site-policy/other-site-policies/github-username-policy)说明唯一命名空间需要额外处理占名与交易。本项目已有 ID 定位，因此选择非唯一显示名；这是本项目的产品判断，不是照搬其先到先得制度。

本方案提供平台内的组织辨识与争议流程，不把平台核验等同于对外部名称权属的最终裁定。
