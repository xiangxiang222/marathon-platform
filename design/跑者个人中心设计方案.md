# 跑者个人中心设计方案

本轮以 2026 年 10 月 29 日提供的数字心动截图为功能参考，延续赛历现有的红、白、浅灰视觉。个人中心的任务是让跑者方便地找回参赛安排、训练数据与个人突破，沉淀自己的赛事档案。数字心动的配色、导航、版式和装饰素材不直接沿用。

## 页面规划

| 页面 | 先看到什么 | 主要操作 |
| --- | --- | --- |
| 我的 | 头像昵称、本周运动摘要、下一场赛事、最好成绩 | 找赛事安排、打开数据、管理资料 |
| 运动数据 | 当前周期公里数、次数、时间、配速与趋势 | 周／月／年／累计切换、查看上一周期、记录运动 |
| 赛事生涯 | 完赛场数、参赛年数、累计比赛里程、项目分布、PB | 年份与类型筛选、打开赛事、查看历年趋势 |
| 城市足迹 | 已到访城市与省份、城市对应的赛事 | 按年份查看、打开对应比赛 |
| 荣誉收藏 | 成绩证书、奖牌照片 | 上传、预览、删除自己的收藏 |
| 赛事影像 | 与比赛关联的照片和视频 | 选择赛事与项目、上传、预览、删除 |
| 数据来源 | 已可使用的手动记录、各设备的实际接入状态 | 去记录运动、了解设备条件 |
| 使用帮助 | 赛事标记、成绩录入、数据口径与隐私说明 | 展开问题、前往对应功能 |

“我的”保留已有赛事安排、完赛记录、个人资料与登录流程。概要负责回答“我最近跑得怎样、接下来跑哪场”，二级页负责筛选和管理。公共赛事日历、拿奖雷达、发现跑团、资讯在已有入口继续使用，不占用每个数据区的同一层级。

## 视觉与交互

- 主色使用现有 `#ff0a30`。红色集中在主操作、选中态和需要突出的一项指标；大面积使用白色卡片与浅灰底。
- 用字号、留白和数字对齐建立层级。距离与单位分开，用时使用等宽数字；长赛事名允许换行，不把用时挤出屏幕。
- 以统一线性图形、轻量几何装饰和小面积渐变形成品牌感。每个区块保留一个清楚的主入口，避免多排同等醒目的图标竞争。
- 趋势保留真实零值。空数据给出“记一次运动”“去看赛事”等可操作方向，避免用大片占位图制造滚动距离。
- 动效用于数据条变化、卡片入场和选中态反馈；短时、低幅度，不使用持续闪烁、滚动数字或影响阅读的视差。Web 尊重系统减少动态效果设置。
- 320px、390px 手机宽度和桌面居中视口均验收。表单标签始终可见，点击区域留够空间，错误提示靠近操作；网络失败保留可恢复入口。

## 数据口径

训练与比赛分别统计，不把两者相加成一个看似更大的“累计里程”。“我的”履历卡统一呈现完赛场数、城市与比赛里程；原始训练公里留在运动摘要与数据页。所有周期以北京时间划分，周从周一开始。

| 指标 | 口径 |
| --- | --- |
| 训练公里数 | 已开始且时间有效的跑步、越野原始距离；采用 `distance_km`，不使用跑团 PK 折算后的 `volume_km` |
| 平均配速 | 累计有效用时除以累计距离；零距离或未知距离显示 —。历年配速用逐年数值列表，明确“数值越小，配速越快”，不与“越高越多”的柱图混用 |
| 周期对比 | 本周期只与上一周期相同已过时段比较；查看过去周期时与上一完整周期比较；上期为零时不编造百分比 |
| 重叠训练 | 既有手动记录按已存数据统计，重叠记录不会在此自动认定为同一场 GPS 运动 |
| 完赛场数 | 按赛事 ID 去重；同场多个项目计一场，成绩条数另算 |
| 比赛累计里程 | 按每条有效已发生的成绩项目累计：全马 42.195、半马 21.0975、10 公里 10、5 公里 5；其他未知距离不猜测 |
| 比赛累计时间 | 对已发生、日期有效的成绩用时求和；未来日期、无效日期不计入生涯聚合 |
| 参赛年数 | 最早参赛年份至当前年份的跨度，包含首尾年份；没有成绩时为 0，不等同于连续参赛年数 |
| 最好成绩 | 在同项目的线下路跑成绩中比较。越野和线上成绩保留自己的记录，不与路跑 PB 混排 |
| 城市足迹 | 来源于实际赛事地点；线上赛不点亮城市。城市数量不依赖精确定位，不推断用户住址 |
| 荣誉与影像 | 本人保存的素材；上传证书不等于官方认证、OCR 识别成功或核验通过 |

成绩保留“未核验”属性。不添加缺少样本依据的全国百分位、热量、分段最佳成绩或官方身份徽章。

城市足迹本轮采用“城市护照”式展示，以城市和对应赛事串起经历；它是赛事地点归档，不是地图。选择城市后同页展开该城全部已记录成绩，可切换城市、年份或收起，不只跳转最近一场。不同省份的同名城市分开统计，线上赛、未来日期与无效日期不点亮城市。不绘制未经来源核实的中国轮廓，也不以装饰性点阵冒充真实地图。后续如接地图，应独立选择合法底图服务、核对地图展示要求、接入真实坐标并做真机验收。

## 收藏与隐私

新收藏支持一条成绩对应多份证书、奖牌、照片和视频，与已有单张成绩证明并存；新上传不会覆盖旧证明。上传时必须选择本人已存在的赛事成绩；保存后收藏独立归本人管理，删除成绩或撤回团内接龙均保留收藏。没有现存成绩时仍能按赛事和年份查看、预览、删除，配额与列表保持一致。删除收藏不删除成绩。账号注销与赛事删除仍执行原有清理。

图片限 JPEG、PNG、WebP，单份最大 8 MB；视频限 MP4、WebM，单份最大 40 MB。网页通过浏览器文件选择器上传，小程序通过微信媒体选择器上传；真实设备上的格式转换、视频解码与系统权限仍需真机验收。

接龙同步只维护由该接龙创建的成绩来源，不凭相同用时认领独立记录。本人编辑生涯成绩或上传旧成绩证明后转为个人记录，团长撤回接龙不能删除。旧数据没有可靠来源标记时保守保留。

收藏清单、文件读取与删除均由服务端确认账号归属，不能只靠前端隐藏按钮。默认仅自己查看；已有跑团成绩可见范围继续执行原规则。图片不转成大段 base64 塞入个人资料。上传校验实际格式和大小，文件访问需要有效身份；敏感素材不作为公共分享封面。文件异步落盘后，用短事务再次检查成绩归属、数量与容量并入库；落盘期间不持有数据库写锁，失败清理未提交文件。

本轮不增加订单、优惠券、赛事缴费、收货地址或身份证信息。平台已有的参赛状态是个人标记，报名仍去赛事官方渠道完成。运动员、裁判、教练、医师跑者和配速员认证，需真实审核主体与证据流程后另行设计。

## 设备接入的真实条件

当前仓库没有以下厂商的生产凭据和完整同步链路，因此页面显示真实未接入状态，不出现可以误认为已经授权成功的按钮或开关。

| 来源 | 官方能力与当前判断 | 上线前需要完成 |
| --- | --- | --- |
| Garmin | 官方现区分个人访问与 Business Starter／Enterprise。个人 API key 用于本人数据；面向多用户的平台应走相应 Business 路径。旧方案“仅限企业”的绝对描述已不适用 | 确认合作档位与用户上限，获得应用凭据，完成用户连接、推送、撤权与历史数据边界联调 |
| COROS | Partner API 面向多用户平台，提供 OAuth 2.0、推送等能力；官方申请流程要求平台和技术联系资料及重定向地址。自助 MCP 工具入口不能当作本平台的多用户授权已完成 | 申请平台接入，保护回调、令牌与撤权，验证同步范围、去重和重试 |
| 华为运动健康 | Health Kit 官方明确支持 Web，并以用户授权为前提；不能因页面能打开厂商登录页就认为已接入运动数据 | 申请相应 API 能力，确认地区和数据范围，完成云侧授权及同步；资质细则以申请时官方要求为准 |
| Suunto | API 面向提供公众服务的公司或组织，采用 OAuth 2.0，并要求 API 订阅密钥 | 完成伙伴申请、开发与生产订阅、授权回调、增量数据和解绑测试 |
| Apple 健康 | HealthKit 是 Apple 原生框架。根据官方平台支持范围，当前 Web／微信小程序无法直接调用 iPhone 健康库 | 如需直接连接，需有支持 HealthKit 的原生 App 或其他经核实的桥接方案，并完成逐项数据授权 |
| 微信运动 | `wx.getWeRunData` 提供过去 31 天微信运动步数，需要微信登录与相应授权；不提供跑表轨迹或跑步项目公里数 | 若后续接入，单独显示步数来源，不把步数折算结果写成已同步跑步距离 |

资料核对日期：2026-10-29。官方入口：

- [Garmin Connect Developer Program Overview](https://developer.garmin.com/gc-developer-program/overview/)
- [COROS API 申请说明](https://support.coros.com/hc/en-us/articles/17085887816340-Submit-an-API-Application)
- [华为 Health Kit](https://developer.huawei.com/consumer/en/hms/huaweihealth/)
- [Suunto API Zone](https://apizone.suunto.com/) 与 [开发接入步骤](https://apizone.suunto.com/how-to-start)
- [Apple HealthKit 文档](https://developer.apple.com/documentation/healthkit)
- [微信运动数据接口](https://developers.weixin.qq.com/miniprogram/dev/api/open-api/werun/wx.getWeRunData.html)

研究过程使用官方页面；COROS 正文通过其官方帮助中心 JSON 接口读取。外部能力接通前，本地编译和模拟接口测试均不能替代厂商生产联调。

## 验收与后续

验收以 [跑者个人中心验收用例](跑者个人中心验收用例.md) 和本轮实际测试报告为准。设计中列出的功能只有在对应交互、服务端权限与测试通过后才算实现。

本轮最终本地结果为：Web 浏览器专项 18 组通过、生成 25 张截图；小程序页面逻辑专项 12 组通过；服务端全套 106 条通过；客户端整套 14 个脚本通过，Web 生产构建与小程序原生离线编译通过。浏览器使用内存接口数据，小程序使用页面逻辑运行环境，服务端使用临时测试数据。这些结果证明已覆盖的统计、交互与权限边界；不代表微信真机、生产存储、真实设备授权同步或视频播放均已验收。后续修复后的重跑结果以报告文件为准。

后续优先级：生产存储与备份容量、账号数据删除／导出与真实客服渠道；随后接入首家手表厂商，再考虑真实地图、OCR 辅助录入、可控公开主页和年度分享报告。任何公开发布素材能力，应先补可见范围、撤回与内容安全链路。
