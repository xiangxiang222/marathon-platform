# 马拉松一站式平台 · 产品与 UI 改版方案

本方案根据本次提供的京东 App 截图及项目已有能力制定。借鉴其清晰的频道、资产、状态与服务入口组织方式，落到赛事和跑团场景。页面使用本平台的原创图标与内容，不展示购物、优惠券或未经接入的服务。

## 1. 产品定位与两条主线

帮助跑者找到比赛、记录参赛计划，并与跑团一起训练和参赛。当前提供赛事信息与个人标记；官方报名由赛事方承接。

- 个人主线：找赛事 → 看时间、项目与规程 → 标记想跑 / 已报名 / 中签 → 赛后记成绩 → 回到个人赛事记录。
- 跑团主线：找到跑团 / 打开邀请 → 看公开介绍 → 申请并审核 → 看团内比赛、训练和成员 → 参与活动 / 记录跑量。

首页的成功标准是容易找到和比较比赛；跑团的成功标准是成员打开后能立刻看到近期比赛和下一场训练；个人中心的成功标准是容易找回自己的计划与成绩。

## 2. 一级导航

| 顺序 | 页面 | 用户主要问题 | 首屏必须呈现 |
| --- | --- | --- | --- |
| 1 | 赛事 | 最近有什么比赛，哪些适合我？ | 搜索、分类、常用入口、截止提醒、真实赛事列表 |
| 2 | 跑团 | 我的团在做什么，怎样加入新团？ | 我的跑团、搜索入口、申请状态 |
| 3 | 运动 | 这个月跑了多少，如何记一场？ | 本月跑量、真实目标与指标、记录入口 |
| 4 | 我的 | 我有哪些比赛和成绩？ | 头像昵称、个人资产、我的赛事 / 完赛记录 / 个人资料 |

小程序和 Web 使用相同的顺序、名称、图标和主要状态。Web 仍保留独立管理后台。

## 3. 赛事发现

顶部按“标题日期 → 搜索 → 一排赛事类型 → 四个工具入口”排列。赛事类型为“全部赛事 / 路跑 / 越野赛”，保留唯一一组红色下划线。工具入口为赛事日历、拿奖雷达、发现跑团、赛事资讯，图标约 32px，标签弱化、上下留白。参赛形式“全部形式 / 线上赛 / 线下赛”移至赛事列表标题下方，采用浅灰分段控件，选中项为白底深色字，不再重复下划线；两端保持同样层级。两类筛选可组合，接口独立使用 `kind` 与 `meet`，例如 `kind=trail&meet=offline` 查线下越野。当前模型没有可靠的国家或海外标记，不展示无法提供结果的海外入口，也不猜测国家。

截止信息以一条浅红提醒展示，可以切换，不使用多张占屏大卡。筛选负责地点、时间、距离和状态；赛事内容卡负责日期、名称、地点项目、报名状态与截止时间。赛事名称优先，日期不再用紫绿底区分报名状态。

赛事卡点击进入详情，搜索结果沿用同一种卡片。空状态说明当前分类没有赛事，网络失败显示可理解的错误信息，不伪造赛事或数字。

日历长图采用已确定的红白灰视觉，保留日期、星期、农历、场数及赛事名称、城市、项目，不包含报名状态或占位小程序码。预览用长按保存，不额外放保存或关闭按钮，点击遮罩空白关闭。

## 4. 赛事详情

详情先提供“名称、比赛日、地点、项目与关键截止”，再提供竞赛规程、赛事资讯、个人参赛状态和成绩记录。

- 个人参赛状态位于靠前位置，登录后可标记，团内按现有权限关联展示。
- 官方报名入口明确标为“官方报名信息”，不使用站内结算式按钮，不做支付与代报名。
- 分享入口按需展开，团内名单仅对已加入成员展示；公开邀请不携带名单。
- 成绩保留手填与证明照片，未核验标识保留，不承诺自动识别。
- 未接入的酒店、证书识别和站内报名功能不占用独立首屏卡片。

## 5. 跑团发现与公开介绍

跑团页先展示“我的跑团”，再提供搜索和口令入口。移除与找跑团无关的个人缴费、赛事统计。已加入、等待审核、可申请这三种状态提供明确入口。

创建跑团是一个按需展开的入口，已有创建资格才提供表单；待审申请显示真实待审状态。游客可以搜索公开跑团目录，也可经邀请或口令打开跑团公开介绍；发起入团申请前再登录。

公开介绍采用留白充分的红白跑团名片，顶部轻量跑道装饰只衬托团名；团长与人数为唯一公开统计。下方白卡介绍团练约跑、赛事同行、跑量排行，不展示实际团内数据。底部固定并列“分享跑团”和“登录并申请加入 / 申请加入 / 等待审核 / 进入跑团”，保留原审核流程和登录后恢复申请；游客可分享，不强制登录。小程序通过原生按钮发给好友或微信群，朋友圈使用菜单指引；微信内网页使用右上角菜单指引，其他支持系统分享的浏览器优先调起系统面板，复制链接收至不支持分享时的备用面板。公开分享不附带登录、自动申请、成员或成绩数据，取消分享不误报成功。

## 6. 跑团工作台

团名、角色、团长、成员头像与邀请入口组成身份区。固定五个主栏目：概览、赛事、训练、跑量、成员。

- 概览：真实统计 → 即将开赛的团内赛事 → 下一场训练 → 常用团内服务。
- 赛事：成员参赛名单优先，成绩与 PB 排名随后；成绩统计表单点击后展开。Web 可导出成绩接龙完整 CSV 和全团赛事名单 CSV；小程序可复制完整成绩榜及全团赛事表格。两端支持单场赛事画像和成绩接龙长图。仅上传成绩、未保留参赛标记的团友也进入赛事聚合与导出；同一成员、同一项目和成绩不重复输出。长图最多展示 350 条，完整名单使用 CSV 或文本表格。
- 训练：现有训练、约跑、队内赛内容优先；签到入口只在活动开场后对已报名成员显示。活动未开场或已取消时不能新增签到；已有签到的活动不能改期到未来。失去当前报名关系但仍保留的签到标注为历史记录。
- 跑量：周期、成员 / 分组排名明确；仅展示已有手动数据，手表同步接入前不展示“已同步”。
- 成员：头像、姓名、角色和组别；管理员看到待审核提示及审核操作。普通成员和跑团管理可主动退团，团长须先转让。退出与移出均先说明报名取消、历史保留和重新审核规则；提交中禁用重复操作，失败留在当前页面。

主动退出、团内管理员移出和后台移出共用事务清理：取消未来团练报名、未出成绩的未来队内赛报名、明日及之后未打卡的约跑报名，再解除成员关系及待审申请。当前北京时间分钟已经开场的团练和队内赛报名保留；约跑只有日期，保留当天及历史报名、已有打卡的报名。历史签到、成绩、个人赛事、积分和已审核申请保留；旧异常提前签到的已有积分后续结算也不删除，新提交的未来团练签到由服务端拒绝。离团失去团内访问权，再次加入重新审核。

会费名单按期次快照：开放期只显示当前成员；成员在开放期离团或被移出时，事务为其补记「未交」，已有状态保持。关闭期时为当时成员补齐未交记录，历史只显示已快照或明确记录的人，离团者标注「已离团」，关闭后不可编辑；期次开始后加入的人不追溯进旧期。重新加入后显示开放期当前记录，历史缴费状态和离团快照不变。上线前已关闭的期次只保留已有记录，不追补无法推断的退出后又重入历史。

发布训练、发起约跑、成绩接龙、设置分组、会费和积分礼物等长表单默认收起。展开操作保留所有现有字段、权限及提交反馈，避免管理员打开页面即进入长表单。

## 7. 个人中心与运动记录

个人中心参考“身份 → 资产 → 状态分类 → 服务”的成熟组织方式：头像昵称和跑团归属在前，已标记赛事、完赛场次、已加入跑团为真实数字。用户先看记录，资料和密码修改进入“个人资料”后操作。

游客看到清晰登录入口，点击后展开微信登录或已有账号登录 / 注册表单；不以满屏表单作为默认欢迎页。微信登录能力只在小程序使用，Web 保留已有账号密码登录，不伪造微信授权按钮。历史仅昵称账号由管理员核验后在原账号上重设密码，不允许注册同名昵称接管，即使昵称唯一也不例外。

运动页以本月公里数为主指标，配合天数、次数、配速。只有真实目标存在时显示进度；记一场和设目标以按钮展开表单，已有记录在后。单条编辑、删除按需展开；现阶段明确支持手动记录，不用未接入设备占满页面。

## 8. 视觉与组件

| 元素 | 规格 |
| --- | --- |
| 主色 / 浅红底 | `#ff0a30` / `#fff0f3` |
| 页面 / 卡片 | `#f5f6fa` / `#ffffff` |
| 主字 / 辅字 / 分隔线 | `#1f2026` / `#8a8e99` / `#f0f1f5` |
| 页标题 / 区块 / 正文 / 辅助 | 24 / 18 / 15–16 / 12–13 px |
| 字重 | 正文400、内容名称600、页标题700 |
| 卡片 / 控件圆角 | 12 / 8 px，小程序对应24 / 16 rpx |
| 页面间距 | 左右12 px；卡片间10 px；内部12–16 px |
| 主按钮 | 红底白字，40–44px高，一张卡明确一个主要动作 |
| 导航图标 | 黑色线性普通态、红色选中态；功能入口采用同源彩色矢量图 |

字体使用系统字体栈，iOS 优先 PingFang SC。小程序自定义导航读取真实状态栏和胶囊尺寸，不绘制假的系统状态栏。小屏给正文和辅助文字设置可读的字号下限。

共享组件包括主页面标题、白卡、数字指标、文字 Tab、状态标签、折叠操作、空状态和登录引导。二级页面保持简洁返回导航，管理后台沿用相同颜色与表单规范。

## 9. 本轮实施范围和能力边界

本轮落实四个主页面、跑团详情与公开介绍、赛事详情的信息顺序和操作层级，统一共享导航及全局视觉；补齐活动发布与分组报名、成绩与赛事导出、退团、关键详情页加载失败恢复。未知网页地址提供返回有效页面的入口，次级页面与后台按路由加载。

小程序已接入微信官方隐私授权事件、同意按钮及可见的隐私指引入口；这不等于微信后台已发布有效指引。运营主体、真实隐私声明、合法 request/upload/download 域名、生产 HTTPS、真实 AppID 和真机验证仍需外部配置与验收。

手表同步、附近推荐、订阅通知、真实站内报名或支付尚未接入。现有成绩接龙与表格导出不等于可自由配置字段的通用活动接龙，也不提供原生 `.xlsx` 文件或所有赛事合并成一张无限长图。个人公开主页、单场目标与展示权限、账号注销和完整客服配置仍是后续产品工作，详见 [本轮验收与产品缺口](本轮验收与产品缺口.md)。

## 10. 验收

1. 两端四个主导航顺序一致，页面名称和主动作一致。
2. 普通成员优先看到内容，管理表单默认折叠且可完整展开和提交。
3. 搜索、筛选、详情、申请、登录恢复和个人记录继续工作。
4. 320 / 390px 下不横向溢出，胶囊不挡标题，底部操作不挡正文。
5. 验证游客、已登录、待审核、已加入与管理员状态。
6. Web 生产构建、微信原生 WXML/WXSS 编译通过；浏览器截图和小程序源码渲染镜像分开标注，不将镜像当作真机截图。

本轮会费成员范围、活动签到入口及取消/改期边界已补入实现，服务端、客户端、小程序离线编译与 Web 构建的完整结果待最终验收后记录。不要沿用上一轮专项统计作为本轮结论；报告索引见 [预览与验证](previews/README.md)。
