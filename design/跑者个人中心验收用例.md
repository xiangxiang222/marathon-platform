# 跑者个人中心验收用例

此表是验收用例清单，不代表每条已经执行通过。执行结果以本轮服务端、浏览器与小程序测试报告为准；微信真机及厂商联调单独记录。

## 本轮实际执行结果

2026-10-29 最终本地回归结果：

| 范围 | 结果 | 实测边界与证据 |
| --- | --- | --- |
| Web 浏览器专项 | 18 组通过，25 张截图；页面运行错误与未预设接口均为 0 | Chrome；320／390／1440px；总览及 7 个二级页。使用内存接口读写，调用真实训练与生涯聚合函数，不写业务数据库。见 [脚本](previews/runner-browser-regression.cjs) 与 [报告](previews/runner-browser-report.json) |
| 小程序页面专项 | 12 组通过 | 在页面逻辑运行环境检查数据装饰、时间轴／城市口径、周期回退、账号隔离与旧请求、收藏与上传限制、登录回跳；未替代微信原生渲染与真机媒体操作。见 [脚本](previews/runner-mini-regression.cjs) 与 [报告](previews/runner-mini-report.json) |
| 服务端全套 | 106 条通过 | 包含本轮跑者中心统计、鉴权、收藏文件权限、实际格式／大小校验、删除清理等测试；使用临时数据库及文件目录。测试文件见 [runner-center.test.js](../server/test/runner-center.test.js)；包含接龙成绩来源、独立收藏保留、异步落盘、上传期间删除成绩、并发配额与数据库失败清理回归 |

根目录客户端整套 14 个脚本均通过，Web 生产构建通过；小程序原生离线编译 34 个 JS、28 个 JSON、24 个 WXML、25 个 WXSS 通过，未发现缺失引用。

Web 已覆盖历史周文案、配速缺省与逐年列表、同城全部成绩、无成绩的私人收藏管理、履历比赛里程、零跑量柱高、窄屏时光轴日期单行、首屏与档案汇总一致、失败重试、周期查询与汇总、年份／类型筛选、未来及无效日期排除、线上记录保留、路跑 PB、跨省同名城市、旧证明预览、新图片上传与删除确认、空态、游客登录回跳和 401 后清空私人数据。25 张截图使用人工构造的跑者记录与样例证书，不含真实用户资料；已人工查看总览、生涯和城市护照代表页面。

以下尚不能由上述结果确认：微信真机权限及媒体选择器、真机视频解码与播放、生产上传域名与存储恢复、厂商生产 OAuth 授权与真实数据推送。设备页当前呈现未接入状态，城市页为城市护照，官方身份认证、赛事报名和支付均未新增。

## 测试准备

使用临时数据库、临时媒体目录和独立测试账号，不修改真实跑者记录。准备两名用户 A、B；A 有跨年训练与同场多项目成绩、旧证明和新收藏，B 无记录。日期包含周一／周日、月末、闰年二月、北京时间跨日；测试文件包含有效 JPEG／PNG／WebP、MP4／WebM、伪造扩展名和超限文件。

| 编号 | 操作与数据 | 预期结果 | 覆盖端 |
| --- | --- | --- | --- |
| AUTH-01 | 游客打开个人中心和各二级页 | 可见登录引导；不显示上个账号的数据，不发起未授权写入 | Web、小程序 |
| AUTH-02 | A 登录后切换到 B／退出 | A 的统计、缩略图、预览与错误状态清空 | Web、小程序 |
| AUTH-03 | A 的页面获取数据时返回 401 | 提示登录失效，不能把缓存结果当作本次成功结果 | Web、小程序 |
| AUTH-04 | 保留原先邀请申请／赛事标记登录回跳 | 登录后仍能回原业务，不被新个人中心截断 | Web、小程序 |
| STAT-01 | 周内有跑步、越野及无关类型记录 | 原始跑步与越野公里计入，无关类型不计入 | 服务端、两端 |
| STAT-02 | 同一训练原始距离 10，PK 折算 12 | 运动数据为 10 公里，不混入 PK 计分规则 | 服务端 |
| STAT-03 | 没有记录或全部零距离 | 次数／公里／时间稳定显示；配速缺省，无 NaN／Infinity | 服务端、两端 |
| STAT-04 | 北京时间周日跨周一、年末跨年 | 周从周一开始，各周期边界一致，无重复计入 | 服务端 |
| STAT-05 | 周／月／年／累计切换及上一周期 | 标题、摘要、柱图和记录为同一周期；不能前进到未来 | 服务端、两端 |
| STAT-06 | 本期仅过三天，与上期做对比 | 仅比较同等已过时段；查看过去周期时比较完整上一周期 | 服务端 |
| STAT-07 | 上期公里为 0，本期大于 0；查看历史周 | 不显示无限百分比；历史周用“该周”，不能声称“这周已重新出发” | 服务端、两端 |
| STAT-08 | 有重叠时间的两条手动训练 | 统计口径明确，不能假称已去重或已由设备核验 | 服务端、两端 |
| STAT-09 | 快速切换多个周期，响应顺序颠倒 | 最后选择的周期胜出，不被旧请求覆盖 | Web、小程序 |
| CAREER-01 | 同场赛事有全马、半马两项成绩 | 完赛场数只增加 1；项目分布、成绩条数和里程按各自口径 | 服务端、两端 |
| CAREER-02 | PB 含同项目路跑、越野、线上数据 | 路跑 PB 不被越野／线上成绩覆盖；记录仍可查看 | 服务端、两端 |
| CAREER-03 | 有未来／无效赛事日期或未知项目距离 | 不污染生涯聚合；未知公里数不猜测 | 服务端 |
| CAREER-04 | 从最早参赛年到本年，中间有空年 | 参赛年数为含首尾跨度；不描述为连续参赛年数 | 服务端、两端 |
| CAREER-05 | 年份与类型筛选、趋势指标切换 | 列表与标签一致，空筛选有恢复入口，不发生内容横向溢出 | Web、小程序 |
| CAREER-06 | 同城多场、多项目；跨省同名城市；线上赛 | 选城展开该城全部成绩；按省份与年份隔离；线上赛不点亮所在地 | 服务端、两端 |
| CAREER-07 | 修改／删除已有成绩 | 回个人中心后统计与 PB 更新；已有私人收藏保留且仍可管理 | 服务端、两端 |
| MEDIA-01 | 选择本人已有成绩上传证书、奖牌、照片 | 类型正确；新增收藏不覆盖旧证明；刷新仍可见 | 服务端、两端 |
