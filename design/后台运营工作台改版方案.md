# 赛历运营中心 · 后台重构方案

## 设计目标

从重度马拉松跑者的角度，平台的价值先由信息可靠性决定：比赛日期有没有变，报名何时截止，规程是否完整，报名链接是否来自官方。后台应让运营者快速发现、核实、补全并发布这些信息，同时照顾跑团申请、成员与账号管理。

视觉采用京东商城的红、白、浅灰、明确状态和高密度信息层级。后台使用本平台的品牌与真实业务，不添加虚构收入、交易、销量或增长趋势。以桌面工作台为主，保留手机处理审核和查看信息的能力。

## 运营总览

总览先展示真实待办，再展示信息质量和近期赛程。待审赛事、待审资讯、建团申请、入团申请等指标必须来自完整数据集的聚合，不拿当前分页行数代替总数。

待办卡点击进入对应列表和状态。近期赛事按比赛日排序，显示日期、名称、城市和当前报名提示，并可直接打开编辑。信息质量只检查即将开赛的已发布赛事，明确缺少报名节点、竞赛规程、来源等数量；没有可靠数据时显示加载或错误，不补假数字。

不展示收入、订单、转化、同比、环比等未建设的数据。总览的数字是工作入口，不是装饰。

## 赛事工作区

赛事工作区拆成三条清晰路径：

1. **赛事库**：已发布赛事的搜索、范围筛选、分页与编辑。日期和名称优先，城市、报名状态与资料提示随后。
2. **内容审核**：查看待审与已打回上报，点开核实所有资料。保存仍是待审稿，只有明确通过才写入赛历。打回必须保留原因。
3. **官网同步**：主动拉取、对比官网的名称、日期和网站变更，区分待确认、变化、已收入、忽略。已有报名节点不被官网缺省数据覆盖。

列表与编辑器各有职责：列表负责定位，编辑器负责核实与补全。宽屏采用可调整左右宽度的分栏；小屏依次排列，保证控件、保存和审核动作可见。

编辑器完整保留九个分区：基本信息、项目、报名、官网、比赛日、规程、直播、奖项、资讯。保留各类图片队列、Markdown 正文、来源、奖金规则、历年中签率和赛事关联资讯。标题、稿件状态、保存与通过位于固定的编辑头部。删除、打回、发布等动作清晰区分，保留既有确认与权限。

## 跑团与跑者工作区

跑者列表使用昵称、加入时间、跑团数、参赛数与可登录状态，详情按账号、跑团、参赛、成绩、积分组织。账号恢复继续要求管理员核验，不允许同名注册接管。设置密码、建团资格和团内角色属于明确编辑操作。

跑团列表显示团名、团长和人数。详情优先团长与成员，口令只打开介绍并进入申请审核。移出成员不删除账号；现任团长须先移交，再改变角色或删除。删除账号、跑团、成员关系均保留确认说明。

后台移出、团内管理员移出和成员主动退出共用事务清理规则：取消未来团练、未出成绩的未来队内赛、明日及之后未打卡约跑报名，再解除成员关系及待审申请。当前北京时间分钟已经开场的报名保留；约跑没有开始时刻，今天的报名保留，已有打卡的报名也保留。历史签到、成绩、个人赛事、积分及已审核申请不因移出删除，旧异常提前签到的已有积分后续结算仍保留。新提交的未来团练签到由服务端拒绝。确认说明需交代取消范围和保留范围，失败时不显示移出成功；再次入团仍要审核。

申请审核将建团与入团分别呈现，显示申请人、目标跑团和时间，提供通过与拒绝。没有待办时显示真实空状态。

## 视觉与交互规范

| 元素 | 规范 |
| --- | --- |
| 主色 | `#ff0a30`，用于品牌、选中与主要操作 |
| 页面 / 卡片 | `#f5f6fa` / 白色 |
| 主字 / 辅字 | `#1f2026` / `#8a8e99` |
| 布局 | 桌面白色侧栏、顶栏、内容工作区；手机抽屉导航 |
| 字体 | 系统字体；页标题24px，模块18px，正文14px，辅助12px |
| 卡片与输入 | 10–12px圆角，细分隔线，减少大面积投影 |
| 图标 | 同源线性图标，状态由文字与颜色共同表达 |
| 数据 | 核心数字突出；辅助说明不与主要动作争夺注意力 |
| 表单 | 字段始终有含义清楚的标签；长文本保留空间，关联选择明确 |
| 反馈 | 读取失败可重试，写入有结果，权限错误不伪装为空数据 |

不复制京东商标、吉祥物、商品促销和购物车。参考的是成熟的信息组织与视觉秩序。

## 保留能力与验收

重构保留既有后端接口、角色校验和保存语义；新增总览为只读聚合。需要验证管理员和跑团管理员两个角色，并覆盖1440px、1024px和390px。

关键流程包括登录、待办跳转、赛事九分区、待审保存/通过/打回、官网核对、资讯发布、跑者详情和密码、跑团角色和移交、申请审核、训练记录、积分礼品、合作权益和后台账号。测试中的写请求使用内存拦截，不能修改真实运营库。Web 构建、浏览器运行错误、横向溢出与关键字段保留作为交付检查。
