# 跑团退出验收用例

范围：Web 与小程序的成员移出/退出操作，以及后台管理端移出成员。主动退出、团内管理员移出和后台移出共用服务端事务清理。浏览器与小程序脚本使用内存请求替身，不修改业务数据库；服务端权限、名额重新占用与后续积分结算由 `server/test/api.test.js` 的独立临时数据库验证，分钟/日期边界、隔离与失败回滚由 `server/test/member-cleanup.test.js` 的内存 SQLite 验证。

| 编号 | 身份与操作 | 预期结果 | 自动化证据 |
| --- | --- | --- | --- |
| LEAVE-01 | 普通成员进入成员页 | 可见「退出跑团」，先说明详情访问、未开始报名取消、历史保留和再次审核规则 | Web 320/390/1440px；小程序 Page VM |
| LEAVE-02 | 点击退出，在确认框取消 | 不调用退出接口，不跳页，仍可访问当前跑团 | 两端行为回归 |
| LEAVE-03 | 点击退出并确认 | 只向当前跑团发送一次 `POST /clubs/:id/leave`；成功后回跑团列表，列表重新获取 | 两端行为回归 |
| LEAVE-04 | 提交退出时重复点击 | 小程序请求中的按钮处于加载/禁用状态，Page 逻辑拒绝重复提交；Web 按钮随提交禁用 | 小程序延迟请求用例；Web 源码禁用绑定 |
| LEAVE-05 | 退出接口失败 | 保留当前跑团页面、显示错误、恢复可操作状态，重试可成功 | 两端行为回归 |
| LEAVE-06 | 团长进入成员页并尝试退出 | 页面只提示先转让，服务端拒绝团长直接退出，避免无主跑团 | 两端及服务端回归 |
| LEAVE-07 | 未登录、非成员或提交他人 `userId` | 分别拒绝，不影响任何其他成员关系 | 服务端回归 |
| LEAVE-08 | 成员退出后打开团内详情 | 返回 403；未来团练、未出成绩未来队内赛、明日及之后未打卡约跑报名取消；个人赛事、成绩、历史签到与积分保留 | 服务端回归 |
| LEAVE-09 | 退出成员再次申请 | 生成新的待审核申请，审核前不能读取详情；旧申请不会自动恢复成员关系 | 服务端回归 |
| LEAVE-10 | 320/390/1440px 查看退出及失败状态 | 说明和操作可见，页面无水平溢出 | 浏览器截图与尺寸检查 |
| LEAVE-11 | 团内管理员或后台管理员移出成员 | 与主动退出共用事务清理：未来团练、未出成绩的未来队内赛、明日及之后未打卡约跑报名与成员关系在同一事务清除；接口返回各类清理数量 | 服务端双接口回归；小程序移出确认 VM |
| LEAVE-12 | 移出或退出时存在历史数据 | 保留历史报名、打卡、比赛成绩、积分和已审核申请；仅删除待审核申请 | 服务端双接口回归 |
| LEAVE-13 | 移出或退出时存在今天的约跑报名 | 因约跑没有开始时刻，保留今天报名；未来日期未打卡报名取消，已打卡报名保留 | 服务端日期边界回归 |
| LEAVE-14 | 成员尝试给未开始的团练打卡 | 服务端拒绝并不创建签到记录，避免未来训练提前记分 | 服务端活动接口回归 |
| LEAVE-15 | 北京时间 06:30:40 离团，有 06:30 和 06:31 开始的团练/队内赛 | 06:30 已开场报名保留，06:31 的未来报名取消；未来队内赛已有成绩的报名仍保留 | 独立内存 SQLite 固定时间测试 |
| LEAVE-16 | 同一人加入多个跑团，同一场还有其他报名成员 | 只清当前跑团的目标成员；该用户其他跑团、其他成员的报名和成员关系保留 | 独立内存 SQLite 隔离测试及接口断言 |
| LEAVE-17 | 在删除成员关系时由 SQLite 触发器故意中止 | 报名取消、待审申请删除和成员关系删除全部回滚；移除故障后同一请求可以完整成功 | 独立内存 SQLite `BEFORE DELETE club_members` / `RAISE(ABORT)` 测试 |
| LEAVE-18 | 被移出的人占着未来活动的最后一个组别名额 | 移出后人数减一，另一个成员可以报名重新占用，仍不能超出容量 | 服务端活动接口真实数据库回归 |
| LEAVE-19 | 旧异常提前签到已产生真实活动积分，移出后其他成员触发结算 | 清除未来报名、保留旧签到及已发积分；后续结算不删除旧积分，不重复奖励，也不把无报名签到算入当前成团人数 | 服务端真实活动积分引用及后续结算断言 |
| LEAVE-20 | 开放会费期成员离团/被移出，或团长关闭期次 | 离团事务为未记录成员快照未交、保留已有状态；关闭时为当时成员补未交；离团成员标注离团 | 服务端接口与名单回归 |
| LEAVE-24 | 会费期开放后新成员加入，或离团成员重新加入 | 新成员不进入旧期；重新加入显示开放期当前记录，旧期快照保留原状态 | 服务端接口回归 |
| LEAVE-21 | 已报名成员查看未开场、开场后及已取消的团练 | 未开场不显示打卡入口；开场后显示；已取消不显示入口，服务端拒绝新增签到 | Web、小程序页面与服务端接口回归 |
| LEAVE-22 | 含已有签到的活动尝试改期到未来 | 服务端拒绝改期并保留原活动时间和签到记录 | 活动更新接口回归 |
| LEAVE-23 | 查看没有当前报名关系、但仍保留的活动签到 | 签到记录保留并标注为历史记录；仍保留当前报名关系的已开场活动不误标为历史 | 活动详情服务端与两端页面回归 |
| LEAVE-25 | 管理员尝试修改已关闭期的会费记录 | 服务端拒绝，快照状态保持不变；两端历史期不显示编辑操作 | 服务端接口及两端页面回归 |

时间边界统一使用北京时间。团练和队内赛的开始时间精度到分钟，等于当前分钟时视为已开场，保留报名。约跑目前只有日期，没有时刻，系统无法判断今天的活动是否已经跑完，因此移出/退出只取消明日及之后、且没有打卡记录的约跑报名。若将来要求取消今天尚未开始的约跑，需要先为约跑增加开始时间。

本轮完整本地流水线通过：服务端 91/91，客户端 11 组，小程序离线编译和 Web 生产构建通过。内存测试覆盖开场分钟边界、约跑日期与签到保护、用户/跑团隔离及成员移出事务回滚（含会费快照）；接口测试覆盖名额重新占用、旧积分后续结算、会费历史快照与关闭期写入拒绝；迁移测试覆盖旧会费记录一次性回填和重启稳定。旧库不追补无法确认的退出后又重入历史。微信真机、生产域名和数据库升级仍需真实环境验收。

运行：

```sh
node --test server/test/member-cleanup.test.js
npm test
node design/previews/membership-browser-regression.cjs
node design/previews/mini-membership-regression.cjs
```

本轮运行 `npm run test:all` 全部通过：服务端 91/91、客户端 11 组、小程序原生离线编译及 Web 生产构建通过。独立命令为 `npm test`、`npm run test:client`、`npm run test:mini`、`npm run build`。上述本地检查不代替微信真机、生产域名或生产数据库迁移验证。
